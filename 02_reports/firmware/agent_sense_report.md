# agent-sense 报告：0x400436 → sense 缓冲通路（通路 B）

**结论：找到。[实证] 完整指令链已闭合。**

样本：`LS8000_111_ROM.bin`（228,345 B，H8/300H 大端，addr = offset + 0x10000）。
工具：修复版加载器 `h8fix.py`（`load_entries_fixed`）+ `h8dis.H8`。只读 D:\，产出在本目录。

## 1. 搜索方法（穷举性）

| 方法 | 内容 | 命中 |
|---|---|---|
| M1 | 全文件 2 字节对齐线性 decode，操作数字符串含 `400436` | 83 条 |
| M2 | 原始字节 `40 04 36`（abs16 尾）+ `00 40 04 36`（abs32/imm32/r32d32hh），对每个命中尝试 X-2/X-4/X-6 起点反确认 | M1 之外 **0 条** |
| M3 | 原始字节命中点全列（含数据表上下文） | 全部落入 M1 的指令流内 |

即：镜像内 0x400436 的引用共 83 处，全部为指令（无数据表内嵌地址）。M1+M2 并集即完备。
另注意：`0x400436` 是 RAM 地址，超出 ROM 文件范围（文件仅到 0x047BF9），字面量只作为指令操作数出现。

83 条分类：**读 9 条 / 直接写 52 条 / `mov.l #0x00400436,erN`（间接访问装入指针）19 条 / 其他 3 条**。

## 2. 主消费路径（判决性证据）

### 2.1 fn 0x0116A0 —— 「解析层状态码 → sense」刷新器 [实证]

```
0x0116A0  mov.w     r6, @-sp
0x0116A2  mov.w     @0x400436, r6        ; r6 = *0x400436（取解析层状态码原值）
0x0116A8  sub.w     r0, r0
0x0116AA  mov.w     r0, @0x400436        ; *0x400436 = 0（一次性消费：读后即清）
0x0116B0  mov.b     @0x400509, r0l
0x0116B6  bne       0x0116d0             ; *0x400509 != 0 → 跳过 0x011708 构造
0x0116B8  mov.b     @0x400503, r0l
0x0116BE  extu.w    r0
0x0116C0  mov.w     #0x0013, e0
0x0116C4  mulxu.w   e0, er0              ; er0 = *0x400503 * 0x13
0x0116C6  mov.w     r6, r1               ; r1 = 状态码原值（第二参数！）
0x0116C8  add.l     #0x00400464, er0     ; er0 = 0x400464 + idx*0x13（sense 缓冲槽）
0x0116CE  bsr       0x011708             ; REQUEST SENSE 逐字节构造器
0x0116D0  mov.w     #0x0005, r0
0x0116D4  mulxu.w   r6, er0              ; ★ er0 = r6 * 5（与 0x01750E 同款 mulxu #5）
0x0116D6  mov.b     @(0x1914a,er0), r0l  ; ★ r0l = *(0x01914A + 原值*5) —— 「索引=原值」直接实证
0x0116DE  btst      #6, r0l
0x0116E0  bne       0x0116fc
0x0116E2  mov.b     @0x400503, r0l       ; 同 0x0116C0 重建 er0
0x0116E8  extu.w    r0
0x0116EA  mov.w     #0x0013, e0
0x0116EE  mulxu.w   e0, er0
0x0116F0  mov.w     r6, r1               ; r1 = 状态码原值（再传一次）
0x0116F2  add.l     #0x00400464, er0
0x0116F8  bsr       0x011882             ; 经 0x01342e 写出 sense 数据
0x0116FC  sub.b     r0l, r0l
0x0116FE  mov.b     r0l, @0x400505      ; *0x400505 = 0（清挂起标志）
0x011704  mov.w     @sp+, r6
0x011706  rts
```

**「索引 = 状态码原值」等式在 0x03E390 之外的路径上获得直接实证**：`0x0116D4 mulxu.w r6, er0` 的 r6 就是 `0x0116A2` 从 `0x400436` 读出的原值（未经任何查表转换），`0x0116D6` 直接以 `er0 = 原值*5` 索引 `0x01914A`。

被调方 `0x011708`（REQUEST SENSE 构造器）对 r1 的用法 [实证]：
```
0x01170C  mov.l er0, er6      ; er0 = 目的缓冲
0x01170E  mov.w r1, e4        ; e4 = 状态码
0x011710  mov.w #0x0005, r5
0x011714  mulxu.w e4, er5     ; er5 = 码*5
0x011716  add.l #0x0001914a, er5   ; er5 = &sense[码]
0x01171C  mov.b @er5, r4l     ; flags 位决定响应码 0x70/0xF0（btst #5）、sense key|0x20（btst #4）等
```
即构造器第二参数同样以「原值」索引同一张表，逐字节写 sense 响应到 `0x400464 + *0x400503*0x13` 槽位。

### 2.2 fn 0x011882 —— 读回型助手 [实证]

```
0x0118C0  jsr 0x01342e        ; 写 sense 数据
0x0118C4  mov.w @0x400436, r0 ; 读回（此时已被 0x0116AA 清 0 → 返回 0，除非中途重写，见疑问 Q1）
0x0118CA  ldm.l @sp+, er4-er6
0x0118CE  rts
```
唯一调用点：`0x0116F8`（fn 0x0116A0 内）。

### 2.3 fn 0x022AD6 / fn 0x022BF2 —— 第二、第三消费路径 [实证]

```
0x022AFE  mov.w @0x400436, r5      ; fn 0x022AD6
0x022B04  mov.w #0x0005, e5
0x022B08  mulxu.w e5, er5          ; ×5
0x022B0A  add.l #0x0001914a, er5   ; → sense 表
0x022B10-0x022B2C  mov.b @(0x1..0x4,er5) → 复制到 0x4007d1 缓冲
```
```
0x022BFE  mov.b #0x06, r0l; mov.b r0l, @er4   ; er4 = 0x4007d1，buf[0] = 0x06
0x022C00  mov.w @0x400436, r5      ; fn 0x022BF2
0x022C06-0x022C0C  ×5 + 0x01914A
0x022C12-0x022C2E  sense[1..4] → buf[1..4]，buf[5..7]=0，buf[8]=1
```
宿主 fn 0x021D68（含 0x3A 步长表、向 er5 写 0x64/0x78/0x79/0x7D 错误码的分支），`bsr 0x022ad6` @0x022308、`bsr 0x022bf2` @0x022434。

## 3. 轮询/触发链（主循环 → 刷新）

```
0x020C26  jmp 0x020b84                      ; 主循环回边（0x020B84 = 主循环头）
0x020BF0  jsr 0x013066                      ; 有命令？
0x020BF6  beq 0x020c22
0x020BFA  mov.b r0l, @0x400505              ; *0x400505 = 1（挂起）
0x020C00  jsr 0x011162                      ; 取命令
0x020C04  jsr 0x020e86                      ; ★ E0 处理包装器
```
fn 0x020E86（主循环每轮执行）：
```
0x020E88  mov.w r0, @0x400436      ; 清 0（同时清 0x4004fd/fe/ff）
0x020EA4  jsr 0x0114b8             ; 算 *0x400509 = (*0x40043d & 0xE0) >> 5
0x020EA8  mov.w @0x400436, r0      ; ★ 轮询读点
0x020EAE  bne 0x020eba             ; 非零 → 直接刷新
0x020EB0  bsr 0x020ec0             ; 零 → 命令分派（8 字节表 @0x3E2E8 → E0 三层）
0x020EB2  mov.b @0x400505, r0l
0x020EB8  beq 0x020ebe
0x020EBA  jsr 0x0116a0             ; ★★ 刷新到 sense（0x400436 → 0x01914A → 缓冲）
0x020EBE  rts
```
第二包装器 fn 0x011460（`*0x400d20 == 1` 命令挂起时用，被 0x0110CA/0x01113E 调用）与 fn 0x020E86 同构：
```
0x01149E  bsr 0x0114b8 ; 0x0114A0 mov.w @er6, r0（er6 = 0x400436）
0x0114A2  bne 0x0114ae ; 0x0114AE bsr 0x0116a0（刷新）
```
`0x0116A0` 的全部调用点：`0x020EBA`（主循环）、`0x0114AE`（第二包装器）——**仅此两处，均在轮询闭环内**。

### 4.3 通路 A 合并写 [实证]

fn 0x021536（唯一调用者 0x02152E，位于 fn 0x02151E 内）：
```
0x02155C  mov.w @0x400402, r0     ; 通路 A 载体低字
0x021562  jsr 0x0211b6            ; 查 0x03E390 → sense_index
0x021566  mov.w r0, @(0xfffe,er6) ; 暂存
0x02156A  mov.l @0x400200, er0    ; 回调（0x02151E 入口清 0）
0x02157C  jsr er0
0x02157E  mov.w @0x400436, r0     ; ★ 读点
0x021584  bne 0x021590            ; 解析层已有码 → 保留（解析层优先）
0x021586  mov.w @(0xfffe,er6), r0
0x02158A  mov.w r0, @0x400436     ; 否则把通路 A 的 sense_index 合并进 0x400436
```
**即 0x400436 是「统一待刷新 sense 索引」单元格：解析层码优先，无则透传导通路 A 查表结果。** 两通路在刷新器 0x0116A0 处完全汇合。

## 5. 数据核验

- sense 表条目（`0x01914A + idx*5`，小端语义按 [flags][SenseKey][ASC][ASCQ][vendor]）[实证]：
  - `sense[0x50] @0x0192DA = 00 05 24 00 00`（ILLEGAL REQUEST / INVALID FIELD IN CDB）
  - `sense[0x56] @0x0192F8 = 06 05 2C 00 00`（ILLEGAL REQUEST / COMMAND SEQUENCE ERROR）
  - 与任务声明逐字节一致。
  - 其他：`sense[0x51] = 06 05 25 00 00`、`sense[0x4F] = 06 05 20 00 00`、`sense[0x65] = 00 0B 08 00 00`、`sense[0x70] = 06 0B 4E 00 00`、`sense[0x6F] = 36 0B 4B 00 00`、`sense[0x7A] = 00 02 04 01 03`、`sense[0x7B] = 00 02 04 01 04`、`sense[0x01] = C0 00 00 00 00`（flags 0xC0，0x011708 内 btst #7 特判）。
- 通路 A 表 `0x03E390`（85 条，4 字节/条）**不含 0x50/0x56**（复核确认任务声明）[实证]。

## 7. 对叙事的建议

1. **保留通路 B 叙事，标注 [实证]**。原「0x50/0x56 只差最后一段」的缺口已闭合：`0x0116A0` 同时坐实「索引=原值」（`0x0116D4 mulxu.w r6,er0` + `0x0116D6 @(0x1914a,er0)`）与「进 REQUEST SENSE 构造器」（`0x0116C6/0x0116F0 mov.w r6,r1` → `0x011708`）。
2. **修正「两条彼此独立」的说法**：fn 0x021536（`0x02158A`）表明通路 A 的查表结果在解析层无码时会合并进 0x400436，由同一刷新器出货。准确表述是「两个输入源、一个出货口（0x0116A0）」。
3. 不建议「删掉通路 B、把 0x50/0x56 并入通路 A」——那会丢失 28+8 个写点的分层语义（解析层 0x50 族 vs 传输层 0x6F/0x7C 族 vs 执行层 0x56），且与 §4.3 的合并事实矛盾。
4. 可补充的新事实：0x50 的第二写入点 `0x026CC8`（CDB 长度>0x0D 拒绝）与执行层 0x56（`0x026BCE`）走同一 er4/er6 指针机制，这解释了为何任务初查只看到 `mov.w #imm,r0` 而找不到 `mov.w r0,@0x400436`。
