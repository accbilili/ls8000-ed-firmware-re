## 2. 你们 §5.3 的矛盾已解：微软驱动内建 32 位兼容路径

对象：`C:\Windows\System32\DriverStore\FileRepository\sti.inf_amd64_14dc9a213197a8b8\scsiscan.sys`（64 位 in-box，57,344 B，只读分析）

### 2.1 ioctl 码：你们没试错，是别的码根本不存在

```
0x190012  在驱动中出现 2 次   ← 你们试的码，正确
0x190004  0 次
0x190008  0 次
0x190014  0 次
```
分派链（`PAGE` 段，`0x140008BA7` 起）：
```
sub ecx, 0x190012 ; je 0x140008CC2   ← 你们的目标
sub ecx, 4        ; je …            ← 0x190016
sub ecx, 4        ; je …            ← 0x19001A
sub ecx, 2        ; je …            ← 0x19001C
cmp ecx, 6        ; je …            ← 0x190022
（以上全不中 → 记录未知 ioctl 并失败）
```
**⇒ 64 位 in-box 驱动只认这 5 个码。** 你们观察到的 `err=50`（`0x190004` 等）不是「码错了」而是「码不存在」，**继续枚举 ioctl 码无意义**；`err=87`（`0x190012`）才是「结构体没对上」。**矛盾(5.3) 的三种可能里，(a) 成立**：驱动为 32 位调用者保留了历史打包布局。

### 2.2 32 位调用者路径：入参布局（这就是你们缺的那块）

`0x140008CC2` 处理块：
```
0x140008CD1  ecx = [rbx+0x10]        ; IoStatus.Information = 实际入参长度
0x140008CD4  test al,al ; je 64位分支
; ===== 32 位调用者分支 =====
0x140008CDC  cmp ecx, 0x2c            ; ★ 入参长度必须 ≥ 44 (0x2C)，否则失败(err=87)
0x140008CDF  jb  fail
0x140008CE1  edx=0x38 ; ecx=edx+8    ; ExAllocatePool(0x40, 0x38, 'SITS'=0x53495453)
0x140008D12  rcx = [rsi+0x18]        ; 用户入参缓冲
0x140008D16  [rcx+0x04] → [int+0x04] ; dword
0x140008D1E  [rcx+0x08] → [int+0x08] ; dword
0x140008D26  [rcx+0x0C] → [int+0x0C] ; byte
0x140008D2E  [rcx+0x0D] → [int+0x0D] ; byte
0x140008D36  [rcx+0x10] → [int+0x10] ; dword
0x140008D4E  [rcx+0x14..+0x23] → [int+0x14..+0x23]  ; movups 16 字节（CDB 区）
0x140008D3E  [rcx+0x24] → qword [int+0x28]   ; ★ 4 字节指针 → 内部 8 字节指针槽
0x140008D46  [rcx+0x28] → qword [int+0x30]   ; ★ 4 字节指针 → 内部 8 字节指针槽
; ===== 64 位调用者分支 =====
0x140008D5E  cmp ecx, 0x38            ; 长度必须 ≥ 56
```
**⇒ 32 位宿主应该发的 44 字节结构**（字段偏移由驱动拷贝表反推，均为字节级实证）：

| 偏移 | 宽度 | 内容（依据） |
|---|---|---|
| +0x00 | 4 | **驱动不读**（拷贝从 +0x04 起）——长度/填充随意 |
| +0x04 | 4 | dword，原样传入内部 |
| +0x08 | 4 | dword，原样传入内部 |
| **+0x0C** | **1** | **CdbLength**（`0x140008D93 cmp al,0xA`：==10 走 CDB 拷贝；==6 也接受；其它值须等于设备期望长度 `[r14+0x78]`） |
| **+0x0D** | **1** | **SenseInfoLength**（`0x140008DBA movzx eax,byte[rbx+0xD]`；==0 则跳过 sense 缓冲分配） |
| +0x0E | 2 | 填充 |
| +0x10 | 4 | DataTransferLength（`0x140008DAD mov eax,[rbx+0x10]` 与设备期望值比较） |
| **+0x14** | **16** | **CDB 区**（`0x140008D9A lea rcx,[rbx+0x14]` → memcpy 长度 = `[r14+0x78]`） |
| **+0x24** | **4** | **数据缓冲指针**（32 位）；内部转成 8 字节指针 |
| **+0x28** | **4** | **sense 缓冲指针**（32 位）；`SenseInfoLength=0` 时不碰 |

总长 **≥ 0x2C = 44**；两个指针各 **4 字节**（不是 8）。

### 2.3 你们暴力扫描为什么全灭（可自查）

你们试过的「数据缓冲区指针偏移与宽度」是 `26/4、32/8、24/8、20/4、28/8、36/8`。
按上面的实证表，**32 位路径要求指针在 +0x24 与 +0x28，各 4 字节**：
- `36/8` 偏移对（36=0x24）但**宽度错**（应是 4，不是 8）——32 位路径按 4 字节读，再零扩展成 64 位指针；
- `28/8` 偏移是第二个指针的位置，宽度同样错；
- `20/4` 是 CDB 区起点（+0x14=20），不是指针。
**⇒ 你们从未试过「+0x24/4 字节」这一组合。** 建议下一轮只试这一组：44 字节、CDB 放 +0x14（10 字节 + 6 填充）、+0x0C=0x0A、+0x0D=0x00、+0x24=数据缓冲、+0x28=0。

**额外提示**：`SenseInfoLength=0` 时驱动不分配 sense 缓冲，`+0x28` 可填 0；`+0x24` 若为 0 且命令无数据阶段（TEST UNIT READY）应可过。

## 3. 你们 §6 的 E0 CDB 模板错位一格（会导致被固件拒）

固件侧 E0 解析层 `0x026BF8` 的实测约束（`[实证]`，地址级）：

| CDB 字节 | 固件要求 | 指令 |
|---|---|---|
| `[0]` | `0xE0` | — |
| `[1]` | `&0x1F == 0`（0x20 倍数） | `0x026C1A/1E/20` |
| `[2]` | **子功能码** | `0x03EDB8` 查表起点 `0x026C5E` |
| **`[3..5]`** | **必须为 0** | 循环 `0x026C24–0x026C3A` 迭代 **3/4/5** |
| `[6..8]` | 24 位大端**分配长度** | `0x026C96–0x026CB4`（`CDB[6]` 高字节） |
| `[9]` | 0 | `0x026C3C` |

> 顺带修正既有主文档一处：旧文档写「`CDB[3]–CDB[6]` 必须全为 0」，**实测是 `CDB[3..5]`**（`CDB[6]` 是长度高字节，不可能为 0）。

你们 §6 的表格：`E0 00 <sub> 00 00 <p2> <p1> <p0> 00 00` —— 参数落在 `[5..7]`，而 `[5]` 必须为 0、`[6..8]` 才是长度。**正确布局应为 `E0 00 <sub> 00 00 00 <p2> <p1> <p0> 00`**（10 字节，24 位长度在 `[6..8]`）。你们正文那句「大端填 CDB[6..8]」是对的，是表格模板错了一格。

## 4. 你们 §1 待办「抓 CDB 字节流以解决 15354/450/3283」——抓 CDB 抓不到

**固件侧已把六数值全部坐实**（`[实证]`，`cmp.l #imm32,er3` 编码 `7A 23 <imm32>`）：

| 子功能 | 约束 | 指令 |
|---|---|---|
| `0x40` | ≤ 15354 | `0x026DF8 cmp.l #0x3bfa` + `bls` |
| `0x41` | ≤ 450 | `0x026E0A cmp.l #0x1c2` + `bls` |
| `0x42` | ≤ 3283 | `0x026E1C cmp.l #0xcd3` + `bls` |
| `0xC1` | ≤ 450 | `0x026E2E cmp.l #0x1c2` + `bls` |
| `0xB3` | −300…+300 | `0x026E86 cmp.l #0xfffffed4` + `blt`；`0x026E8E cmp.l #0x12c` + `ble` |
| `0x91/0x92` | 0 或 1 | `0x026E9C mov.l er3,er3`+`beq`；`0x026EA0 cmp.l #1`+`beq` |

越界 → `mov.w #0x53` → `0x400436`（0x53 = 参数越界，与参数块引擎 `0x025A56` 同码）。

**关键点（纠正一个容易踩的坑）**：被比较的量 `er3` **不是 CDB 字节**，而是 **32 位大端参数 V1 = `payload[1..4]`**（`payload[1]<<24 | payload[2]<<16 | payload[3]<<8 | payload[4]`）〔R25：模拟器实跑确认；R22 的「重排相加」说已撤销〕——

```
0x026C06  er4 = 0x0040043c        ; CDB 基址
0x026C0C  er5 = 1 ; add.l sp,er5  ; er5 = sp+1 = 13 字节 payload 暂存区
0x026D12–0x026D40  er3 = payload[1]<<24 | payload[2]<<16 | payload[3]<<8 | payload[4]
```
payload 由 data-out 相位经 `0x0118D0 → 0x013994`（传输层）拷入暂存区。

⇒ **这三个数在 data-out payload 里，不在 CDB 里。** 抓 CDB 字节流看不到它们；要抓就抓 **data-out 缓冲**（或同时抓 CDB 与 data-out）。
⇒ 同一 V1 也是执行层写进 `0x400408` 的那 4 字节（C1 臂 `0x026A92`、B3 臂 `0x026B0A` 同源同序），交叉一致。
⇒ `0x91/0x92` 的 `V1∈{0,1}` 是**布尔参数校验**（语义自洽，非死子功能）。

## 5. 你们 §6「固件侧执行层 `0x0269A6`」——命名要改

主命令分派表 `0x03E2E8`（20 条 × 8 B）实测：

```
[16] op=0xC0 f3=000754 fn=0x02694A
[17] op=0xC1 f3=000014 fn=0x0269A6   ← 不是「E0 执行层」
[18] op=0xE0 f3=000014 fn=0x026BF8   ← 才是 E0（解析+门限+落存）
[19] op=0xE1 f3=000014 fn=0x026EFC
```
**协议是两段式**：E0 解析并落存（`0x400C55`=子功能码、payload@`0x400C56+`、错误码 0x50/0x53→`0x400436`），**C1（EXECUTE）** 才触发 12 值开关（8 臂 + default 0x56）。这与你们记录的「C1 = EXECUTE、C1 的 CDB 不带子码」自洽。

对你们抓包的意义：**E0 与 C1 是两条独立的 CDB**，中间的参数靠固件内存传递；抓包时应能看到 `E0 …` 后跟 `C1 00 00 00 00 00 00`。

## 6. 你们 §2 的补丁比对结论——本轮间接佐证

你们已证明已安装的 `LS8000.md3` 与原版 `.text`/`.rdata`/`.data` 逐字节一致，差异只在 `.rsrc` 与 PE 头。固件侧本轮发现的三条主机侧可验证结论，可用于交叉确认补丁确实没改行为：

1. 主机侧**不做数值校验**（你们已验证）⇒ 固件侧那六个上限是唯一防线 ⇒ 固件确实在拦（`0x53`）。
2. E0 的 24 位字段是 **CDB 里的长度**（`CDB[6..8]`），**不是参数**；参数在 data-out payload 的 `payload[1..4]`（V1）与 `payload[5..8]`（V2）。你们的 CDB 构造点 `0x100A0230` 写 `CDB[6..8]` 的是 24 位值——请核对该值是「长度」还是「参数」：按固件语义，`CDB[6..8]` 必须是 ≤13 的分配长度，`payload` 的实际长度另行给出（`0x026D00 mov.w @(0x18,sp),r1` → `0x0118D0` 的拷贝长度）。
3. `0xD1` 缺陷结论不变：主机确实会发（你们已验证 `0x100AA3BC`），固件三层拒（E0 解析表无 `0xD1` → 0x50；C1 开关无 `0xD1` 臂 → 0x56；作业表无 `0xD1` 键）。
