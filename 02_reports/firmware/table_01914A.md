## 0. 结论（一句话）

**记录布局 = `[u8 flags][u8 SenseKey][u8 ASC][u8 ASCQ][u8 vendor]`——5 个独立字节**，不是 `[u16][u16][u8]`，也不是 `[u8][u16][u16]`。
它是**固件内部错误/状态号 → 标准 SCSI sense 三元组**的翻译表；`0x01750E` 所在的 `0x0174BC` 是「结果码/状态码 → 主机可见状态帧」的**发布器**，**不是命令分派器**。

## 1. 表结构判定

### 1.1 边界自证 `[实证]`

```
rec[0]    0x01914A: 00 00 00 00 00
rec[142]  0x019410: 00 02 04 03 07
0x019415: FF 80 20 21 22 00 0A 0B 03 02 23 FF 00 FF FF 06 80 02 02 1F 00 00 00 4E 69 6B 6F 6E …
```
143 × 5 = 715，`0x01914A + 715 = 0x019415`，紧接的是 `Nikon   LS-8000 ED     1.11` 构建串（尾部 `4E 69 6B 6F 6E` = "Nikon"）。
`0x019100`–`0x019149` 是**另一张** 8 字节/条的表（首条 `00 08 00 00 00 54 00 01 1A 9C`），与本表无字节级衔接，故 `0x01914A` 是独立表首。
索引上界自洽：`0x400436` 常量索引实测最大 `0x7D`、`0x03E390.field2` 最大 `0x8E`，均 ≤ 142。

### 1.2 判据一：`0x011708` 是 REQUEST SENSE 构造器（判决性）`[实证]`

`0x011708(er0 = 目标缓冲, r1 = 索引)`：`mov.w #5,r5 / mulxu.w e4,er5 / add.l #0x0001914a,er5`，随后**逐字节**把记录字段写进 sense 缓冲：

| 输出偏移 | 值 | 源 | 指令 |
|---|---|---|---|
| +0 | `0xF0`（flags.b5）/ `0x70` | 响应码 Deferred / Current | `0x011724`–`0x011736` |
| +1 | `0x00` | segment number | `0x01173E` |
| +2 | **rec[1]**（flags.b4 时 `\|0x20`） | **Sense Key**（+EOM） | `0x011748`/`0x011754`/`0x011758` |
| +3..+6 | flags.b5 ? `*(u32)0x400426` : `00 00 00 00` | Information | `0x01175A`–`0x01178A` |
| +7 | `0x0B` | additional sense length = 11 | `0x011790` |
| +8..+11 | `0x00` | command-specific info | `0x01179A`–`0x0117AE` |
| +12 | **rec[2]** | **ASC** | `0x0117B4`–`0x0117B8` |
| +13 | **rec[3]** | **ASCQ** | `0x0117BE`–`0x0117C2` |
| +14..+15 | `0x00` | FRU / SKS 首字节 | `0x0117CA`/`0x0117D2` |
| +16..+17 | flags.b3 ? `*(u16)0x40042A` : `00 00` | Sense-Key Specific | `0x0117D4`–`0x0117F6` |
| +18 | **rec[4]** | 附加 sense 首字节（厂商自定义） | `0x0117F8`–`0x0117FC` |

合计 **19 = 0x13 字节**，与 `0x0116C0` `mov.w #0x0013,e0; mulxu.w e0,er0` 构造的 sense 队列步长 `0x400464 + n*0x13` **字节级吻合**。
`rec[1]` 全部取值 ∈ `0x00..0x0B`，正好塞进 sense 字节 2 的低 4 位（SK 位域）。**布局由此锁死为 5 个独立 u8。**

> 两个含 u16 的候选被此表直接证伪：全表 6 个消费点**没有一条** `mov.w @(n,er5)` / `mov.w @er5`，全是 `mov.b @(0x1..0x4, erN)`。

### 1.3 判据二：`0x01750E` 起 120+ 指令（函数 `0x0174BC`–`0x0176CC`）

```asm
0x0174CA  mov.w r0,r5        ; r5 = 入参低16 = 状态码 (0x400402)
0x0174CC  mov.w e0,e5        ; e5 = 入参高16 = 结果码 (0x400404)
0x0174EA  mov.w @0x449b0a,r0 / cmp.w e5,r0 / bne 0x017500  ; 结果码没变?
0x0174F4  mov.w @0x449b08,r0 / cmp.w r5,r0 / beq 0x0175a4  ; 状态码没变 → 整段跳过
0x017500  mov.w e5,e5 / beq 0x01759c   ; 结果码 0 → 不处理
;; ---- 路径 A：结果码 ----
0x01750C  mov.w e5,r0
0x01750E  jsr   0x0211b6     ; r0 = field2（0x03E390 查表，原值返回）
0x01751E  mulxu.w e0,er0     ; ×5
0x017520  add.l #0x0001914a,er0
0x017532  mov.b @er0,r0l     ; ← 只按字节取 b0
0x01753E  btst #7,r0l / bne 0x017594   ; b7=1 → 只存码，不发布
0x017548  btst #1,r0l / beq 0x017594   ; b1=0 → 不发布
0x017552  mov.b @(0x1,er0),r0l → 0x449af1
0x017562  mov.b @(0x2,er0),r0l → 0x449af2
0x017572  mov.b @(0x3,er0),r0l → 0x449af3
0x017582  mov.b @(0x4,er0),r0l → 0x449af4
0x01758C  mov.w #0x0020,r0 / bsr 0x016ab0   ; 发布
0x017594  mov.w e5,@0x449b0a
;; ---- 路径 B：状态码（0x0175B6–0x017684，与 A 同构）----
0x0175B6  mov.w r5,r0 / jsr 0x0211b6 → ×5 + 0x01914A
0x0175E8  btst #7 → bne 0x01765e
0x0175F2  btst #0 → 置位时要求 e5 ∈ {0x2000,0x3000}（0x017600/0x017606）
0x017612  btst #1 → beq 0x01765e
0x01761C… mov.b @(0x1..0x4,er0) → 0x449af1..0x449af4 ; bsr 0x016ab0
0x01767E  mov.w r5,@0x449b08
```

**判读**：`rec[0]` 只做 `btst` 位测试（**是标志位掩码**）；`rec[1..4]` 只做 `mov.b` 逐字节搬运（**是数据**）。
全函数**没有任何** `jsr erN` / `jmp @erN` / `cmp.w` 落在记录字节上 —— 记录里没有操作码，也没有分派键。

### 1.4 其余四个消费点（同一算式，同一用法）`[实证]`

| PC | 公式 | 用法 |
|---|---|---|
| `0x0116D0`–`0x0116D6` | `mov.w #5,r0; mulxu.w r6,er0; mov.b @(0x1914a,er0),r0l` | **只读 `rec[0]`**，`btst #6` → 置位则跳过 `bsr 0x011882` |
| `0x022B0A`（函数 `0x022AD6`） | `mov.w @0x400436,r5; ×5; +0x01914A` | `rec[1..4]` → `0x4007D2..0x4007D5` |
| `0x022C0C`（函数 `0x022BF2`） | 同上 | `rec[1..4]` → `0x4007D2..0x4007D5` |
| `0x027D8E`（函数止于 `0x027DC2`） | `mov.w @er6,r0; jsr 0x0211b6; ×5; +0x01914A` | `rec[1..4]` → `0x4206EE..0x4206F1` |

四处**全部**是 `mov.b @(0x1..0x4, er5)` 逐字节搬，零算术、零分支。

**结论**：布局 = 5 × u8，b0 = flags、b1..b4 = 载荷。 `[实证]`

## 2. 字段语义

### 2.1 `flags`（b0）位表 `[实证]`

| 位 | 检查点 | 置位效果 |
|---|---|---|
| b7 | `0x01171E`、`0x01753E`、`0x0175E8` | **抑制**：不生成 sense / 不发布（表内 3 条：`0x01`=C0、`0x02`/`0x03`=80，载荷全 0） |

### 2.2 `rec[1..4]` = SK / ASC / ASCQ / 厂商子码

`[实证]` 落位见 §1.2：byte12 = rec[2]、byte13 = rec[3]，正是 SCSI 固定 sense 的 ASC / ASCQ 位置。

`[实证]` **硬编码旁证**：`0x016B20`–`0x016B44` 在 `0x449AF0 == 0x10` 时直接写常量
`02 → 0x449AF1`、`04 → 0x449AF2`、`03 → 0x449AF3`、`07 → 0x449AF4`，正是 `rec[142]`（`0x1100`）的 `02 04 03 07`。
而 `0x449AF0` 由 `0x016C10` 从 `0x4003FB` 归一化而来（`0x11..0x1F` 原样抄，否则写 `0x10`）——即"片夹在位、未识别完成"→ `02 04 03 07`，与 `calib_2753E.md` §3.1 对齐。

标准 sense 直读：`02 04 03` = NOT READY / LU NOT READY / MANUAL INTERVENTION REQUIRED；
`02 04 02` = …/ INITIALIZING COMMAND REQUIRED；`02 3A 00` = NOT READY / MEDIUM NOT PRESENT；
`04 08` = HARDWARE / LU COMMUNICATION FAILURE；`04 44` = HARDWARE / INTERNAL TARGET FAILURE；
`04 53` = HARDWARE / MEDIA LOAD OR EJECT FAILED；`04 15` = HARDWARE / RANDOM POSITIONING ERROR。
SK 全集 9 个（`04`×62、`02`×15、`03`×15、`05`×14、`0B`×13、`06`×8、`09`×7、`01`×5、`00`×4）；ASC 全集 37 个取值。
`[推断]` rec[4] 是 Nikon 私有子码（`0x0E10→05`、`0x5000→06`、`0x1100→07` = "未就绪"三阶段，见 `calib_2753E.md` §5）。

## 3. `0x01750E` 在干什么

`0x01750E` 是函数 **`0x0174BC(er5 = [结果码:状态码])`** 的第一条查表指令。

**它是「固件内部结果码 / 状态码 → 主机可见状态帧」的发布中枢，不是命令分派器。** `[实证]`

```
主循环 0x020B84
  ├─ 0x020BC2 mov.w @0x400404,e0   ; 结果码（0000/1100/2000/3000/5000/9000/0E00/0E10）
  ├─ 0x020BC8 mov.w @0x400402,r0   ; 状态码（0010/0110/0120/0810/0F20…）
  └─ 0x020BCE jsr 0x0174bc
        ├─ 0x01750E / 0x0175B8  jsr 0x0211b6      ; 0x03E390: code → field2
        │      └─ ×5 + 0x01914A → 5 字节 sense 记录
        │           ├─ 门控 b7/b1（+b0 与结果码 0x2000/0x3000 的联合条件）
        │           └─ rec[1..4] → 0x449AF1..0x449AF4
        └─ 0x01758C bsr 0x016AB0(0x20)
               ├─ 0x016C10 : 0x4003FB → 0x449AF0
               ├─ 0x016F46 : 构造 0x22 字节 0xAA 状态帧
               │             （+0x11 = 0x449AF0，+0x12..+0x15 = rec[1..4]，+0x1F = 0x55 结尾）
               └─ 0x016C46 : 发送
```
另一处调用点 `0x0110BC`（同样 `mov.w @0x400404,e0 / mov.w @0x400402,r0`）。

三条并列下游：
1. **`0x0116A0` → `0x011708`**（由命令分派器 `0x020EBA` 进）→ 真正 19 字节 **SCSI REQUEST SENSE**；
2. **`0x0174BC`**（主循环，每轮一次）→ `0xAA` **厂商状态帧**；
3. **`0x022AD6` / `0x022BF2` / `0x027D5x`** → `0x4007D2` / `0x4206EE` 的本地状态快照。

`0x0211B6` 全镜像 **9 个**调用点：`0x01750E`、`0x0175B8`、`0x021562`、`0x0215FE`、`0x0216D6`、`0x021728`、`0x022FC0`、`0x02381E`、`0x027D84`（`table_03E390.md` 记的 7 处漏了 `0x021562` 与 `0x027D84`）。

实测高字节 **15 组**（任务书给的 12 组少了 `0x0E`、`0x11`、`0x50`，见 §7）：

| `0x06` | 10 | `00-04 10-14` | `0311` `0460` | 全 `00` |
| `0x09` | 9 | `10-14 20 30 40 50` | `0161` `0311` | 全 `03` |
| `0x0F` | 6 | `10 20 30 40 50 60` | `0403` `0408` `0415` `0444` | `00`/`02` |
| `0x01` | 4 | `10 20 21 22` | `0415` `0462` | `00`/`03` |
| `0x05` | 3 | `00 01 02` | `0453` | 全 `03` |
| `0x04` | 1 | `30` | `0415` | `00` |
| `0x0E` `0x10` `0x11` `0x20` `0x30` `0x50` | 各 1 | 全 `00` | **全 `0204`** | `00`/`02` |
| `0x40` `0x90` | 各 1 | 全 `00` | **全 `023A`** | `00` |

**判定**：高字节**不是**"命令类别"，而是**错误/状态大类** `[实证]`：
- `{0x0E 0x10 0x11 0x20 0x30 0x50}` 六组（各 1 条，低字节全 `00`）→ **全部** `02 04`（NOT READY / LU NOT READY），正是 `calib_2753E.md` §3.1 的"结果码族"（`0x0E10`/`0x1000`/`0x1100`/`0x2000`/`0x3000`/`0x5000`）。
- `{0x40 0x90}` → **全部** `02 3A`（MEDIUM NOT PRESENT），同属结果码族。
- 其余 7 组（`01/04/05/06/08/09/0F`）是**硬件/介质故障族**，组内由低字节再分：`0x08` 族低字节的**十位**（`0/3/4/5/6/7/8/9/A/B`）决定 SK+ASC，**个位**（`0-4`）决定 `rec[4]` 的高半字节 `{0,1,2,3,9}`。
  `[推断]` 低字节 = 「故障子类（十位）× 通道/轴编号（个位 0–3，9 = 特殊）」。
  反证条件：若 `0x08` 族个位为 4 的记录其 `rec[4]` 高半字节不是 `9`，该读法作废。

## 8. 未解疑问

1. **`rec[4]` 的真实语义**：落在 19 字节 sense 的 +18（附加 sense 首字节），但 `0x0E10/0x5000/0x1100` 三条只有它不同（`05/06/07`）。是"阶段号"还是"厂商限定符"，需主机侧 `NKDUSCAN.dll` 的 sense 解析代码对照，本轮未做。
2. **`0x400426` / `0x40042A`**（flags.b5/b3 时的 Information 与 SKS 来源）由谁写未追，仍为未解项（引导块镜像本地已有，可直接查；不在引导块的前提下更可能是应用内未被引用的变量）。
3. **`0x016C46`**（`0xAA` 帧发送端）未反汇编，故"帧发给谁（SCSI `0xE1`？诊断口？）"未定。
4. **36 个空槽位**是否还有第三条动态索引路径（如从 `0x03E5D8` 的 key→handler 列表间接算出索引）未穷尽；本轮只覆盖了立即数常量与 `0x0211B6` 两条路径。
5. **`0x019100`–`0x019149`** 的 8 字节/条表（`00 08 … / 00 01 1A 9C 03 00 00 7F` 结构）与本表相邻但语义未解，留给后续。
