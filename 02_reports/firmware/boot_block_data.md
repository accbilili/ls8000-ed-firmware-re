# 引导块数据侧（B18）+ B3 机制最终判决

日期：2026-10-24 23:20–23:55 · 脚本：`_jobfuncs\boot_data.py` · 只读样本

## 0. 一句话结论

**引导块 64 KB 的 99.7% 是擦除态 0xFF，真正的内容只有四块：92 项表（0x0000–0x016F）、144 字节桥接代码（0x0180–0x0213）、一个单字节命令集选择器（0x17E）、出厂设置记录（0x6000–0x601F）。**
**B3「写引导块 flash」的机制成立**（agent_b3 的结论正确），但**寄存器与地址的描述需更正**：实际是「同址命令」写 Intel 28Fxx flash，目标 16 位地址 `0x6000`，芯片地址 `0x60000/0x70000`。

## 1. 引导块内容地图 `[实证]`

```
0x00000–0x0016F   92 项 × u32 表（向量表 / 描述表混合）
0x00170–0x0017D   0xFF（擦除态）
0x0017E           0x53   ★ flash 命令集选择器（单字节，擦除区里唯一被编程的字节）
0x00180–0x00213   代码：复位 0x180（11 条）+ 缝隙 0x192（30 条）+ 共享尾 0x1FC
0x00214–0x0027F   0xFF
0x00280–0x00287   两个桩：0x280 = nop; bt 0x280 ／ 0x284 = nop; bt 0x284
0x00288–0x05FFF   0xFF
0x06000–0x0601F   ★ 出厂设置记录（33 B 结构的前 32 B）
0x06020–0x0FFFF   0xFF
```
非零字节合计 65,310 / 65,536 ⇒ **除上述四块外全是擦除态**。

### 1.1 两个桩 = 「未处理中断就挂死」`[实证]`

```asm
0x000280  nop
0x000282  bt 0x000280     ; = BRA 自身 → 死循环
0x000284  nop
0x000286  bt 0x000284     ; = BRA 自身 → 死循环
```
表里 **80 项 → `0x284`**、`vec[7]` → `0x280`：即**除复位外的所有 H8 异常向量都指向「挂死」**。
**设计含义**：固件不打算处理任何异常；一旦有未预期的中断/异常，设备**挂起而不是复位**（与实机现象吻合：驱动超时 → SCSI 层报错，但设备可能仍在跑）。
**另一层含义**：**引导块里没有 ISR**——`0xFFDCxx` 那 9 项不是被跳转到，而是「1394 中断源寄存器地址」被存在表里（切分问题见 §5.1）。

## 2. 出厂设置记录（`0x6000`）结构 `[实证]`

```asm
0x06000: 00 00 00 85 | 00 00 00 00 | 00 00 00 00 | 00 00 | FF FF
0x06010: 00 04 FC 27 | 00 05 3A D3 | 00 03 42 95 | 00 0E 23 56 | 00
0x06020: 00 00 FF FF ...
```

按 **33 字节参数块**（B3 组装到 `0x400CA0` 的同一格式）解读：

| 偏移 | 长度 | 字段 | stock 值 |
|---|---|---|---|
| +0x00 | 4 | **V1**（32 位大端）＝ 位置偏移 | `0x00000085` = **133** |
| +0x04 | 4 | **V2**（32 位大端） | 0 |
| +0x08 | 5 | 附加字节 | 0 |
| +0x0D | 1 | 0（填充） | 0 |
| +0x0E | 2 | `FF FF` | FFFF |
| +0x10 | 17 | **模板** | 见 §2.1 |
| +0x21 | 12 | `FF FF …`（擦除态） | — |

### 2.1 模板 17 字节 = 4 组 (count, value) + 终止 `[实证]`

原始：`00 04 FC 27 | 00 05 3A D3 | 00 03 42 95 | 00 0E 23 56 | 00`
消费点 `0x03109A` 起按 **u32 字**取：

```asm
0x03109A  er0 = @0x006010 ; → sp+0x54      ; = 0x0004FC27
0x0310A8  er0 = @0x006014 ; → sp+0x58      ; = 0x00053AD3
0x0310B6  er0 = @0x006018 ; → sp+0x5C      ; = 0x00034295
（下一组 @0x00601C → sp+0x60 = 0x000E2356；末字节 @0x006020 = 0x00）
```
⇒ 结构为 **4 组 (小 u16 = 个数, 大 u16 = 值)** + 1 字节 0：

| 组 | 个数 | 值 | 备注 |
|---|---|---|---|
| 1 | 4 | 0xFC27 = 64551 | |
| 2 | 5 | 0x3AD3 = 15059 | |
| 3 | 3 | 0x4295 = 17045 | |
| 4 | 14 | 0x2356 = 9046 | |
| — | 0x00 | — | 终止标记 |

**未解**：这 4 组的业务含义（哪些实体、什么量）。已在 §5.2 记录。

### 2.2 记录的读取点（应用侧）`[实证]`

| 地址 | 读什么 | 说明 |
|---|---|---|
| `0x027154` | `mov.b @0x00600D, r0l` | **有效标志**：≠0 → 记录无效 |
| `0x027166` / `0x027176` / `0x027180` / `0x02718C` | `@0x006000` 的 4 字节 → 依次写入工作缓冲 +1..+4 | **V1 按自然字节序展开** |
| `0x027196` / `0x0271A6` / `0x0271B0` / `0x0271BC` | `@0x006004` 的 4 字节 → +5..+8 | **V2** |
| `0x03109A`–`0x0310BE` | `@0x006010/14/18` → sp+0x54/58/5C | 模板 4 组 |
| `0x02692A` | `er6 = 0x00006010; jsr 0x011900` | 从 flash 读 **16 字节**模板（`0x011900` = 通用 flash 读；长度须 ≤16，否则 `0x50`） |

## 3. flash 驱动（应用 ROM `0x17708` → RAM `0x400F5A`）`[实证]`

### 3.1 RAM 驻留代码搬运（更正 agent_b3 的范围）

```asm
0x0176CE  jmp 0x400F5A          ; 擦除分发器入口
0x0176D2  jmp 0x401134          ; 另一 RAM 分发器入口
0x0176D6  (保存 er4/er5/er6)
0x0176E2  er5 = 0x00017708      ; ★ 源：ROM 0x17708
0x0176E8  er6 = 0x00400F5A      ; ★ 目标：RAM 0x400F5A
0x0176EE  r4  = 0x0370          ; ★ 长度 880 字节
0x0176F2  eepmov.w              ; 块搬移
0x0176F6  mov.w r4, r4 ; bne    ; 等完成
```
> **更正**：agent_b3 记「flash 驱动源码 ROM `0x17AB4–0x17F04`（336 B）」——**实测是 ROM `0x17708` 起 880 字节**，目标 RAM `0x400F5A`。分发器入口为 `jmp 0x400F5A`（擦除）与 `jmp 0x40121C`（编程），第二个 `jmp 0x401134` 是第三个入口。

### 3.2 命令集选择器 `@0x17E`（6 处读取）

```asm
0x017708  r0l = @0x00017E
0x017710  == 0x00 → 0x017726   ; 字节宽命令集
0x017716  == 0xFF → 0x017726   ; 字节宽
0x01771C  == 0x53 → 0x01772E   ; ★ 本机 = 字宽命令集
0x017726  bsr 0x01773A          ; 字节宽擦除
0x01772E  bsr 0x017812          ; 字宽擦除
```

### 3.3 擦除例程（字宽 `0x01773A`）：**同址命令**

```asm
0x017750  er6 = @0x449ACC        ; 目标地址（RAM 参数槽）
0x017758  er0 = 0x00060000 ; cmp er6,er0 ; beq → 擦除
0x017766  er0 = 0x00070000 ; cmp er6,er0 ; bne → 返回
0x017772  er0 = 0x0000AAAA | er6 ; @er0 = 0xAA      ; ★ 解锁 1
0x017782  er0 = 0x00005554 | er6 ; @er0 = 0x55      ; ★ 解锁 2
0x017792  er0 = 0x0000AAAA | er6 ; @er0 = 0x0080    ; ★ 擦除命令 0x80
0x0177A2  er0 = 0x0000AAAA | er6 ; @er0 = 0xAA      ; 再解锁（供后续编程）
0x0177B2  er0 = 0x00005554 | er6 ; @er0 = 0x55
```
编程例程（字宽 `0x017812`）：目标必须 ∈ {`0x60000`, `0x70000`}，否则返回；随后 `bsr 0x01785A` 执行 `0xA0` 编程命令 + bit7 轮询。

> **机制定性**：这是 **Intel/AMD 28Fxx 系列 flash 的标准「同址命令」**——命令写在目标单元本身（`0xAAAA`/`0x5554` 是命令别名），**不是**通过某个独立邮箱寄存器。
> **目标地址**：RAM 参数槽里是 **16 位** `0x6000`，而 flash 命令地址是 **20 位** `0x60000`／`0x70000` ⇒ 存在 ×16 的地址换算（`0x6000 << 4 = 0x60000`），换算点在 RAM 驻留分发器内（`0x449ACC` 由 `0x016D66`/`0x016EDE` 从 `0xFFDC34` 取值后写入）。

## 4. B3 机制：最终判决 —— **成立**（描述需更正）`[实证]`

### 4.1 完整链条（作业函数 `0x02BBAE`）

```asm
; ① 组装 33 B 参数块 @0x400CA0：V1(4) V2(4) 5B 00 FFFF + 模板17B（从 0x6010 拷入）
0x02BC54  er4 = 0x00006010                ; 模板源
0x02BC5C–0x02BC70  循环 17 次：模板 → 参数块 +0x10..+0x20
; ② flash 编程请求
0x02BC72  er0 = 0x00006000
0x02BC78  @0xFFDC34 = er0                 ; ★ 目的地址 = 0x6000（16 位）
0x02BC80  jsr 0x010BD2                    ; = orc #0x07,exr（关可屏蔽中断）
0x02BC84  r4 = @0x00FFFED2 ; &= 0xFFFC ; |= 3 ; @er5 = r4      ; ★ flash 控制字置位
0x02BC96  jsr 0x017A78                    ; = jmp 0x400F5A（RAM 擦除分发器）
0x02BC9A  jsr 0x010BD8                    ; = andc #0xf8,exr（开中断）
0x02BC9E  @0x400D38 = 0x21                 ; ★ 长度 33
0x02BCA6  @0xFFDC30 = er6(0x400CA0)        ; ★ 源地址 = 参数块
0x02BCAE  jsr 0x010BD2 ; jsr 0x017A7C      ; = jmp 0x40121C（RAM 编程分发器）
0x02BCB6  r4 = @0x00FFFED2 ; &= 0xFFFC ; |= 3 ; @er5 = r4
0x02BCC2  jsr 0x010BD8                    ; 开中断
; ③ 回读校验 + 机构重定位
0x02BCC6  bsr 0x02BCCE
```

### 4.2 回读与重定位（`0x02BCCE`）—— 本轮新解出

```asm
0x02BCD2  r1 = @0x00FFFF48 ; |= 0xF000 ; @er0 = r1     ; 置某控制位
0x02BCE0  @0x440E50 = @0x03F0F9                        ; 包 ID
0x02BCEC  bsr 0x02BAA6                                  ; ★★ 轴1 三步伐进（与 0x81 同一条）
0x02BCF0  r0 = @0x400402 ; ==0x0120/0x0121 → 退出        ; 失败即止
0x02BD08  r0l = @0x00600D ; bne 0x02BD40                ; ★ 有效标志：非 0 → 用默认
0x02BD10  er0 = @0x006000 ; cmp #0xFFFFFED4 ; blt 0x02BD40   ; ★ V1 < −300 → 默认
0x02BD20  er0 = @0x006000 ; cmp #0x0000012C ; bgt 0x02BD40   ; ★ V1 > 300 → 默认
0x02BD30  er6 = @0x006000 ; er6 += 0x14D                ; ★ 目标 = V1 + 333
0x02BD40  er6 = 0x14D                                    ; 默认目标 333
0x02BD48  e0 = 0x64(100) ; r0 = r6 ; bsr 0x02B8EA         ; ★ 轴1 绝对移动
```

### 4.3 判决与更正

| 项 | agent_b3 的说法 | 实测判决 |
|---|---|---|
| B3 写引导块 flash `0x6000` | ✔ | **成立** |
| `0xFFDC34` = 目的指针 | ✔ | **成立**（16 位 `0x6000`；另有多处 32 位写） |
| `0xFFDC30` = 源指针 | ✔ | **成立**（`0x400CA0`） |
| `0x400D38` = 编程字节数 | ✔ | **成立**（`0x21` = 33） |
| `0xFFFED2` = flash 控制字（\|=3） | ✔ | **成立**（flash 前后各置一次） |
| `0x010BD2/0x010BD8` = 中断屏蔽对 | ✔ | **成立**（`orc #0x07,exr` / `andc #0xf8,exr`） |
| 驱动源码范围 `0x17AB4–0x17F04`（336 B） | ✘ | **更正：ROM `0x17708` 起 880 B → RAM `0x400F5A`**；另两个分发器入口 `jmp 0x40121C`（编程）、`jmp 0x401134` |
| flash 命令机制 | 「同址写 0xAAAA/0x5554」 | **成立且更明确**：命令写在 `目标\|0xAAAA`／`目标\|0x5554`；目标 16 位 `0x6000` ↔ 芯片地址 `0x60000`/`0x70000`（×16 换算）；命令集选择器 `@0x17E`=0x53 → 字宽（0xAAAA/0x5554），0x00/0xFF → 字节宽（0xAAA/0x554） |
| 「−300…+300」的含义 | 参数范围 | **两处都有**：解析层 `er3`=payload[1..4] 门限（`0x026E86/8E`）+ 执行层回读 V1（`@0x6000`）门限（`0x02BD10/20`），一致 |
| B3 是否只写 flash | 部分 | **还先动机构**：`0x02BCEC bsr 0x02BAA6` = 轴1 三步伐进，之后才绝对移动到 V1+333（`0x02B8EA`，速度参数 0x64=100） |

**⇒ B3 的「持久设置写 + 机构重定位」结论完全成立**；第四轮我在 `boot_block_code.md` §4 标的「待重审」可以**撤销**，但其中的地址级错误（驱动范围、芯片地址）要按本表更正。

## 5. 未解决的疑问

1. **表 `0x0000` 的切分**：92 项里 9 个 `0xFFDCxx` 项的归属——既然 `0x280/0x284` 是挂死桩、且 `0xFFDCxx` 是 1394 控制器寄存器地址，这 9 项更像是「1394 中断源 → 寄存器映射」表而非向量。**但表在引导块 ROM 里、没有任何代码读它**（引导块只有 144 字节且不引用该表）⇒ 谁读它？H8 硬件（VBR=0）会把它们当向量跳转到寄存器地址——除非这些中断永远不触发。**需要实机或 H8/300H 手册确认向量表布局。**
2. **模板 4 组 (count, value) 的业务语义**（4/0xFC27、5/0x3AD3、3/0x4295、14/0x2356）——与已知常数无明显对应（`0xFC27`=64551、`0x3AD3`=15059、`0x4295`=17045、`0x2356`=9046）。
3. **`0xFFDCxx` 窗口的物理归属**：1394 控制器与 flash 控制器共用同一命令窗（boot 写 0x3C–0x48，应用写 0x30/0x34），还是同一 ASIC 块的两组寄存器？
4. `0x420736`（缝隙函数读的第 3 个状态字节）是什么。
5. `0x4001`（镜像选择字节）由谁写、何时写 0。
6. `0x449AC6` 的语义（被当成「标志」用，`0x016D56` 从某处取 1 字节写入）——它同时充当编程例程的「长度/计数」。
