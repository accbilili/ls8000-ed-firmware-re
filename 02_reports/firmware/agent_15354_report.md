# E0 参数校验六数值出处判决报告（agent_15354）

**结论先行：六个数值全部在固件中找到判决性比较指令，且全部位于同一函数——E0 解析层 `0x026BF8`。**
前序「找不到」的原因是搜索形态错误：实际编码是 `cmp.l #imm32, er3`（`7A 23 <imm32 大端>`），不是 `cmp.w #imm16`。

## 2. 搜索方法论与完备性

1. **CFG 层**：扫 `cfg_v4.json` 全部 27,215 条指令的立即操作数，命中 14 条（含非比较）。
2. **原始字节层**：全镜像（228,345 B）搜大端立即数字节模式并回溯 2/4/6/8/10 字节试解码（修复版 h8fix 加载器）：
   - `3B FA`（15354）：**1 处** → 即 `0x026DF8` 的 cmp.l
   - `0C D3`（3283）：**1 处** → 即 `0x026E1C` 的 cmp.l
   - `01 C2`（450）：24 处 → 6 处指令级（§4.2），其余为数据/巧合
   - `01 2C`（300）：6 处 → 4 处指令级（§4.4），其余为数据/巧合
   - `FE D4`（−300）：7 处 → 2 处 cmp.l（`0x026E86`/`0x02BD18`），其余 5 处为分支指令位移字节巧合
   - 8 位形态 `A0 0n C2/D3/2C`（cmp.b #imm8）：**0 处**——排除 8 位比较形态
3. **反向验证**：`0x026EFC`（主命令 0xE1 处理器，249 条指令）与 `0x0269A6`（执行器）内**均无**六数值——校验只存在于解析层。

## 3. `0x026BF8` 结构与 E0 块布局（新查明，前序未记录）

**入口坐实**：主命令分派表 `0x03E2E8`（8 字节/条 `[cmd:u8][?:u8][flags:u16][handler:u32]`）条目 `0x03E378: E0 → 0x026BF8`；消费代码 `0x020EC0`（用 `@0x40043C` 的命令字节匹配后 `jsr er3`）。[实证]

**E0 块（13 字节 @ `0x40043C`）布局与校验流程**：

| 偏移 | 内容 | 校验 |
|---|---|---|
| [0] | `0xE0` 命令字节 | 分派表匹配 |
| [1] | 参数高字节/标志 | 低 5 位必须为 0（`0x026C1A` and.b #0x1f; bne） |
| [2] | **子功能 ID** | `0x03EDB8` 表匹配（[id][最小长度码]，0xFF 终止：0x40/0x41/0x42→11，0x91/0x92/0xC1→5，0xA0→9，0xB3→13，0x80/0x81/0xB0/0xD0→0）+ `0x026DAE` 起 12 路 cmp.b 分派链 |
| [3][4][5] | 0 | 循环检查必须为 0（`0x026C24-0x026C3A`） |
| [6][7][8] | 长度 L = cdb[6]+cdb[7]·256+cdb[8] | 表内最小长度码 ≤ L ≤ 13（`0x026CBC` bcc / `0x026CD4` cmp.l #0x0d bls）——即前序记载的「表内长度 ≤ 分配长度 ≤ 13」 |
| [9] | 0 | 必须为 0（`0x026C3C`） |
| [10..12] | 载荷尾部 | 通过后 cdb[2]→`0x400C55`，cdb[0..L-1]→`0x400C56`（`0x026EB6-0x026EEA`） |

**被校验的参数 er3 装配**（`0x026D10-0x026D40`）：
```
er3 = (cdb[1]<<8) + cdb[2] + (cdb[3]<<8) + cdb[4]
```
cdb[3]/cdb[4] 恒 0，故 **er3 = cdb[1]·256 + 子功能号**（16 位大端参数，低字节即子功能号）。六条范围校验全部作用于 er3。

> **📌 R25 更正记录**：上式（`er3` = CDB[1]·256 + 子功能号）**仍不成立** ——
> 根因是把 `er5` 误当成 CDB 基址。实际序言是
> `0x026C0C mov.l #0x00000001, er5` / `0x026C12 add.l sp, er5`
> ⇒ **`er5 = sp+1`，是 data-out 相位 payload 的暂存区**；CDB 基址是 `er4`（`0x40043C`）。
>
> **正确的 `er3` 公式 = `BE32(payload[1..4])`**（32 位大端 V1），
> 由指令级模拟器实跑确认（`03_analysis/_pkgtool/sim_verify_formulas.py`，
> 测试 payload `11 22 33 44 …` → `er3 = 0x11223344`）。
>
> ⇒ §4.5 基于旧式得出的「`0x91/0x92` 恒不可满足」结论**仍然失效**，
> 正确表述为「布尔参数校验」（`er3 ∈ {0,1}`）。
>
> **本报告 §1 判决表与 §3 的「12 路 cmp.b 分派链」经复核为正确。**
> 完整证据见 `03_analysis/firmware/E0子功能分派与校验表-实测补全.md`。

**错误码**：`0x50` = 结构/格式错误（保留字节非 0、长度越界、未知子功能 `0x026EAE`）；`0x53` = 参数越界。0x53 与另一条命令路径的参数块引擎 `0x025A56`（`0x025AA2`）一致，跨模块坐实「0x53 = 参数越界」。

**A0 旁支**（非六数值，备查）：`0x026E3E-0x026E84` 用 `0x018E1E`(乘)/`0x01872E`(除) 做动态换算——er3 ≤ u16@`0x4007BE`·10000/4000，第二值 ≤ u16@`0x4007BE`·42739/4000（常量 0x2710/0xFA0/0xA6F3）。

## 4. 逐个数值的甄别细节

### 4.1 15354 / 3283 [实证，无歧义]
全镜像各仅 1 处字节模式，即 `0x026DF8` / `0x026E1C` 的 `cmp.l #imm32, er3` + `bls`（≤ 通过，越界 0x53）。

### 4.2 450：E0 校验 2 处 + 4 处无关命中 [实证]
- E0 参数校验：`0x026E0A`（0x41）、`0x026E2E`（0xC1）。
- `0x03A49E`/`0x03AE20`/`0x03AE78`：`mov.w #0x01c2` 加载（A0 处理器 `0x03A3D4` 链内），非比较。
- `0x03AEE6`：`cmp.w #0x01c2, r0; bls` —— A0 处理器内**循环上界**（循环体 0x03AED2-0x03AEE4），与 E0 校验无关。
- `0x03B410`/`0x03B4CC`：`cmp.w #0x01c2, r6; beq` —— 曝光标定逻辑（owner `0x03B0E8`，float 运算区）中「r6==450」的特殊值判断，选择状态码 0x0920/0x0930 写 `0x400402`，非参数校验。

### 4.3 −300：2 处 cmp.l，均为 ±300 守卫 [实证]
- `0x026E86`：E0 解析层 0xB3 下界（er3 < −300 → 0x53）。
- `0x02BD18`：电机作业函数（CFG 未覆盖，raw 扫描+回溯解码抓到）`cmp.l #0xfffffed4, er0; blt` 与 `0x02BD28 cmp.l #0x12c, er0; bgt` 配对——入参 er0 或 `*(u32*)0x6000` 越出 ±300 则跳过马达动作（基值改 333=0x14D），是执行层的二次守卫，佐证 ±300 语义。

### 4.4 300：E0 校验 1 处 + 3 处无关命中 [实证]
- E0：`0x026E8E`（0xB3 上界，与 0x026E86 配对）。
- `0x02BD28`：见 4.3（马达 ±300 守卫上界）。
- `0x02C040`：`mov.w #0x12c, r1; divxu.w r1, er0` —— 0x42 作业链单位换算除数（er0/300 → `0xFFFFF8`）。
- `0x02CCE6`：`mov.l #0x12c, er0; jsr 0x015FFC` —— 0x81 作业链传给助手（疑似延时/等待）的参数。

### 4.5 0x91/0x92「必须 0 或 1」：指令存在且活，但恒不可满足 [实证+推断]
`0x026E9C-0x026EA8`：
```
mov.l er3, er3      ; H8/300H 的 MOV 会测试传送数据并置 N/Z（V 清零）——Hitachi H8/300H 编程手册实锤
beq  0x026eb6       ; er3 == 0 → 通过
cmp.l #0x00000001, er3
beq  0x026eb6       ; er3 == 1 → 通过
mov.w #0x0053, r0   ; 否则 0x53
```
**「活代码」判定依据**（排除前序可能的「死代码」误判）：
- H8/300H 手册：MOV 置 Z（本报告 Web 检索引 Hitachi H8/300H Series Programming Manual §2.2.35：MOV "tests the transferred data, and sets condition-code flags... Z: Set to 1 if the data value is zero"）。
- 全镜像统计佐证：CFG 内 `cmp.l #0x00000000` **0 次**、`tst.*` **0 次**（H8/300H 无 TST），而 `mov.l erX,erX` **37 次**（多后接条件分支）——零测试惯用法就是 MOV。
- 反证案例 `0x02848C`：`mov.l @0x400522, er5; mov.l er5,er5; beq` 是「while(er5!=0)」计数循环头；若 MOV 不置位，进入循环时 Z 残留自上一条 `sub.l er0,er0`（恒 1），循环将永远第一轮退出成为死代码——不合理。

**但**：er3 = cdb[1]·256 + 子功能号，0x91/0x92 的子功能号为 145/146，er3 ≥ 145 > 1，**该等式检查对 0x91/0x92 恒不可满足**。推论：E0 0x91/0x92 命令必然在解析层被 0x53 拒绝；执行器 `0x0269A6` 中 0x91→`0x026BB2`（payload 第 5 字节→`0x42029E`）、0x92→`0x026BBE`（→`0x42029F`）的内联分支经 E0 路径不可达（`0x400C55` 唯一校验门就是解析层；另一写者 `0x012A8E` 非校验路径）。
**倾向解释**：0x91/0x92 为固件中保留/停用子功能，或该校验为协议设计缺陷（参数低字节与子功能号合并导致）。[推断]

## 5. 相关但无关的路径（前序线索排查结论）

- **`0x03EBC0` lo/hi 表 + 引擎 `0x025A56`**：属**另一条命令**（`0x400316` 参数块，26 字段）的字段校验。引擎逐条调 handler（表 +4），失败累计偏移并写 0x53。handler 如 `0x025D08`（lo=666,hi=4000）实现 `<lo 或 >hi 拒绝` + 4000/value 换算（错误码 0x04）。表中 lo/hi 为 666/333/4000/512/255/2/0x7FFFFFF 等（dpi 等量纲），**不含**六数值中任何一个——E0 的 0x40/0x41/0x42/0xC1 不经过此路径。
- **`0x024058` + `0x03E5D8`**：SCSI 主命令分派器（`mulxu.w #6` 索引 6 字节/条表 [cmd][?][handler:u32]，命中 `jsr er0`；0xFF 终止；二级表 `0x03E62C` 36 字节/条）。**纯分派，无数值校验**。前序「重点嫌疑区」排除。
- **`0x03E518` 参数描述表**（12 字节/条）：id 0xE0 → size 0x406/addr 0x400855/mask 0x0800 等。mask 是位标志（0x0800/0x0E00/0x1000/0x2000），**不编码数值范围**。

## 6. 前序误判原因（供主文档修订参考）

1. 搜索形态错误：找 `cmp.w #imm16`（`79 2n` 或误记的 `02` 前缀），漏掉 `cmp.l #imm32, er3`（`7A 23`）。
2. 反汇编不完整：只跟到 `0x026CD4`（长度 ≤13 检查）即下结论；六个比较在 `0x026DF8-0x026EA8`，在同一函数后段。
3. 「16/16 抽样命中实为巧合」的教训在此复现：本轮全部结论均以「回溯解码确认指令边界 + 立即数匹配 + 分支极性」三重判据，非数值巧合。

## 7. 对主文档的修改建议

1. **六个数值一个都不要删**——全部坐实（0x91/0x92 见下）。
2. §11.4 表格建议补充/修正：
   - 0x40/0x41/0x42/0xC1/0xB3：维持原值，**引用点统一改注 `0x026BF8` 内 cmp.l 地址**（0x026DF8/0x026E0A/0x026E1C/0x026E2E/0x026E86+0x026E8E），并注明错误码 0x53 写 `0x400436`。
   - 0x91/0x92：「必须 0 或 1」建议改述为：**解析层存在 `er3 ∈ {0,1}` 检查（0x026E9C-0x026EA8），但因 er3 = 参数高字节·256 + 子功能号，0x91/0x92 实际恒越界返回 0x53（该子功能不可用/保留）**。若文档想表达的是 payload 第 5 字节的 0/1 开关语义，应改指向执行器 `0x026BB2/0x026BBE`（直传无校验）。
3. 建议新增 E0 块布局小节（§3 表）：子功能号在 cdb[2]、参数 = cdb[1]:cdb[2] 大端 16 位、cdb[3:6]/cdb[9] 保留必须为 0、cdb[6:9] 为长度（最小长度码见 `0x03EDB8` 表，≤13）。
4. 建议注明 ±300 在执行层有第二处守卫（`0x02BD18`/`0x02BD28`），450/300 在 A0 曝光链另有无关用法（`0x03AEE6`/`0x03B410`/`0x02C040`/`0x02CCE6`），避免后续分析混淆。

## 7b. 补充：team-lead 更正的复核 + 0x43E1(17377) 搜索结果

### 7b.1 作业表 0x03EDE8 复核（确认 lead 更正）
6 字节/条 `[subid:u8][?:u8][handler:u32]`，从 `0x03EDE8` 起逐条复核：
`0x10→0x035598`、**`0x40→0x02AEAA`**（`0x03EDEE: 40 00 00 02 AE AA`，lead 更正确实）、`0x41→0x02B98A`、`0x42→0x02CB66`、`0x81→0x028648`、`0xA0→0x03A3D4`、`0xB0→0x027F24`、`0xC1→0x02BA24`、`0xD0→0x02866E`、`0x80→0x028722`、`0xB3→0x02BBAE`、`0x00→0x028722`。本报告六数值判决在解析层 `0x026BF8`，与此表无关，不受影响。

### 7b.2 0x43E1（17377）搜索 [实证]——不在悬案六数内，属 0x40 作业执行层钳位
全镜像 `43 E1` 字节模式仅 **3 处**（CFG 未覆盖该区，均为 raw 扫描+回溯解码确认）：
1. **`0x02AEFE: cmp.w #0x43e1, r0` + `0x02AF02: bls` + `0x02AF04: mov.w #0x43e1, r6`**（0x40 作业函数 `0x02AEAA` 内）：目标位（payload @(er4+2)）> 17377 时**钳位到 17377**（r6），否则用原目标；随后与当前位置 @er5 比较算方向（r4l）与步数 e6，并装常量 `0x000186A0`（100000）调 `0x02ADCE`。即**走片最大位置 = 17377**。
2. **`0x02AD18: cmp.w #0x43e1, r0` + `0x02AD1C: bcs`**（`0x02AEAA` 的 helper ~`0x02AD0A` 内）：当前位置 `@0x4202A2` ≥ 17377 时查 `@0x440810 == 1` → 走 `0x02ADC8` 特殊路径；否则清 `0x440E3E`、暂存目标到 `0x440E3C` 并写 `@0x4202AA`（目标位，32 位）。
3. 相关 RAM：`0x4202A2` = 走片当前位置，`0x4202AA` = 目标位置，`0x440E3C/0x440E3E` = 移动暂存，`0x440810` = 末端标志。

**结论**：17377 是走片物理极限的执行层钳位（0x40 作业），与 E0 解析层六数值校验（er3 = cdb[1]·256+子功能号）是两套不同机制；文档如提及 0x40 参数上限需区分「解析层 er3 ≤ 15354」与「执行层目标位 ≤ 17377」。

## 8. 未解决的疑问

1. **0x91/0x92 设计意图**：是固件保留的停用功能，还是参数装配缺陷？若主机协议确实需要 0x91/0x92，则固件存在功能性 bug（恒 0x53）。需主机侧协议文档或实测确认。
2. **er3 的 cdb[1]·256+子功能号装配**使 0x41/0x42/0xC1/0xB3 的校验在 cdb[1]=0 时恒通过（0x41→65≤450、0x42→66≤3283、0xC1→193≤450、0xB3→179∈±300）；cdb[1] 的非零合法取值仅 0x20 的倍数（0x20→全部越界）。这是否为协议本意（cdb[1] 实为标志位）待确认。
3. **`0x0118D0`/`0x013994` 拷贝源**：`0x026BF8` 中 `jsr 0x0118D0(sp+1, L)` 把 L 字节拷入栈缓冲区（推定为源自 `0x40043C`，因解析层其余字段直接读 `0x40043C` 且与之一致），但 `0x013994` 内部经 `0x01380C` 的源地址未最终坐实（不影响六数值判决）。
4. **0x4007BE**（A0 动态校验所用的 u16，见 1200/4000 两档模型常量）的语义（最大光学分辨率？）未查。
5. `0x03E2E8` 主命令表中 flags 字段（0x14/0x7D4/0x7FF/0x7CC/0x7FC/0x254 等）的确切含义未查。
