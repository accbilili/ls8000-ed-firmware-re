## 0. 一句话结论

**引导块不是一个「迷你固件」，而是一块 144 字节的 1394 硬件桥接固件 + 一张 92 项向量/描述表**：复位入口按 `0x4001` 选镜像段后跳进应用；应用每轮 `jsr 0x000192` 把准备好的 1394 请求（CDB + 160B 描述块 + 8B 附加块）用 `EEPMOV.B` 推进 1394 控制器寄存器，再跳回应用入口。
**由此推翻一条长期假设**：`0x400408` 不是「交给引导块消费的请求块」——引导块从不引用它；它是应用自己的 E0/C1 参数暂存区。

## 2. B17：引导块代码侧

### 2.1 引导块的物理构成 `[实证]`

```
0x00000–0x0016F   92 项 × u32 表（向量表 / 描述表混合，见 §2.2）
0x00170–0x0020F   代码：复位入口 0x180（11 条）+ 缝隙函数 0x192（30 条）+ 共享尾 0x1FC
0x00210–0x0FFFF   数据（0x6000–0x7FFF 为可写设置记录区；0x17E = 0x53 flash 命令集选择器）
```
**引导块全部可达代码仅 144 字节**（0x180–0x210），其余 64 KB 全是数据。

### 2.2 表 0x0000：92 项，不是纯向量表

| 项 | 值 | 次数 | 判读 |
|---|---|---|---|
| vec[0], vec[1] | `0x000180` | 2 | 复位向量 + 第二个同址向量 |
| vec[2..6], vec[9..15], vec[18], vec[21], vec[23..47], vec[49..55], vec[57..72], vec[74..91] | `0x000284` | **80** | 默认桩（未处理的中断） |
| vec[7] | `0x000280` | 1 | 另一个桩 |
| vec[8] | `0x00FFDC00` | 1 | **1394 控制器寄存器**（非代码地址） |
| vec[16] | `0x00FFDC20` | 1 | 同上 |
| vec[17] | `0x00FFDC1C` | 1 | 同上 |
| vec[19] | `0x00FFDC04` | 1 | 同上 |
| vec[20] | `0x00FFDC08` | 1 | 同上 |
| vec[22] | `0x00FFDC24` | 1 | 同上 |
| vec[48] | `0x00FFDC10` | 1 | 同上 |
| vec[56] | `0x00FFDC14` | 1 | 同上 |
| vec[73] | `0x00FFDC18` | 1 | 同上 |
| vec[92..95] | `0xFFFFFFFF`×3 + `0xFFFF53FF` | 4 | **已是数据**（0x180 处的代码字节） |

**⇒ 该表不是纯 H8 向量表**：0xFFDCxx 这类「寄存器地址」不能作为中断向量被跳转。
**未决**：这 92 项的确切切分（向量表边界在哪、0xFFDCxx 项属于哪张表）待查（见 §5）。

### 2.3 复位入口 `0x000180`（11 条）`[实证]`

```asm
0x000180  mov.l #0x00fffb00, sp      ; 栈顶
0x000186  ldc   #0xc0, ccr           ; CCR = 0xC0（关中断）
0x000188  mov.b #0x00, r0l
0x00018A  mov.b r0l, @0xffdc3c      ; 1394 控制器寄存器 = 0
0x00018E  bt    0x0001fc            ; = BRA（无条件）
0x0001FC  ldc   #0x07, exr          ; 放开可屏蔽中断
0x000200  mov.b @0x004001, r0l      ; ★ 读 0x4001（镜像选择字节）
0x000206  cmp.b #0x00, r0l
0x000208  bne  0x000210
0x00020C  jmp   0x020600            ; ★ 段2 入口
0x000210  jmp   0x010600            ; ★ 段1 入口
```

**⇒「双镜像回退」的选择点在引导块，判据是 RAM 字节 `0x4001`**（0 → 段2 `0x20600`；非 0 → 段1 `0x10600`）。
此前只知道两个入口地址，不知道谁选、依据什么——现在坐实。

### 2.4 缝隙函数 `0x000192`（应用↔引导块唯一调用缝，30 条）`[实证]`

```asm
0x000192  mov.l #0x00fffb00, sp      ; 每次都重设栈顶
0x000198  ldc   #0xc0, ccr
0x00019A  ldc   #0x07, exr
0x00019E  mov.b #0x01, r0l
0x0001A0  mov.b r0l, @0xffdc3c      ; 1394 控制器：模式 1
0x0001A4  mov.b @0x40033a, r0l      ; ★ 3 个状态字节
0x0001AA  mov.b r0l, @0xffdc3d
0x0001AE  mov.b @0x40033b, r0l
0x0001B4  mov.b r0l, @0xffdc3e
0x0001B8  mov.b @0x420736, r0l
0x0001BE  mov.b r0l, @0xffdc3f
0x0001C2  mov.l #0x0040033c, er5    ; ★ 待发 CDB（8 字节）
0x0001C8  mov.l #0x00ffdc40, er6
0x0001CE  mov.b #0x08, r4l
0x0001D0  eepmov.b                  ; ★ 8 B：0x40033C → 0xFFDC40
0x0001D4  mov.l #0x00400344, er5    ; ★ 1394 描述块（160 B）
0x0001DA  mov.l #0x00ffdc48, er6
0x0001E0  mov.b #0xa0, r4l
0x0001E2  eepmov.b                  ; ★ 160 B：0x400344 → 0xFFDC48
0x0001E6  mov.l #0x004003e4, er5    ; ★ 附加块（8 B）
0x0001EC  mov.l #0x00ffdce8, er6
0x0001F2  mov.b #0x08, r4l
0x0001F4  eepmov.b                  ; ★ 8 B：0x4003E4 → 0xFFDCE8
0x0001F8  bt    0x0001fc            ; → 跳去选镜像段（**不返回应用**）
```

**⇒ 职责划分坐实**：
- **应用**负责 SCSI 语义：解析收到的 CDB（`0x0114B8` → `0x40043C`）、构造要发出去的 1394 请求（`0x40033C` CDB / `0x400344` 160B 描述块 / `0x4003E4` 8B 附加块）。
- **引导块**只是 1394 硬件桥：把上述三块用 `EEPMOV.B` 搬进 1394 控制器寄存器区（`0xFFDC40` / `0xFFDC48` / `0xFFDCE8`），写 `0xFFDC3C=1` 发起，然后跳回应用入口。
- `jsr 0x000192` **不返回**：应用每轮走到这里，等于被引导块「重入应用入口」——即应用是**每轮重新初始化**的节拍式结构（与应用侧「主循环 `0x020B84` 每轮 `jsr 0x000192` 一次」一致）。

### 2.5 关键否定结果：引导块不碰应用的 RAM 状态 `[实证]`

对引导块 64 KB 做 4 字节立即数 + 16 位寻址模式搜索，**全部 0 命中**：

| 地址 | 含义 | 引导块引用 |
|---|---|---|
| `0x0040043C` | 应用 CDB 缓冲 | **0** |
| `0x00400408` | E0/C1 请求块 | **0** |
| `0x00400402` / `0x00400436` | 状态码 / sense 索引 | **0** |
| `0x00400C55` | E0 子功能码 | **0** |
| `0x00FFDC30` / `0x00FFDC34` / `0x00FFFED2` | B3 认定的「flash 邮箱」 | **0** |

## 3. A 类四项的最终状态

| # | 项目 | 结论 | 证据 |
|---|---|---|---|
| A1 | 复位向量 / 中断向量表 | **已解**：表在 `0x0000`（92 项，见 §2.2 的切分疑问）；复位入口 `0x180`；镜像选择字节 `0x4001` | §2.2 / §2.3 |

| A3 | 把 CDB 填入 `0x40043C` 的代码 | **已解**：应用侧 `0x0114B8`（`jsr`，SCSI 分派器 `0x020E86` 在 `0x020EA4` 处调用）。**注意 `0x40043C` 与 `0x40033C` 是两个不同缓冲**：前者是「收到的 CDB」，后者是「待发的 1394 CDB」 | §2.4 + `0x020E86` 反汇编 |
| A4 | `0x400408` 的真实消费方 | **原假设被推翻**：它不是交给引导块消费的请求块。应用内有 **4 处直接写**（`0x026A88` C1 臂、`0x026AC6` A0 臂、`0x026B48` B3 臂、**`0x028D96`（新增，此前文档只记 3 处）**）、**5 处地址装入**（`mov.l #0x00400408,erN`：`0x02AEC8`/`0x02B9AA`/`0x02BBC0`/`0x02CACE`/`0x02CB70`）、**至少 1 处真读**（`0x02BBC6 mov.w @er5,r0`）。它就是应用自己的 **E0/C1 参数暂存区（V1/V2）**，被 C1/A0/B3 写入、被作业处理函数读回；**引导块从不引用** | 本节 + `0x400408` 全镜像引用分类 |

**⇒ 旧文档「`0x400408` 只写不读、推断为引导块消费」两处均需更正。**

## 4. 连带影响：B3 的「flash 邮箱」解释需要重审

`agent_b3` 判定 B3 通过 `0xFFDC34`(目的) / `0xFFDC30`(源) / `0x400D38`(长度) / `0xFFFED2`(控制) 写引导块 flash `0x6000–0x7FFF`。但本轮发现：

1. `0xFFDCxx` 是 **1394 控制器寄存器窗**——引导块缝隙函数就在 `0xFFDC3C/3D/3E/3F/40/48` 与 `0xFFDCE8` 上操作它（`EEPMOV.B` 搬运），语义是「1394 传输控制」，不是 flash 邮箱。
2. 引导块**完全不引用** `0xFFDC30`/`0xFFDC34`/`0xFFFED2`。

⇒ 「B3 写引导块 flash」这一结论**需要重新取证**（可能仍成立，但机制描述必须改；也可能是 1394 控制器/闪存的另一种访问路径）。**本轮未推翻它，只是标记为「待重审」。**
