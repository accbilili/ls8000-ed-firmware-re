## 0. 结论摘要（TL;DR）

| 项 | 裁决 |
|---|---|
| **最终公式** | **`0x400408` = BE32(mem[0x400C57], mem[0x400C58], mem[0x400C59], mem[0x400C5A])**，即 `payload[1]<<24 \| payload[2]<<16 \| payload[3]<<8 \| payload[4]`（标准 32 位大端） |
| **被证伪的说法** | **说法 B（agent_b3 报告）**：`P1<<24 + (P2+P3)<<16 + P4` —— **证伪**。根因是纯算术错误：把 `4 × shll.l #2` 当成 `<<16`，实际 `4×2 = 8` 位。 |
| **第三种形态（任务书转述）** | 任务书中给出的"B3 臂转写"逐条**指令本身与 ROM 完全一致**（我已逐字节复核），但**其随附注释有 3 处语义错误**，按其注释推出的公式同样不成立。 |
| **4 个写入点是否一致** | **否**。3 个 payload 臂（C1/A0/B3）公式**完全一致**；第 4 个（`0x028D94`，片夹识别区）是**完全不同的公式**（来自两个其它 RAM 字的算术，与 payload 无关）。 |
| **置信度** | **高（公式本身：实证 4 重独立验证）**；中（`0x400408` 语义标签、payload 索引起点约定） |

## 1. 复核：任务书给出的 B3 臂转写

### 1.1 逐条复核结果

我独立跑了 `dis.py 26AE0 26B60`，并用 `probe.py` 打印原始字节逐条比对。

**结论：任务书的指令转写逐条正确**（含地址、助记符、操作数顺序）。

```
0x026B0A  mov.b    @(0x1,er6), r0l      ; 原始字节 6E 68 00 01
0x026B0E  mov.b    r0l, @0x400412       ; 原始字节 6A A8 00 40 04 12
0x026B14  sub.l    er0, er0            ; 原始字节 1A 80
0x026B16  mov.b    @(0x2,er6), r0l      ; 6E 68 00 02
0x026B1A  mov.b    r0l, r0h            ; 0C 80
0x026B1C  sub.b    r0l, r0l            ; 18 88
0x026B1E  mov.w    r0, e0              ; 0D 08
0x026B20  sub.w    r0, r0              ; 19 00
0x026B22  sub.l    er1, er1            ; 1A 91
0x026B24  mov.b    @(0x3,er6), r1l      ; 6E 69 00 03
0x026B28  mov.w    r1, e1              ; 0D 19
0x026B2A  sub.w    r1, r1              ; 19 11
0x026B2C  add.l    er1, er0            ; 0A 90
0x026B2E  sub.l    er1, er1            ; 1A 91
0x026B30  mov.b    @(0x4,er6), r1l      ; 6E 69 00 04
0x026B34  shll.l   #2, er1   ×4        ; 10 71 10 71 10 71 10 71
0x026B3C  add.l    er1, er0            ; 0A 90
0x026B3E  sub.l    er1, er1            ; 1A 91
0x026B40  mov.b    @(0x5,er6), r1l      ; 6E 69 00 05
0x026B44  add.l    er1, er0            ; 0A 90
0x026B46  mov.l    er0, @0x400408      ; 01 00 6B A0 00 40 04 08
```

### 1.2 但随附注释有 3 处语义错误（这是"第三种形态"的来源）

任务书注释里的这三条**不成立**：

| 任务书注释 | 实际语义 | 错误性质 |
|---|---|---|
| `0x026B28 mov.w r1, e1 ← e1 = P3<<8` | 此处 `r1h = 0`（因为 `0x026B22 sub.l er1,er1` 已把 ER1 全清），所以 `r1 = P3`（**无 <<8**）。`mov.w r1,e1` → E1 = P3 → ER1[31:16] = P3 → **P3 落在 bits 23:16** | 误以为 `e1` 里已经带了 <<8 |
| `0x026B34 shll.l #2, er1 ×4 ← er1 = P4 << 16` | `shll.l #2` 每条**左移 2 位**，4 条 = **左移 8 位**（`h8.lst` 第 1073 行：`1070 fff8 0 shll.l two r32l s20`，sleigh 语义 `do_shll2_32`）。故 `er1 = P4 << 8` → **P4 落在 bits 15:8** | **纯算术错误：4×2=8，不是 16** |
| `0x026B2C add.l er1, er0 ← er0 = (P2<<8) + (P3<<8)` | 三个字节走**三条不同代码路径**，累加进 ER0 的是**已就位于正确字节道**的三个 32 位值；不存在"同位相加" | 把三条异构路径当成同一条 |

**这正是 agent_b3 报告错误的同一根源**：agent_b3 在 §2.8 写「`mov.w r1,e1` **或** `shll.l #2 ×4` → bits16-23」，把第二字节的代码路径（`mov.w r1,e1`）错误地套用到了第三字节的代码路径（`shll.l #2 ×4`）上。

## 2. 推导：字节级 → 位级

### 2.1 必须先钉死的 H8/300H 语义（4 条）

| 语义 | 内容 | 依据 |
|---|---|---|
| **S1** | `ERn` 是 32 位寄存器，由 `En`（bits 31:16）与 `Rn`（bits 15:0）组成。 | H8/300H 寄存器架构 |
| **S2** | **`mov.w Rm, En` 只写 ERn 的高 16 位（bits 31:16），Rn（低半）保持不变** —— 所以紧随其后必须有 `sub.w r0,r0` 显式清低半。 | 本项目 `REPORT_L3-交接定稿.md` 的 M7 方法论条目；且代码本身自证：若 `mov.w r0,e0` 会顺带清低半，则 `sub.w r0,r0` 就是废指令 |
| **S3** | `mov.b r0l, r0h` = 把 R0 的**低字节复制到高字节**（源=低半、目标=高半）。配套的 `sub.b r0l, r0l` 用来把低半清零，于是得到 `R0 = byte << 8`。 | `h8.lst` 第 1006 行 `0c00 ff00 0 mov.b r8h r8l`，sleigh：`m_TMP1 = r8_r(op>>4); r8_w(op&0xf, m_TMP1)` → 高半位域为源、低半位域为目标；配合 S2 与紧随的 `sub.b` 可反推 |
| **S4** | `shll.l #2, erN` = **左移 2 位**（不是左移 1 字节、也不是 4 位）。`h8.lst` 第 1073 行 `1070 fff8 0 shll.l two r32l s20`，sleigh 语义 `do_shll2_32`（`two` = 固定立即数 2）。 | `h8.lst` + sleigh 段 |

### 2.3 字节道归属表（4 个 payload 字节 → 4 个字节道）

| payload 字节 | 源地址（C1/A0/B3 臂的 er6 偏移） | 绝对地址 | 落地字节道 | 代码路径 |
|---|---|---|---|---|
| b₁ | `@(0x2,er6)` | 0x400C57 | **bits 31:24** | `mov.b→r0l; mov.b r0l,r0h; sub.b r0l,r0l; mov.w r0,e0` |
| b₂ | `@(0x3,er6)` | 0x400C58 | **bits 23:16** | `mov.b→r1l; mov.w r1,e1; sub.w r1,r1; add.l` |
| b₃ | `@(0x4,er6)` | 0x400C59 | **bits 15:8** | `mov.b→r1l; shll.l #2 ×4; add.l` |
| b₄ | `@(0x5,er6)` | 0x400C5A | **bits 7:0** | `mov.b→r1l; add.l` |

**四个字节各占一个独立字节道，无任何进位/叠加。** 这就是标准 BE32。

### 2.4 关于"payload[1] 是否参与"

任务书按其 B3 臂标注把 `@(0x1,er6)` 叫 "payload[1]"。为消除歧义，本报告一律用**绝对地址**表述：

- `mem[0x400C56]`（= er6+1）：**不参与** `0x400408`。B3 臂把它单独写到 `0x400412`；C1/A0 臂根本不读它。
- `mem[0x400C57..0x400C5A]`（= er6+2..er6+5）：**这 4 个字节**构成 `0x400408`。

在 `REPORT_L3-交接定稿.md` §7.4 的 payload 约定（`payload[i] = mem[0x400C56+i]`）下，等价表述为：

> **`0x400408` = BE32(payload[1], payload[2], payload[3], payload[4])**，payload[0] 不参与。

这与 agent_b3 报告 §2.8 用的 payload 索引一致（他写 `P1..P4 = payload[1..4]`），仅公式错。

## 3. 4 个写入点对比表

### 3.1 全 ROM 穷举扫描（无遗漏）

`0x400408` 的绝对寻址写入在 H8/300H 只有 3 种编码形式（`mov.l ERm,@abs32` / `mov.w Rm,@abs32` / `mov.b Rm,@abs32`），我对 16 个寄存器变体逐一枚举扫描：

| 编码 | 命中 |
|---|---|
| `01 00 6B A_` + addr32（`mov.l ERm,@abs32`，8 字节） | `0x026A86`、`0x026AC4`、`0x026B46`、`0x028D94`（`A2`=er2） |
| `6B A_` + addr32（`mov.w Rm,@abs32`，6 字节） | `0x026A88`、`0x026AC6`、`0x026B48`、`0x028D96` —— **全是上面 4 条指令内部的字节重叠假阳性**，见 §3.3 |
| `6A A_` + addr32（`mov.b Rm,@abs32`） | 无 |
| 经寄存器间接（基址=0x400408 再 `mov.* @erN`） | **无**（5 处地址装入点全部只读，见 §5.2） |

`0x40040C` 同理：`mov.l` 命中 `0x026AFE`、`0x026B80`、`0x028DB0`；`mov.l @abs32,ERn` 读命中 `0x03A424`、`0x03A96A`。

### 3.2 4 个写入点逐一对比

| # | 真实指令地址 | 助记符 | 源 | 公式 | 与 B3 臂一致？ |
|---|---|---|---|---|---|
| **W1** | **`0x026A86`** | `mov.l er0,@0x400408` | payload 字节 | `BE32(b₁,b₂,b₃,b₄)` = payload[1..4] | **基准** |
| **W2** | **`0x026AC4`** | `mov.l er0,@0x400408` | payload 字节 | `BE32(payload[1..4])` | ✅ **完全一致**（同一段指令模板，逐字节同构） |
| **W3** | **`0x026B46`** | `mov.l er0,@0x400408` | payload 字节 | `BE32(payload[1..4])` | ✅ **完全一致** |
| **W4** | **`0x028D94`** | `mov.l er2,@0x400408` | **不是 payload** | `mem[0x420308] + (mem[0x4204E8] >> 1)` | ❌ **完全不同的公式** |

**W4 的完整推导**（片夹识别区，`0x028D80`–`0x028D94`）：

```
0x028D80  mov.l    @0x4204e8, er1     ; 原始字节 01 00 6B 21 00 42 04 E8
0x028D88  shlr.l   er1                ; 原始字节 11 31   → er1 = mem[0x4204E8] >> 1
0x028D8A  mov.l    @0x420308, er2     ; 原始字节 01 00 6B 22 00 42 03 08
0x028D92  add.l    er1, er2           ; 原始字节 0A 92
0x028D94  mov.l    er2, @0x400408     ; 原始字节 01 00 6B A2 00 40 04 08
```
⇒ `0x400408 = mem[0x420308] + (mem[0x4204E8] >> 1)`。**与 payload 字节组装毫无关系**（对称地，`0x028DB0` 写 `0x40040C = mem[0x4203F8] + (mem[0x4205D8]>>1)`）。

> **修正要点**：现有文档把 W1–W4 并列为"4 处直接写，公式相同"，这是错的。W4 是**另一个量**（片夹几何量），只是复用了同一个暂存槽位。这直接支持 `LS8000-E0总表` 第 176 行那句"**`0x400408` 是被多处复用的暂存槽位，不是单一字段**"。

### 3.3 重要附带发现：现有文档的写点地址与助记符双错

`REPORT_L3-交接定稿.md` §7.7 与 `REPORT_全面分析总结-20261024.md` §4 都写：

> 直接写（`mov.w rX,@0x400408`）| **4** | `0x026A88`（C1 臂）、`0x026AC6`（A0 臂）、`0x026B48`（B3 臂）、`0x028D96`（片夹识别区）

两处都错：
1. **地址整体 +2 偏移**。真实指令起点是 `0x026A86 / 0x026AC4 / 0x026B46 / 0x028D94`。
2. **助记符错**：不是 `mov.w`（16 位），是 **`mov.l`**（32 位）。

**根因**：`mov.l ERm,@abs32` 的 8 字节长格式是 `01 00 6B A0 <addr32>`。其中 `6B A0 <addr32>` 恰好**完全等于** `mov.w Rm,@abs32` 的 6 字节短格式编码。任何按 `6B A0` + addr32 做字节模式扫描的脚本，都会在长指令**内部 +2 处**命中一次假阳性，并把它误判成 16 位写。

我从指令流边界独立验证：从 `0x0269A6`（函数序言）线性解码，`0x026A86` 是指令边界，其 `mov.l` 长 8 字节，`0x026A8E` 才是下一条指令（`jmp 0x026bd2`）。同理 `0x028D94` 从 `0x0289B8`（`stm.l er4-er6,@-sp`）线性解码确认在指令边界。

**这很重要**：把它误判为 `mov.w`（16 位写）会让人以为 `0x400408` 只被写 2 字节，从而完全改变对槽位宽度的理解。

### 4.3 `0x400412` 是什么？

- **只被 B3 臂写一次**（`0x026B0E mov.b r0l,@0x400412`，1 字节，值 = `mem[0x400C56]` = payload[0]）。
- C1/A0 臂**不写**它 —— 所以 `0x400412` 在非 B3 命令下是**残留旧值**。
- 它**不属于** V1（`0x400408`）也不属于 V2（`0x40040C`），是独立的单字节字段。
- 全 ROM 只有 1 处写（`0x026B0E`）、1 处读（`0x02BC3A`）。

## 5. 读回侧交叉验证

### 5.1 决定性证据：打包器逐字节复制 `0x400408` 的 4 个字节

`0x02BBAE` 是把暂存槽位打包成 33 字节 flash 记录（写到 `0x400CA0`）的函数。它**不把 `0x400408` 当作一个数来重排**，而是**按地址升序逐字节搬运**：

```
0x02BBC0  mov.l    #0x00400408, er5
0x02BBC6  mov.w    @er5, r0          ; 大端 16 位读 → r0h = mem[0x400408], r0l = mem[0x400409]
0x02BBC8  sub.w    e0, e0
0x02BBCA  mov.b    r0h, r0l          ; r0l = mem[0x400408]
0x02BBCC  sub.b    r0h, r0h
0x02BBCE  mov.b    r0l, @er6         ; buf[0] = mem[0x400408]
0x02BBD0  mov.w    @er5, r0
0x02BBD2  mov.b    r0l, @(0x1,er6)   ; buf[1] = mem[0x400409]
0x02BBD6  mov.b    @(0x2,er5), r0l   ; mem[0x40040A]
0x02BBDA  sub.b    r0h, r0h

```

⇒ **`0x400408` 的存储字节序 = 内存升序 = 大端**。若真是"第二、三字节同落 bits16:23"，则 `mem[0x40040A]` 恒为 0、`mem[0x400409]` 是两字节之和——打包出来的是损坏字节流，与"参数原样搬运"的设计意图直接矛盾。

**输出记录 `0x400CA0` 的完整字段图**（`0x02BBAE` 逐条实测）：

```

buf+0x04..07 ← 0x40040C,0x40040D,0x40040E,0x40040F   (V2, 4 字节, 升序)

buf+0x09    ← 0x400411

buf+0x0C    ← 0x400412          ← payload[0] 被排到最后

buf+0x0E    ← 0xFF              (常量)
```

（`0x02BC12`–`0x02BC4C` + `0x02BC5C`–`0x02BC70` 的 0x11 次循环）

### 5.4 【关键交叉验证 A】"16 位钳位"要求高字节有信息量

`0x40` 作业对 `0x400408+2` 的 u16 做 `cmp.w #0x43e1`(17377) 钳位，`0x42` 作业做 `cmp.w #0x0f60`(3936) 钳位。

- **在 BE32 下**：该 u16 = payload[3]<<8 | payload[4]，可取值 0–65535，**确实需要 16 位钳位**。✓
- **在说法 B 下**：该 u16 = `mem[0x40040A]<<8 | mem[0x40040B]` = `0<<8 | payload[4]` ≤ **255**，永远小于 3936，**两个钳位阈值都变成废代码**。✗

→ 读侧钳位语义**独立排除**说法 B。

### 5.5 【关键交叉验证 B】flash 记录的 signed 32 位比较

`0x02BD10`（B3 尾）从 flash `0x6000` 读回 32 位并做**有符号**比较：

```
0x02BD10  mov.l    @0x006000, er0
0x02BD18  cmp.l    #0xfffffed4, er0   ; −300
0x02BD1E  blt      0x02bd40
0x02BD20  mov.l    @0x006000, er0
0x02BD28  cmp.l    #0x0000012c, er0   ; +300
0x02BD2E  bgt      0x02bd40
0x02BD30  mov.l    @0x006000, er6
0x02BD38  add.l    #0x0000014d, er6   ; +333
```

flash `0x6000` 的前 4 字节 = 打包器从 `0x400408` 逐字节搬来的 V1（§5.1）。

- **在 BE32 下**：V1 是标准 signed 32 位大端整数，MSB = payload[1]，负值需 payload[1] ≥ 0x80。`0xfffffed4` = −300 的字节序列 = `FF FE D4 00`，即 payload[1..4] = FF FE D4 00 —— 完全自洽。✓
- **在说法 B 下**：值 = payload[1]<<24 + (payload[2]+payload[3])<<16 + payload[4]，其中 payload[3] **被 payload[2] 吞掉**、bits15:8 恒为 0。这样的量做 signed 比较毫无意义，也不可能对应 `FF FE D4 00` 这样的规范字节模式。✗

**并且**：`REPORT_L3-交接定稿.md` §11.4.1 已记载 stock 记录 `@0x6000` 的 V1 = `0x00000085` = 133，落在 [−300,300] 内、目标位 = 133+333 = 466。`0x00000085` 的字节序列 `00 00 00 85` 在 BE32 下 = payload[1..4] = 00 00 00 85，**四个 payload 字节一一对应**；在说法 B 下则 payload[2]、payload[3] 必须同时为 0（因和为 0 且不溢出），无法解释主机为何要发 4 个字节。✓

### 5.6 【关键交叉验证 C】E0 解析臂的独立同构实现

`0x026BF8`（E0 解析/门限处理函数）用**完全不同的寄存器、不同的 payload 来源**（data-out 相位暂存区 `sp+1`，不是 `0x400C55`）独立地组装同一个量：

```
0x026D10  sub.l    er3, er3
0x026D12  mov.b    @(0x1,er5), r3l   ; er5 = sp+1 → payload[1]
0x026D16  mov.b    r3l, r3h
0x026D18  sub.b    r3l, r3l
0x026D1A  mov.w    r3, e3            ; er3[31:24] = payload[1]
0x026D1C  sub.w    r3, r3
0x026D1E  sub.l    er0, er0
0x026D20  mov.b    @(0x2,er5), r0l   ; payload[2]
0x026D24  mov.w    r0, e0            ; er0[31:16] = payload[2] → 贡献 bits 23:16
0x026D26  sub.w    r0, r0
0x026D28  add.l    er0, er3
0x026D2A  sub.l    er0, er0
0x026D2C  mov.b    @(0x3,er5), r0l   ; payload[3]
0x026D30  shll.l   #2, er0 ×4        ; er0 = payload[3] << 8  → bits 15:8
0x026D38  add.l    er0, er3
0x026D3A  sub.l    er0, er0
0x026D3C  mov.b    @(0x4,er5), r0l   ; payload[4]
0x026D40  add.l    er0, er3          ; er3 = payload[4]
```
⇒ `er3 = BE32(payload[1], payload[2], payload[3], payload[4])`。

这个 `er3` 随后被 `0x026E2E cmp.l #0x000001c2`(450)、`0x026E86 cmp.l #0xfffffed4`(−300)、`0x026E8E cmp.l #0x0000012c`(300)、`0x026E9C/0x026EA0`（0 或 1）做 **signed 32 位**门限比较。

**同一段"逐字节入道"模板在两个互不相干的函数、两个不同的 payload 载体上，产生同一个 BE32 布局** —— 若是编译器的"系统性缺陷"（说法 B），不可能在两处独立复现出完全一致的错误。

### 5.7 【关键交叉验证 D】`shll.l #2` 的移位量由工具链定义

`h8.lst` 第 1073 行：
```
1070         fff8         0 shll.l   two      r32l     s20
	r32_w(m_IR[0], do_shll2_32(r32_r(m_IR[0])));
```
`two` 是**固定立即数 2**（`h8dis.py`: `if a=="two": return "#2"`），sleigh 语义函数名 `do_shll2_32` 明确是"左移 2 位"。故 `shll.l #2` ×4 = **<<8**，不是 <<16。

> agent_b3 报告 §2.8 写「已核对原始字节 `10 71 10 71 10 71 10 71`（**4×shll = <<16**）」—— 这行自证反而暴露了算术错误：4 条 `shll.l #2` = 4×2 = **8 位**。

### 5.8 引导块侧

`LS8000_bootblock.bin`（64 KB）对 `0x400408 / 0x40040C / 0x400410 / 0x400412` 的 4 字节立即数搜索：**0 命中**。→ `0x400408` 与引导块无关，既有结论正确。

## 6. 最终裁决

### 6.1 公式

```
0x400408 = BE32(mem[0x400C57], mem[0x400C58], mem[0x400C59], mem[0x400C5A])
          = payload[1]<<24 | payload[2]<<16 | payload[3]<<8 | payload[4]
```
（`er6 = 0x400C55`，`payload[i] = mem[0x400C56+i]`；等价地 `0x400408` 的 4 个存储字节按内存升序 = payload[1..4]）

同理：
```
0x40040C = BE32(payload[5], payload[6], payload[7], payload[8])     （仅 A0 / B3 臂）
0x400410 = payload[9]<<8 | payload[10]                            （u16 大端，仅 B3 臂；0x40/41/42 臂写 0）
0x400412 = payload[0]                                            （1 字节，仅 B3 臂）
0x400413 = payload[11]                                           （1 字节，仅 B3 臂）
0x400414 = payload[12]                                           （1 字节，仅 B3 臂）
```

### 6.2 三种说法的判定

| 说法 | 出处 | 判定 | 依据 |
|---|---|---|---|
| **A** `BE32(V1)` = `payload[1]<<24\|payload[2]<<16\|payload[3]<<8\|payload[4]` | `REPORT_L3-交接定稿.md` §7.4.2、§11.4.1；`e0_bridge.md` §87–89 | ✅ **成立** | §2 逐指令推导 + §5.4/5.5/5.6/5.7 四重独立交叉验证 |
| **B** `P1<<24 + (P2+P3)<<16 + P4` | `agent_b3_report.md` §2.8、§8-① | ❌ **证伪** | 根因：`4×shll.l #2` = **<<8** 不是 <<16（`h8.lst` 第 1073 行）；第二、三字节走**不同代码路径**、落**不同字节道**；§5.4/5.5 的读侧钳位与 signed 比较均要求 BE32 |
| **第三种形态** | 任务书转述的 B3 臂注释 | ❌ **不成立** | 指令转写正确，但 3 条注释（`e1=P3<<8`、`er1=P4<<16`、`er0=(P2<<8)+(P3<<8)`）均错；按其注释推出的公式与说法 B 同源 |

### 6.3 4 个写入点

**不一致。** W1/W2/W3（C1/A0/B3）公式完全相同 = BE32(payload[1..4])；**W4（`0x028D94`）是另一个量**：`mem[0x420308] + (mem[0x4204E8]>>1)`。

### 6.4 置信度

| 结论 | 置信度 | 理由 |
|---|---|---|
| 公式 = BE32(payload[1..4]) | **高（≈0.97）** | 4 处独立实现（3 个 payload 臂 + 1 个 E0 臂）+ 4 类读侧交叉验证（字节打包、16 位钳位、signed 32 位比较、bootblock 排除）全部一致；唯一残余不确定性是解码器自身若有系统性错误 —— 但 §5.7 用 `h8.lst` 的 sleigh 语义独立钉死了移位量，且 §5.4/5.5 的读侧语义无法用别的布局解释 |
| 4 个写点中 W4 公式不同 | **高（≈0.95）** | 指令级完全确定；仅"它语义上是片夹几何量"这一定性带推断成分 |
| `0x400408` 的业务语义标签（signed 32 位位置偏移 V1） | **中（≈0.7）** | 数值形态（signed 32 位、±300 门限、+333 偏置、+2 处取低 16 位作位置）已实证；但"V1 与执行层 0x400408 的 4 字节是否逐字节同源"（data-out 相位 vs `0x400C55` 载体）**未能确定** |
| `0x400408` 是"待访问地址" | **低，应作废** | §5.1/5.3/5.4 显示它被当 signed 位置量用、被大端字节流打包进 flash 参数记录，不是地址 |

1. **`0x400408` 槽位被多方复用**：payload 臂写 V1，片夹区（W4）写几何量。应在 `REPORT_L3` §7.7 与 `LS8000-E0总表` §3 都补上"该槽位是复用暂存区，不是单一字段"，并补 W4 的确切公式。

3. **打包记录 `0x400CA0` 的字段图**（§4.3 / §5.1）目前散落在 agent_b3 §4，建议在主报告补一张完整表；注意 buf+0x0A/0x0B/0x0C 的次序是 `0x400413 / 0x400414 / 0x400412`，**payload[0] 被排到最后**。
4. **待确认（我未能确定）**：E0 臂 `er3`（data-out 相位 payload）与执行层 `0x400408`（`0x400C55` 载体）是否**逐字节同源**。两侧公式相同已实证；同源与否需追踪 `jsr 0x0118D0` 的传输层来源，我未闭合。`REPORT_L3` §11.4.1 的"同源同序"目前应降级为"同序、来源待证"。

---

## 8. 未能确定的事项

1. **E0 `er3` 与 `0x400408` 的数据同源性**（§7.3-4）。两者公式相同已实证，但字节来源是两条不同路径（data-out 相位暂存区 vs `0x400C55` CDB 区）。
2. **`0x400408` 的完整业务语义标签**。已实证：signed 32 位、±300 门限、+333 偏置、`+2` 处取低 16 位作位置、被大端字节流打包进 flash 参数记录。"有符号 32 位位置偏移 V1"是最贴合的标签，但"位置偏移"这层语义来自 `REPORT_L3` §11.4 的既有结论，本次未独立重证。
3. **`0x400410` 在 0x40/41/42 臂被写 `0x0000` 的意图**（`0x026A50 sub.w r0,r0` 清零后写）。已实证"确实写 0"，但"为什么先拼 16 位再清零"未闭合。
4. **`0x400412` 在非 B3 命令下的残留值是否被消费**。全 ROM 只有 `0x02BC3A` 一处读它，而该读点在 B3 尾路径上；未找到"非 B3 也走打包器"的证据。
