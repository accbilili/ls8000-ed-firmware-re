## 0. 结论速览

1. `[实证]` 覆盖 `0x028B00–0x028E68` 的只有 **两个**函数：`0x0289B4–0x028E30`（主流程）与 `0x028E30–0x0290A0`（单排识别）；结果再交给 `0x0290A0` 消费。`0x028BB0` **不是函数入口**，是前一函数内的标签。
2. `[实证]` 识别结果码（`0x11`–`0x1F` / `0x10` / `0x81`）落在 **`0x4003FB`**；`0x400D79` 只是「识别正常」标志位（1=正常，0=失败）。**这一条与前序三份报告冲突，见 §4.2。**
3. `[实证]` **34.8 mm 不是存储的常量**。落地形式是：双精度 `22.3`@`0x3EF38` × `157.4803149606`@`0x3EDE0` → `0x01876A` 截断得 **3511**，再 `add.w #0x07B0`（+1968，即 12.5 mm）→ **5479** 计数 = **34.7917 mm**。前序写的 3512 / 5480 各差一步。
4. `[实证]` `0x81` 是**过程信号**（上排读到 raw `0x07` → "须走片后读下排"），既非类型码也非错误码。
5. `[实证]` 全镜像 `bsr` 扫查：`0x028E30` 只有 **2** 个进入点 `0x028BB0` / `0x028BFE`，同属 `0x0289B4`；无第三个调用者。
6. `[实证]` 识别失败 → `0x4003FB=0x10`、`0x400D79=0`，**不重试**；上层据此报 `0x1100` / `0x5000`。

## 1. 区段结构与边界

### 1.1 真实函数划分（按序言判定）

| # | 入口 | 范围 | 序言字节 | 一句话作用 |
|---|---|---|---|---|
| A | `0x0289B4` | `0x0289B4–0x028E30`（0x47C B） | `01 10 6D F2` `stm.l er2-er3,@-sp` / `01 20 6D F4` `stm.l er4-er6,@-sp` / `sub.l #0xAA,sp` | 片夹识别主流程：初始化 → 走到上排工位 → 上排识别 → （GR）走片 → 下排识别 → 类型分发 → 收尾 |
| B | `0x028E30` | `0x028E30–0x0290A0`（0x270 B） | 同上两式，帧 `0x12` | 单排光学采样 + 自适应阈值 + 定位 + 4 位取值 + 查表出码 |
| C | `0x0290A0` | `0x0290A0–0x029160`（0xC0 B） | `01 00 6D F5` `mov.l er5,@-sp` | 清 4 张 60 项参数表，按结果码查 `0x3EEF0` 的 16 项向量，转该类型的参数装配例程 |

A 的收尾 `0x028E20–0x028E2E`（`add.l #0xAA,sp` / `ldm.l` ×2 / `rts`）；B 的收尾 `0x029090–0x02909E`；C 的公共出口 `0x02915C`（`mov.l @sp+,er5` / `rts`）。边界处无填充、无对齐空隙，A/B/C 首尾相接。

C 的两级分派（`[实证]`，表基址 `0x3EEF0`，`code−0x10` 索引，每项 4 B）：表项指向 `0x029100+4i` 的**跳板**（`bsr` + `bra 0x02915C`），跳板再 `bsr` 到真正的装配例程：

`0x10→0x029100(→0x029162)`、`0x11→0x029104(→0x02919C)`、`0x12→0x02910A(→0x02920E)`、`0x13→0x029110(→0x0295C2)`、`0x14→0x029116(→0x0296A8)`、`0x15→0x02911C(→0x02978E)`、`0x16→0x029122(→0x0298E8)`、`0x17→0x029128(→0x0299A6)`、`0x18→0x02912E(→0x0299E0)`、`0x19→0x029134(→0x029A1A)`、`0x1A→0x02913A(→0x029A8C)`、`0x1B→0x029140(→0x029AFE)`、`0x1C→0x029146(→0x029B70)`、`0x1D→0x02914C(→0x029BE2)`、`0x1E→0x029152(→0x029C54)`、`0x1F→0x029158(→0x029C96)`。即**每个类型码一个专属的扫描参数装配例程**。

### 1.2 `0x028BB0` 不是入口

- 该处字节 `5C 00 02 7C` 是 `bsr 0x028E30`，前面 `0x028BAE` 是 `F8 80`（`mov.b #0x80,r0l`），后面 `0x028BB4` 是 `68 E8`（`mov.b r0l,@er6`）。三者在同一条基本块里。
- 全镜像对 `0x028BB0` 的 `bsr`/`jsr`/24 位绝对引用 **均为 0**（`_f2\sweep2.py`）。
- 唯一的"切分"来源是 `cfg_v4.json` 的解码空洞（下节），不是真实序言。

任务给的范围 `0x028B00–0x028E68` 里**只有 `0x028E30` 一个序言**；`0x028E68` 落在 B 的 max/min 循环体内（`0x028E68` = `mov.w r3,r5`），不是边界——它是 `cfg_v4.json` 的一个**假入口**。

### 1.3 `cfg_v4.json` 为何在 `0x028B00–0x028E00` 是空白

`[实证]` 直接从 `cfg_v4.json` 读出的事实：

```
insns 连续区段: … 0x28A2C(size 2) → [洞 0x28A2E–0x28AA0，114 B] → 0x28AA0 → … → 0x28AF0(size 2)
                → [洞 0x28AF2–0x28E36，836 B] → 0x28E36 → … → 0x28EFE
owner 在 0x28B00–0x28E35 完全没有条目（不是 NULL，是键缺失）
owner 出现 0x28AA0 / 0x28E36 / 0x28E68 / 0x28E9E 四个假条目（后三个都在函数 B 体内）
```

成因两条，都可复核：

1. **解码器不支持 10 字节的 `0x0100` 前缀 `MOV.L` 绝对索引形式**，而空洞起点恰是这类指令：`0x028A2E` `01 00 78 40 6B A1 00 40 0E DE` = `mov.l er1,@(0x00400EDE,er4)`（10 B）；`0x028AF2` `01 00 78 40 6B 21 00 40 0F 32` = `mov.l @(0x00400F32,er4),er1`（10 B）。解码在这两处无法推进，函数归属链断掉。`dis28B.py` 的注释「补 `0x0100` 前缀 MOV.L d:32/d:16 形式」正是为此打的补丁。
2. **重新接上是错位 2 字节**：`0x28E36` 只解出一条 2 字节的 `6D F4`（`mov.w r4,@-sp`），吃掉了 `0x028E34` 的 `01 20` 前缀，之后在 `0x28E38` 重新对齐。所以 `0x28E36` 也是假入口。

推论：`cfg_v4.json` 的「622 函数」含至少 4 个此段假条目；任何"某地址 0 引用"的结论都必须先补扫 `bsr`（见 §7）。

## 2. 两阶段机制

### 2.1 时序（A 函数体内，全部 `[实证]`）

| 地址 | 指令 | 作用 |
|---|---|---|
| `0x028B82` | `mov.b #0x01,r0l` | — |
| `0x028B84` | `mov.b r0l,@0x400d79` | 状态位预置 =1（"正常"） |
| `0x028B8A` | `40 16` = `bra 0x028BA2` | 先跳到位置判据，跳过首次走片 |

两阶段的判据只有一条：**上排返回码是否等于 `0x81`**。`0x81` 只可能由 `0x029044` 产生（上排 raw `0x07`，四点全透 = GR 片夹）。

### 2.2 34.8 mm 的落地形式（本文最关键的一条）

**没有任何地方存着"34.8"这个数，也没有整数 5480。** 它是三段拼出来的：

```
028BBA  mov.l #0x0003EDE0, er1     ; er1 -> double 157.48031496062993 (= 4000/25.4)
028BC0  mov.l #0x0003EF38, er2     ; er2 -> double 22.3
028BC6  mov.l #0x00000008, er0
028BCC  add.l sp, er0              ; er0 -> 结果缓冲(栈)
028BCE  jsr   0x018AA0             ; 软双精度乘法：157.4803149606 × 22.3 = 3511.8110236220473
028BD2  jsr   0x01876A             ; 双精度 -> int32：截断
028BD6  add.w #0x07B0, r0          ; +1968
028BDA  mov.w r0, r5
```

**常量地址**：`0x3EF38` = `40 36 4C CC CC CC CC CD` = 22.3（精确）；`0x3EDE0` = `40 63 AF 5E BD 7A F5 EC` = 157.48031496062993。二者都在 §8.9 的几何常量区内。

**截断而非四舍五入**：`0x01876A` 是纯移位式转换——`018794 or.w #0x10,e0` 补隐含位后，`0187A0` 起 `shll.l er2 / rotxl.l er0` 把尾数左移，`0187A6–0187AC` 的循环把小数位直接移出，无任何进位项；`0187DA` 只按 `e3` 的符号位做 `neg.l`。所以 3511.81 → **3511**。

复算（`157.4803149606` 计数/mm = 4000 dpi）：

| 量 | 表达式 | 计数 | mm |
|---|---|---|---|
| 上排工位 | `0x07B0` | 1968 | 12.497 |
| GR 走片增量 | `int(157.4803149606×22.3)` | **3511** | 22.295 |
| 下排工位（绝对值） | 1968+3511 | **5479** | **34.792** |

前序报告写的 `3512` / `5480`（`REPORT_片夹类型码…` §6.1 注释、`REPORT_L3` §9.7）在这两点上都差 1。差 1 个计数 ≈ 6.35 µm，对机构无影响，但作为"指令里到底是什么数"的结论必须改正 —— 详见 §4.2 第 2 条。

**"34.8 mm"的两种读法都对，但要说清是哪一种**：位置寄存器 `0x4202A2` 的目标值是**绝对 5479**（34.79 mm）；而 `0x3EF38` 的字面值 22.3 是**增量 3511**。`+1968` 才是把相对量搬到绝对坐标上——所以 `0x3EF38` 被前序命名为"GR 片夹走片重定位量"是准确的。

### 2.3 单位与工位

`[实证]` 位置反馈 `0x4202A2` 与 `0x3EDE0` 同单位（1 计数 = 1/4000 英寸）：1968/157.4803 = 12.497 mm，3511/157.4803 = 22.295 mm。
`[推断]` `0x4202A2` 零点在机构 home（非片夹定位边）；上排 CCD 门控窗在 11.5 mm（`0x3EF58`）而工位在 12.5 mm，差 1.0 mm —— 与常量表里尚未定位的 `0x3EF48 = 1.0` 数值吻合，但无代码引用，不下结论。

## 3. `0x028E30` 判定树

**接口**：入参 `r0l` = bank（`0x80` 上排 / `0x81` 下排）；回参 `r0l` = 结果码。

### 3.1 采集

```
028E3E  mov.b  r0l,@(0x9,sp)        ; 存 bank
028E42  mov.l  #0x004407FE,er1      ; 通道缓冲描述符（0x028B1A 处按通道填入）
028E48  mov.b  #0x04,r0l            ; 采集模式 4
028E4A  jsr    0x02D700             ; 采一帧
028E4E  mov.l  #0x00C2D000,er4      ; 采样基址（10000 × u16）
```

### 3.2 自适应阈值 `0x028E5C–0x028E90`

```
028E5C  er6=0; loop 10000 (0x2710):
028E62    r3 = *(u16*)(0xC2D000 + er6*2)
028E64    cmp.w r5,r3 / bls  → r5 = max
028E6A    cmp.w e5,r3 / bcc  → e5 = min
028E7C  r0 = max>>1; cmp.w r0,e5 / bls 跳过清零   (min > max/2 时 min=0)
028E84  cmp.w #0x0FFF,r5 / bcc 跳过置数           (max < 0x0FFF 即整体偏暗时 max := 0x3FFF)
028E8E  r5 = max+min; shlr.w r5                  → r3 = threshold
```

### 3.3 定位（两 bank 几何）

| | bank `0x80` 上排 | bank `0x81` 下排 |
|---|---|---|
| pitch | `0x3EF50`=10.0 → `int(157.48×10)×2` = **3148**（`0x028EBC`） | `0x3EF60`=8.0 → **2518**（`0x028EE8`） |
| 基准 | `0x3EF58`=11.5 → `(10000−1811)×2` = **16378**（`0x028F7A`） | 搜索起点 `0x3EF68`=1.7 → **267**（`0x028F06`）；终点 `0x3EF70`=26.0 → **4094**（`0x028F1E`） |
| 搜索 | 无 | `0x028F26–0x028F44`：从 267 递增，找第一个 `sample > threshold` 的点 `e3`；命中 → `(10000−e3)*2 − pitch/4`（`pitch/4`=629=1.996 mm，即"开口中心"）；`0x028F46` 未命中 → `0x3EF78`=15.5 → `(10000−2440)*2` = **15120** |

`0x028F62`/`0x028F86` 无条件回 `0x028F8C`；`0x028F88` 的 `jmp 0x02908E` 是死代码。

### 3.4 取位 `0x028F8C–0x028FF4`

```
028F8C  r5l = 0
028F92  r0 = sample[base]; cmp.w r3,r0; bcs 0x02908E   ; 门控 < 阈值 → 0x10
028F9A  base − 1×pitch > thr ? bset #0                  ; bit0 = P1
028FAE  base − 2×pitch > thr ? bset #1                  ; bit1 = P2
028FC4  base − 3×pitch > thr ? bset #2  (jsr 0x018E1E)  ; bit2 = P3
028FE2  base − 4×pitch > thr ? bset #3                  ; bit3 = P4
```

极性：`cmp.w r3,rN` + `bls` ⇒ **采样 > 阈值才置位 = 透光为 1**。门控点 `base` 不作数据位，只做合法性判断（暗 → 整件 Unknown）。每 bit 只比 1 个采样点，无平均、无多数表决。

### 3.6 结果码落点

`0x028BB4` / `0x028C02` 用 `68 E8`（`mov.b r0l,@er6`）写入 **`0x4003FB`**；`er6` 由 `0x0289C4` `7A 06 00 40 03 FB`（`mov.l #0x004003FB,er6`）设定，全函数**无第二次改写**（`_f2\er6.py` 全函数扫描：er6 只在 `0x0289C4` 被赋值，`0x028E26` 出栈恢复）。

| `0x02759E` | `cmp.b #0x10` | `=0x10` → 报状态 `0x1100` |
| `0x016C16` / `0x02236E` / `0x02322E` / `0x023D22` / `0x02474E` / `0x02491A` / `0x028590` / `0x029D06` / `0x029D98` | 读 | 扫描/校准/图像通路按片夹类型取参数 |

**`0x3EE70` = 每类型 8 字节双精度参数表**（`[实证]`，闭合了前序 §10 遗留问题 3）：`0x0289D0–0x0289DE` 把 `0x80` 字节从 `0x3EE70` memcpy 到栈 `sp+0x10`；`0x028C2E–0x028C38` 以 `code×8 + (sp+0x10) − 0x80` 取址，等价于 `0x3EE70[(code−0x10)]`。实测值（`code 0x10…0x1F`）：`0,0,0,0,0,38.0,0,14.0,2.5,67.25,60.0,53.5,49.75,46.7,58.5,55.0`。本函数只在 `code∈{0x15,0x17,0x18}` 时用它做 `|值 − 50.0(@0x3EF40)| × 157.48` 的条片走片量（`0x028C3E` `jsr 0x017FD2`，`0x028C52` `jsr 0x018AA0`）。

### 4.2 七处不一致（逐条附证据）

**① 类型码落点：`0x4003FB`，不是 `0x400D79`**（影响面最大）

```asm
0289C4  7A 06 00 40 03 FB   mov.l  #0x004003FB, er6     ; ← er6 指向 0x4003FB
028BB4  68 E8               mov.b  r0l, @er6            ; ← 上排结果写这里
028C02  68 E8               mov.b  r0l, @er6            ; ← 下排结果写这里
028C14  68 68               mov.b  @er6, r0l            ; ← 随后按码分支
```
反证（`0x400D79` 的全部引用，cfg + 手工解码共 5 处）：

```asm
027E30  6A A8 00 40 0D 79   mov.b r0l,@0x400D79   ; 写 1
027EC4  6A A8 00 40 0D 79   mov.b r0l,@0x400D79   ; 写 1
02758C  6A 28 00 40 0D 79   mov.b @0x400D79,r0l   ; 唯一读点
028B84  6A A8 00 40 0D 79   mov.b r0l,@0x400D79   ; 写 1
028C0A  6A A8 00 40 0D 79   mov.b r0l,@0x400D79   ; 写 0
```
取值只有 `0`/`1`，从不承载 `0x11`–`0x1F`。前序 §6.1 的清单把 `028B84` 写成 `mov.l #0x00400D79, er6` —— 该地址的字节是 `6A A8 00 40 0D 79`（`mov.b`，6 字节），不是 `mov.l`。

**② 34.8 mm = 5479 计数，`int()` 得 3511 不是 3512**

`0x3EF38` 精确等于 22.3；`157.4803149606 × 22.3 = 3511.8110236220473`；`0x01876A` 截断 → 3511；`0x028BD6 add.w #0x07B0` → **5479**。前序 `3512`（按四舍五入）与 `5480`（按未截断/未核）均差 1。`3511.81…` 的小数部分 0.81 说明四舍五入与截断必然分叉，而 `0x01876A` 没有舍入项（`0x018794`–`0x0187AC`）。

**③ `0x028E30` 的进入点是 2 个，不是 1 个**

```asm
028BB0  5C 00 02 7C   bsr 0x028E30    ; 0x028BB0+4+0x027C
028BFE  5C 00 02 2E   bsr 0x028E30    ; 0x028BFE+4+0x022E
```
全镜像按偶数偏移扫 `5C`（`_f2\sweep2.py`，`bsr` 实测 4 字节、位移在 +2、`PC=addr+4`）：目标 `0x028E30` 命中 2 处，目标 `0x0290A0` 命中 1 处（`0x028C10`），`0x028E30` 的 24 位绝对引用 0 处。所以"唯一调用者"应表述为"**唯一调用函数是 `0x0289B4`，其内有两次 `bsr`**"。

**④ `0x028BB0` 不是"调用者"而是标签**

无独立序言、无任何 `bsr`/`jsr`/表引用。前序把它当作函数名使用（"调用者 `0x028BB0` 附近"），会让人误以为可以单独 `jsr 0x028BB0`——不行，进入时 `sp` 必须已按 A 的 `0xAA` 帧布局，`er6` 必须已置 `0x4003FB`。

**⑤ cfg 空白区间的边界与成因**

前序说"`owner` 在 `0x028B00–0x028D00` 是空白"。实测空洞是 `0x28AF2–0x28E36`（836 B），另有 `0x28A2E–0x28AA0` 一个 114 B 小洞；成因是 10 字节 `0x0100` 前缀 `MOV.L` 解码失败 + `0x28E36` 错位重连（§1.3）。此外 `0x0290A0` 整个函数也不在 `insns` 内。

**⑥ `0x5000` 的极性反了**

```asm
02758C  mov.b @0x400D79, r0l
027592  A8 01     cmp.b #0x01, r0l
027594  47 08     beq   0x02759E     ; ← 等于 1 就跳过 0x5000
027596  79 00 50 00  mov.w #0x5000, r0
02759C  40 14     bra   0x0275B2
02759E  mov.b @0x4003FB, r0l        ; 第二道判据用的完全是另一个变量
0275A4  A8 10     cmp.b #0x10, r0l  ; → 0275A8: 0x1100
```
前序 §6.3 写"若仍为 1，报状态 `0x5000`"。实际 `beq` 跳过 0x5000：**1 = 正常，非 1 才报 `0x5000`**。所以 `0x400D79` 的语义是"识别正常（默认 1，下排失败时清 0）"，不是"待识别"——这也解释了为什么 `0x028B84` 在识别**之前**就写 1。

**⑦ 前序把两个变量当成了一个**：`0x02758C` 与 `0x02759E` 是两道独立判据——先判"流程是否正常"（否 → `0x5000`），再判"结果是否 Unknown"（是 → `0x1100`），都过才回 0。前序的解释（"`cmp.b #1` 是门禁"）方向正确，但把门禁变量当成类型码，使两条错误路径混成一条。

### 4.3 前序遗留问题的闭合情况

- 已闭合：§10 问题 3「`0x028C2E` 后查表的基址」→ **`0x3EE70`**（16 项 × 8 B 双精度，索引 `code−0x10`，见 §3.6）；§10 问题 4「`0x4003FB` 语义」→ **片夹/画幅识别结果码**（见 §3.6 / §4.2①）。
- 未闭合：问题 1/2/5（机械基准、`0x027DC4` 全语义、主机 E0 对应），见 §8。

## 5. `0x81` 的确切含义

**确定答案：是"需读下排"的过程信号（stage-2 request），不是类型码，也不是错误码。**

依据五条，均可复核：

1. **产生条件唯一**：`0x029014 cmp.b #0x07` → `0x029044 mov.b #0x81,r0l`。只有上排 raw `0x07`（P1–P4 全部透光）才产出，对应"GR 片夹"这一物理族。
2. **立刻被解释为分支条件**：`0x028BB6 cmp.b #0x81,r0l` / `0x028BB8 bne 0x028C10` —— 相等才走片读下排。它的全部意义就是这条分支。
3. **不在名字表内**：`0x3EAD4` 的 18 项覆盖 `0x0F`–`0x20`，无 `0x81`；若它是类型码，诊断/日志路径将无法命名。
4. **不被分发器接受**：`0x0290E0 add.b #0xF0` / `cmp.b #0x0F` / `bhi 0x02915C`，`0x81` 落在范围外被直接跳过。作为过程信号它天然到不了那里（`0x028C02` 已覆盖）。
5. **存续期极短**：`0x028BB4` 写入 `0x4003FB`，`0x028C02` 在同一基本路径上覆盖。

`[推断]` 选 `0x81` 而非 `0x08`–`0x0F` 是**刻意落在名字表与分发表区间之外**（`0x0F–0x20`、`0x10–0x1F` 都被占），高位 `0x80` 又与 bank 号 `0x80/0x81` 呼应。反证条件：若某条未扫到的路径把 `0x4003FB` 以 `0x81` 持久保存，本推断不成立。

## 6. 失败路径

| 情形 | 结果码 `0x4003FB` | 状态位 `0x400D79` | 依据 |
|---|---|---|---|
| 上排门控暗（`base` 采样 ≤ 阈值） | `0x10` | 保持 1 | `0x028F96 bcs 0x02908E` → `0x02908E mov.b #0x10` |
| 上排 raw 不在表内 | `0x10` | 保持 1 | `0x029048` / `0x02908E` |
| 下排门控暗 / raw 不在表内 | `0x10` | **0** | `0x028C04 cmp #0x10` → `0x028C0A` 写 0 |
| 下排搜索全未命中 | 走兜底 15.5 mm 继续读，不单独报错 | — | `0x028F46 bne 0x028F64` → `0x028F7A` |
| 走片位置超时 | 不改码 | — | `0x028BDE`/`0x028C66`/`0x028CEA` 只在位置不符时重发，`er1=100000` 为驱动内部超时 |

**错误码写在哪**：识别函数**自己不写任何 sense/错误码**。它只产出上表两个字节；错误状态由上层 `0x02753E` 块合成到 `@er5`：

```
0x9000  若 0x400D72 ≠ 1        (02757A–02758A)
0x5000  若 0x400D79 ≠ 1        (02758C–02759C)
0x1100  若 0x4003FB == 0x10    (02759E–0275AC)
0x0000  其余
```

**是否重试**：**否**。`0x028E30` 每阶段只被调用一次；两阶段之间没有回到 `0x028BB0` 的边（`0x028BB0` 前驱唯一是 `0x028BAE` 的顺延）。`0x028B8C–0x028BAC`、`0x028BDE–0x028BFA`、`0x028C66–0x028C82`、`0x028CEA–0x028D14`、`0x028D18–0x028D3E` 五处循环全部是"位置未到位就重发走片命令"，与识别成败无关。

**成功侧的可观测标志**（`0x028DC8`–`0x028E1E`，`0x4003FB != 0x10` 才执行）：`0x400D86=1`、`0x400D7E=0x4203FA`、`0x400D84=0x4205DA`、`0x4007CA=0`、`0x4007C9=1`，随后 `jsr 0x02EEE2`、`jsr 0x02FFE6`。`0x400D86` 被 `0x02F26E`、`0x030110`（扫描参数装配）读取，可作"片夹已识别"的上层依据（`[实证]`）。

## 7. 调用链

### 7.1 向下：谁进 `0x028E30`

- `0x028BB0`（第一阶段）与 `0x028BFE`（第二阶段），**两者同属函数 `0x0289B4`**。
- 全镜像 `5C` 扫查（偶数偏移，`bsr` 实测 4 字节、位移在 +2、`PC=addr+4`）目标 `0x028E30` = 2 处；`5E`/`5A` 绝对 = 0 处；`0x00028E30` 三字节立即数 = 0 处。
- **结论：除 `0x028BB0` 外无其他调用者；`0x028BFE` 是同函数内的第二次调用，不是外部入口。** `[实证]`

### 7.2 向上：`0x0289B4` 怎么被命令通道唤起

```
0x0289B4  ← jsr @0x02799C  (函数 0x027930，序言 027930 mov.l er3,@-sp)
                          门控：027994 jsr 0x02CF60 → 027998 cmp.b #0x01 → 等 1 才进识别
0x027930  ← bsr @0x0276FA  (函数 0x027676，序言 027676 stm.l er4-er6,@-sp)
0x027676  ← bsr @0x02755E  (0x0274BC 段 = E0 作业体，0x02753E 为循环头)
0x02740A  ← 无静态调用点    (序言 02740A mov.l er3,@-sp；前一函数 0x027408 rts)

（`jsr`/`jmp` 绝对目标全镜像扫描：`0x0289B4` 命中 1 处 `0x02799C`；`0x028E30`/`0x028BB0`/`0x0290A0` 命中 0 处；`bsr` 扫描见 §7.1。`[实证]`）
```

`0x02740A` 的进入方式（`[推断]`，证据在 `0x010AE0` 区）：`010AEA er0=0x00470000` → `010AF0 er1=0x0002740A` → `010AF6 mov.l er1,@-er0`（存到 `0x46FFFC`）→ `010AFA/010AFE` 写 `0x46FFFA=0` → 再压 7 个 0 长字 → `010B1E mov.l er0,@0x4003F2`；紧邻的 `010AE6` 还在 `0xFFFFBC` 写 `0x5A00`（片上中断向量）。同一 `0x010A60` 区有一条平行块（`0x010A66`：`er0=0x480000`，按 `0x4003FA` 选 `0x20A5A`/`0x10F5C`，`0x010AB0` 存 `0x4003EE`，`0x010AC2` 用 `mov.l er0,sp` + 弹 7 寄存器 + `rte` 收尾）。形态是**中断/软中断上下文入口**，不是普通子程序。

命令通道侧的接口（`[实证]`）：E0 的 `CDB[2]` 落 `0x400C55`（写点 `0x026EBA`，读点 `0x0269BA`）；`0x02740A` 不读写 `0x400C55`，它与上层通过 `0x4206EC`（机构忙位，`bset #2`@`0x03C394` / `bclr #2`@`0x03C38A`，`0x0274C6` 轮询）和 `0x4207F8`（`0x0274C0` 置 1，`0x027F02` 读）异步握手。

**因此**：片夹识别是"机构作业"的一个环节，由 E0 机构控制命令启动的作业体驱动，而非由 SCSI 分派器直接 `jsr`。`[推断]` 触发点在中断/任务调度层；`[未证]` 该调度器的 `jsr @erN` 指令位置（`0x46FFFA` 无直接访存指令可见）。
