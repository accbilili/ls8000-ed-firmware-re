## 3. 关键技术结论（合并后）

### 3.1 内存映射

```text
0x000000-0x00FFFF  引导块（向量表/ISR）—— 不在升级包内
0x010000-0x047BF8  应用固件（本镜像）
0x200000-0x2FFFFF  ASIC / FPGA
0x400000-0x43FFFF  主 RAM
0x440000-0x44FFFF  第二 RAM / 图像缓冲描述
0xFFFF00-0xFFFFFF  H8/300H 片上 I/O
```

### 3.3 升级协议（Harness 第 20 轮）

```text
CDB: 3B 05 00 00 00 <len24> 00        （WRITE BUFFER, mode 5）
数据流帧头 6 字节:
    [0]=0xAB  [1]=?  [2..4]=24 位总长度（含头，大端）  [5]=0x56
净长度 = 总长度 - 6  → RAM 0x449B00
已处理计数           → RAM 0x449B04
暂存缓冲 0x418000
版本校验: 主机送 24 B 到 RAM 0x400D3D，与 ROM 0x019448 逐字节比对，不符拒绝
```

### 3.5 其他要点

- 最通用同步原语：`0x010B56` 设备就绪等待，25 个调用者

## 4. 唯一的真实缺口

**引导块 `0x000000–0x00FFFF`**：复位向量、中断向量表、1394/SCSI 收包 ISR。

Harness 已穷尽验证：
- 622 个已恢复函数中**无 `ldc`/`stc VBR`** → 固件不重定位向量表
- 在全部 2 字节对齐偏移检索 256×u32 向量表（≥40 不同项且 ≥150 可解码）→ **0 命中**
- 已证实该区与固件**同处一片 AMD 命令集 flash（基址 0）**

**结论（2026-10-24 第三轮更正）**：~~一次器件 flash dump（或拆焊读出）即可补齐。这是样本固有限制~~ → **引导块镜像本地就有**（`D://DS//TEST//LS8000//LS8000_bootblock.bin` 64 KB、`LS8000_full_512K.bin` 512 KB，已验证 `full[0:0x10000]==bootblock`），**不需要任何硬件操作**；引导块侧分析已完成（代码侧 + 数据侧），见 `REPORT_回写总账-20261024.md` R14–R20。
