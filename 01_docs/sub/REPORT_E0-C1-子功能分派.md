# E0 / C1 子功能分派完整恢复（含对 Harness 结论的一处修正）

日期：2026-10-24
输入：`D:\DS\TEST\LS8000\cfg_v4.json`（27,215 条指令）+ `LS8000_111_ROM.bin`
方法：从 CFG 提取 `0x0269A6` handler 全部 196 条指令，提取判等链，与 `0x03EDB8` 表交叉验证
边界：纯静态，未执行任何命令

## 0. 结论速览

1. **`0x0269A6` 的 12 路分派与 `0x03EDB8` 长度表 12/12 完全一一对应**（交集 12，双向无单边项）。这是一条强证据，把"表"和"代码"锁死。
2. 确认 **E0 设置 + C1 执行**的两阶段命令模式：E0 把子功能码与参数存入 `0x400C55` 起的区域，C1 读取该子功能码再分派执行。
3. **修正**：Harness `REPORT_PhaseM-O_v3.md` 第 2 节把 `0xC100` handler 描述为"影片/片夹类型分派（对应 35mm/中画幅片夹）"、把 `0x40/0x41/0x42/0x80/0x81/0x91` 当作片夹码——**这些值是 E0 子功能码，不是片夹类型码**。相应地，`REPORT_HostSide-3.md` 第 7 节待办 2 的前提需要修正。

## 2. 各分支行为（按代码实读，不推测语义）

### 2.1 `0x40 / 0x41 / 0x42` → `0x026A3E`

```asm
0x026A3E  mov.b @(0xa,er6),r0l     ; b[10]
0x026A42  extu.w r0
0x026A44  mov.b r0l,r0h            ; r0 = b[10] << 8
0x026A46  sub.b r0l,r0l
0x026A48  mov.b @(0xb,er6),r1l     ; b[11]
0x026A4E  add.w r1,r0              ; r0 = (b10<<8) | b11
0x026A50  sub.w r0,r0              ; r0 = 0
0x026A52  mov.w r0,@er5            ; @0x400410 = 0
```

三个码共享同一分支，读第 11–12 字节后**把 `0x400410` 清零**。三者差异仅体现在子功能码本身（由 E0 阶段区分），执行动作相同。

### 2.2 `0x80` → `0x026A2E`

```asm
0x026A2E  mov.b #0x01,r0l
0x026A30  mov.b r0l,@0x400D3B      ; 置标志 = 1
```

### 2.3 `0x81 / 0xB0 / 0xD0` → `0x026BD2`

无参数读取，汇入共同出口。这三个是"无数据动作"类。

### 2.4 `0xC1` → `0x026A54`

```asm
0x026A54  sub.l er0,er0
0x026A56  mov.b @(0x2,er6),r0l
0x026A5C  sub.b r0l,r0l            ; b[2] << 8
0x026A5E  mov.w r0,e0
0x026A64  mov.b @(0x3,er6),r1l
0x026A6C  add.l er1,er0            ; + b[3]
0x026A70  mov.b @(0x4,er6),r1l
0x026A74  shll.l #2,er1  (×4)      ; b[4] << 16
0x026A7C  add.l er1,er0            ; + (b4<<16)
0x026A80  mov.b @(0x5,er6),r1l
0x026A84  add.l er1,er0            ; + b[5]
0x026A86  mov.l er0,@0x400408      ; 存 24 位值
```

**组装出一个 24 位值 `(b4<<16)|(b2<<8)|b3 + b5` 存入 `0x400408`** —— 形态是一个地址。

### 2.5 `0xA0` → `0x026A92`

与 `0xC1` 完全相同的 24 位组装序列（偏移 2–5），之后继续读偏移 6、7、8（因此需要 9 字节）。Harness 已确认 `0xA0` 为自动对焦，窗口 = 分辨率×2.5 ~ 分辨率×10.68475。

### 2.6 `0xB3` → `0x026B0A`、`0x91/0x92` → `0x026BB2/0x026BBE`

13 字节 / 5 字节参数，本次未逐条细读，保留为待办。

## 3. 与 `0x03ED60` 地址白名单的关联

`0xC1` 与 `0xA0` 都把 24 位值装配到 `0x400408`。而 `0x03ED60` 的 11 组地址范围白名单（见 `REPORT_DataTables-解析.md` 第 4 节）正是访问合法性校验。

**推断**：`0x400408` 是待访问地址寄存器，`0x03ED60` 表用于在真正读写前校验该地址。这与 `READ BUFFER (0x3C)` 的"用 CDB 第 3..5 字节拼 24 位地址"行为同构。

**未确认**：`0x400408` 由哪段代码取出并校验；白名单的具体比对点。

## 4. 对 Harness 结论的修正

| Harness 原文 | 修正 |
|---|---|
| `REPORT_PhaseM-O_v3.md` §2：`0xC100` handler 依 `@0x400C55` 分派到 `0x40/0x41/0x42/0x80/0x81/0x91`，为"影片/片夹类型分派（对应 35mm/中画幅片夹）" | 这些是 **E0 子功能码**，不是片夹类型码。`0x400C55` 存的是 E0 的 CDB[2] |
| `REPORT_HostSide-3.md` §7 待办 2：片夹码 `0x40/0x41/0x42/0x80/0x81/0x91` 与 LS8000.md3 片夹条目一一对应 | **前提不成立**，该待办应撤销或改写 |
| `REPORT_MASTER.md` §C：`0x400C55` 为"片夹/模式码（源：CDB 0xE0 的 CDB[2]）" | 括号内正确；"片夹"一词易误导，应为"E0 子功能码" |

**片夹/胶片类型码的真实位置仍未定位。** 新的可能位置：
- `0x40/0x41/0x42` 子功能的 11 字节参数内（可能含片夹 ID）
- `0x400C55` 所在结构体的其他偏移
- 或完全由主机侧维护，固件只按 E0 子功能执行动作、不感知片夹型号

固件内确实存在胶片名表（`0x3E9D2` 起 14 项：`16mm Film` / `35mm Mount Film` / `Brownie Strip Film` / `6*4.5`–`6*9 Film` / `Panorama 58|65 Film`），但**尚未找到该表与任何代码分派点的引用关系**，因此不能断言它参与运行时判定——它也可能仅用于诊断输出。
