# B3（E0 子功能 0xB3）作业处理链分析报告

**对象**：`0x02BBAE`（80 条，已由前序确认）的被调链 + 执行层 B3 臂 `0x026B0A`
**工具**：修复版加载器 `h8fix.py` + `h8dis.py`（H8/300H 大端，地址 = 偏移 + 0x10000）
**样本**：`D:\DS\TEST\LS8000\LS8000_111_ROM.bin`（228,345 B，覆盖 0x10000–0x47BF8）；引导块另见 `LS8000_bootblock.bin`（64 KB，0x0–0xFFFF）
**产出目录**：本目录（`agent_b3/`），反汇编文件 `f_*.asm` / `region_*.asm` / `ram_src_17AB4.asm` / `ctx_*.asm` / `exec_026900.asm`

## 1. 结论摘要（TL;DR）

1. **`0x010BD2`/`0x010BD8` 不是 DMA 原语，而是中断屏蔽控制**：`0x010BD2` = `orc #0x07,exr`（I 位全置 1，屏蔽全部可屏蔽中断）；`0x010BD8` = `andc #0xf8,exr`（I 位全清，放开中断）。二者成对包裹每一次 flash 操作，构成临界区。［实证］
2. **真正的"传输"是 flash 擦除/编程**：`0x017A80` 把 ROM `0x17AB4–0x17F04`（336 B）拷到 RAM `0x400F5A`；`0x017A78` = `jmp 0x400F5A`（RAM 内**擦除分发器**）、`0x017A7C` = `jmp 0x40121C`（RAM 内**编程分发器**，`0x017AB4+0x2C2=0x017D76` 与 `0x400F5A+0x2C2=0x40121C` 严格对应）。分发器读引导块字节 `@0x17E` 选择命令集：`0x53('S')`=字宽（`0xAAAA/0x5554`），`0x00/0xFF`=字节宽（`0xAAA/0x554`）。本机 `@0x17E = 0x53` → 字宽路径。［实证］
3. **`0xFFDC30`/`0xFFDC34`/`0xFFFED2`/`0x400D38` 是 flash 驱动邮箱**（非 DMA 寄存器）：`0xFFDC34` = 目的指针（B3 写 0x6000）、`0xFFDC30` = 源指针（B3 写 0x400CA0 参数块）、`0x400D38` = 编程字节数（B3 写 0x21 = 33，即参数块长度，**不是命令字/类型码**）、`0xFFFED2` = flash 控制字（每次 flash 操作前后 `|= 3`，全样本只见置位不见清除）。［实证=用法；物理位置未证］
4. **引导块 ROM `0x6010` 的 17 字节模板在样本内不可读，但同目录 `LS8000_bootblock.bin` 完整覆盖 0x0–0xFFFF**（已验证 `bootblock == full_512K[0:0x10000]`，`111_ROM == full_512K[0x10000:]`）。模板内容：`00 04 fc 27 00 05 3a d3 00 03 42 95 00 0e 23 56 00`。"样本固有限制"实际不存在——不需要主动访问设备。［实证］
5. **B3 的物理效果**：把 13 字节 payload 组装成 33 字节参数记录，**擦写引导块 flash 0x6000–0x7FFF（持久设置区）**，回读校验后**把电机轴移动到 `V1 + 333`**（V1 为记录中第一个 32 位有符号字段，钳位 [−300, +300]，无效时用默认 333）。即"保存位置偏移并驱动机构就位"。［实证=机制；物理量名称/轴属推断］

## 2. 被调函数链逐个体（8 个目标）

### 2.1 `0x010BD2` / `0x010BD8` —— 临界区进/出（**修正：非 DMA**）
```
0x010BD2  orc  #0x07, exr   ; I2:I0 = 111，屏蔽全部可屏蔽中断
0x010BD6  rts
0x010BD8  andc #0xf8, exr   ; I2:I0 = 000，放开中断
0x010BDC  rts
```
B3 中用法：`jsr 0x010BD2` → `0xFFFED2 |= 3` → `jsr 0x017A78`(擦除) → `jsr 0x010BD8`；再 `jsr 0x010BD2` → `jsr 0x017A7C`(编程) → `0xFFFED2 |= 3` → `jsr 0x010BD8`（0x02BC80–0x02BCC2）。同一惯用法在 `0x016D88`、`0x016EE8`、`0x0110F2`、`0x01218C` 等 12+ 处重复，均围绕 flash 操作。［实证］

### 2.2 `0x017A80` —— flash 驱动装载体（ROM → RAM）
```
0x017A8C  er0 = 0x17AB4; er1 = 0x400F5A
0x017A98  loop: r2 = @er0+; @er1 = r2; er1 += 2; until er0 == 0x17F04
```
拷 0x150 = 336 B（168 字）到 RAM `0x400F5A`。flash 操作期间不能从 flash 取指，故驱动必须驻留 RAM。［实证］

### 2.3 `0x017A78` / `0x017A7C` —— RAM 跳板
```
0x017A78  jmp 0x400F5A    ; = ROM 0x017AB4 的 RAM 副本：擦除分发器
0x017A7C  jmp 0x40121C    ; = ROM 0x017D76 的 RAM 副本：编程分发器
```
两分发器同在被拷区间内，偏移差均为 0x2C2。ROM 侧对应桩：`0x0176CE = jmp 0x400F5A`、`0x0176D2 = jmp 0x401134`（另一个 RAM 入口，见"未决"）。［实证］

### 2.4 RAM 驱动内容（源 `ram_src_17AB4.asm`，运行于 0x400F5A/0x40121C）
- **擦除分发器 0x017AB4**：读 `@0x17E`；0x00/0xFF → `0x017AE6`（字节宽擦除）；0x53 → `0x017C10`（字宽擦除）。
- **字宽擦除 0x017C10→0x017CB0**：按 `@0xFFDC34`（= 0x6000）查表得扇区数与粒度——0x6000 → **2 扇区 × 0x1000 B**（即 0x6000–0x7FFF）。命令序：`0xAA@0xAAAA, 0x55@0x5554, 0x80@0xAAAA, 0xAA@0xAAAA, 0x55@0x5554`，随后每扇区 `@er0 = 0x30`，轮询 `& 0x80` 完成位；间隙写 `0x5A00` 到 `0xFFFFBC`。［实证］
- **编程分发器 0x017D76**：同样按 `@0x17E` 分流；字宽 → `0x017E56`。
- **字宽编程 0x017E56**：`er5 = @0xFFDC30`（源 = 0x400CA0）、`er6 = @0xFFDC34`（目的 = 0x6000）、计数 = `@0x400D38`（奇数 +1 取偶）；每字：`0xAA@0xAAAA, 0x55@0x5554, 0xA0@0xAAAA`（**0xA0 = program 命令**），`@er6 = @er5`，轮询双方 bit7 一致；指针各 +2，`@0xFFDC30/@0xFFDC34` 回写更新。B3：`0x21 → 34 B → 17 字`，即写 0x6000–0x6021。［实证］

### 2.5 `0x016E8E` —— 等待机构空闲
```
0x016E94  r0l = @0x4202A4（忙标志）；== 0 → 返回
loop: r0 = @0x400406 & 0xFF；== 0xF3 → 等待；@0x4202A4 != 0 → 等待；否则返回
      等待 = jsr 0x010B56
```
即"等 `0x4202A4` 忙标志清除"，轮询间隙调 `0x010B56`。［实证］

### 2.6 `0x010B56` —— 端口触发 + 陷阱调用（**修正：非简单就绪等待**）
读 `@0x4003EC` 分流；核心动作是对片上端口 `0xFFFF2E` 的位操作（`bset/bclr #4`、`& 0xBE`、`| (r4l & 0x41)`），并调 `0x010BCE` = **`trapa #0`**（软陷阱，推测为延时/让服务）。被 `0x016E8E`、`0x02B82A` 等轮询环调用。［实证=指令；trapa 服务内容未证］

### 2.7 `0x02BCCE` —— 共享的"flash 后重定位"例程
```
0x02BCD2  er0 = 0xFFFF48; *er0 |= 0xF000          ; 端口高半字节置 1
0x02BCE0  @0x440E50 = ROM[0x03F0F9]              ; 常量搬入第二 RAM
0x02BCEC  jsr 0x02BAA6                            ; 共享移动作业（0x81 链共用）
0x02BCF0  @0x400402 == 0x120/0x121 → 跳过移动
0x02BD08  @0x600D != 0 → 用默认 333               ; 记录有效标志
0x02BD10  er0 = @0x6000（u32，回读校验值）
          不在 [−300, +300]（有符号）→ 默认 333
0x02BD30  er6 = er0 + 333（0x14D）
0x02BD48  e0 = 0x64（100）; r0 = er6
0x02BD4E  bsr 0x02B8EA; bsr 0x02B82A              ; 相对移动 + 等待完成
0x02BD5A  @0x4202E0 = 0xE2
```
调用者两处：B3 尾（0x02BCC6）与 `0x027CAC`（0x027xxx 扫描完成路径）。［实证］
`0x02B8EA`（agent-motor 分析中）：`er0 = (参数<<16 | 目标)`，与 `@0x4202E0` 现位比较算增量，按方向步进；`0x02B82A` 轮询 `@0x4202E6` 等完成。模式 `0x400402` = 0x120/0x121 时两者都跳过移动。［实证］

### 2.8 `0x026B0A` —— 执行层 B3 臂（payload → 请求块）
分发器 `0x0269A6` 按 `@0x400C55`（子命令字）分多臂；**B3 臂的 `er6 = 0x400C55`**（不是 payload 缓冲），payload 13 字节位于 `0x400C56–0x400C62`（E0 表 `0x03EDB8` 中 B3 表内长度 = 13，已核实）。映射：
```
0x026B0E  @0x400412 = payload[0]
0x026B46  @0x400408 = P1<<24 + (P2+P3)<<16 + P4      ; P1..P4 = payload[1..4]
0x026B80  @0x40040C = P5<<24 + (P6+P7)<<16 + P8      ; P5..P8 = payload[5..8]
0x026B9A  @0x40040E = P9<<8 | P10                    ; u16
0x026BA0  @0x400413 = payload[11];  0x026BAA @0x400414 = payload[12]
公共尾 0x026BD2：@0x400400 = 0xF3B3（子码|0x40 高字节）；@0x4007C8 = 1（触发作业）；@0x400438 = 0
```
32 位组装惯用法（`mov.b src,r0l; mov.b r0l,r0h; sub.b r0l,r0l; mov.w r0,e0` → 字节落 bits24-31；`sub.l er1,er1; mov.b src,r1l; mov.w r1,e1` 或 `shll.l #2 ×4` → bits16-23；末字节直接 add）在 C1 臂（0x026A54）、flash 更新机（0x0121BC/0x0121F6/0x01222E/0x012268）、0x0265C6 等 ≥6 处逐字节相同，**第三字节一律落 bits16-23（与第二字节同位相加）而非 bits8-15**——已核对原始字节 `10 71 10 71 10 71 10 71`（4×shll = <<16）确认非解码错位。［实证=CPU 执行语义；源 C 意图见 §7 未决①］
`0x400410/0x400411` 非 B3 写入——由 0x40/0x41/0x42 作业（0x02AED0/0x02B9B2/0x02CAD6）维护，B3 只是搬入记录。［实证］

## 3. "DMA/寄存器写制链"结论

| 地址 | 角色 | 证据 |
|---|---|---|
| `0x010BD2`/`0x010BD8` | EXR 中断屏蔽置位/清除（临界区） | 指令本体 `orc #7/andc #f8, exr` |
| `0xFFDC34` | flash 驱动**目的指针**邮箱（B3 = 0x6000；其他用户 0x4000/0x8000/0x10000/0x20000/0x60000/0x70000 及 0x121xx 动态算出的区址） | 0x017B06/0x017C1C/0x017DC8/0x017E76 等读；12+ 处写 |
| `0xFFDC30` | flash 驱动**源指针**邮箱（B3 = 0x400CA0） | 同上 |
| `0xFFFED2` | flash 控制字，bits0-1 在 flash 操作前置 1（全样本 20 处引用全部为 `&0xFFFC|0x0003`，无一清除；`0x100A0`/`0x200A0` 为数据巧合误匹配） | 逐处核对 |
| `0x400D38` | 编程字节数（奇数取偶）；B3 = 0x21 | 0x02726E 写 0x0E/0x0272D6 写 0x05/0x027362 写 0x21 与各自编程长度一致 |
| `0x400CA0` | 参数块（33 B），即 flash 源数据 | 19 处引用 |
| `0xFFFFBC` | flash 操作期间反复写 `0x5A00`（看门狗/VPP 使能？） | 0x017BE2/0x017CB0 等 |
| `0xFFFF48` | 端口，`|= 0xF000`（B3 尾） | 0x02BCD2 |

`0xFFDC30/34/0xFFFED2` 均**低于** H8 片上 I/O 区（0xFFFF00–0xFFFFFF），推测为片上 RAM 变量或 ASIC 映射邮箱（驱动以普通 load/store 访问，行为与 RAM 变量一致）。［用法实证；物理实体未证］

## 4. 参数块 `0x400CA0`（0x21 = 33 字节）字段语义

| 块内偏移 | 来源（0x02BBAE 0x02BBC0–0x02BC70） | 语义 |
|---|---|---|
| +0x00..03 | `0x400408` 四字节（= BE32(V1)） | **V1：有符号 32 位位置偏移**（−300…+300），回读钳位后 +333 驱动电机 |
| +0x04..07 | `0x40040C` 四字节（= BE32(V2)） | V2：第二 32 位字段，B3 尾未消费（其他命令/引导块逻辑用） |
| +0x08 | `0x400410` | 0x40/41/42 作业维护的机构状态（B3 不写只搬） |
| +0x09 | `0x400411` | 同上 |
| +0x0A..0C | `0x400412/413/414` | payload[0]、payload[11]、payload[12] |
| +0x0D | 常量 0 | **记录有效标志**（0 = 有效；擦除态 0xFF = 无效，0x02BD08 据此放行） |
| +0x0E..0F | 0xFF, 0xFF | 定值（与 stock 引导块 0x600E/F 一致） |
| +0x10..20 | ROM `0x6010` 起 17 B 循环拷贝 | **配置模板**（被保留，B3 只更新记录前 16 字节） |

与 stock 引导块逐字节对照（`LS8000_bootblock.bin`）：`0x6000 = 00 00 00 85`（V1 = 133）、`0x6004 = 0`（V2）、`0x6008–0C = 00×5`、`0x600D = FF`（**stock 为无效态**）、`0x600E/F = FF FF`、`0x6010 起 = 模板`——结构与参数块完全同构，证明参数块就是该持久记录的"快照+更新"映像。［实证］
姊妹写证：`0x027362`（0x026632 调用）构造 33 字节块 = 0x6000 现内容前 16 B + 调用方 16 B + 0，同样写 0x6000——即**同一记录的互补更新器**（B3 更新前段保模板，0x027362 更新模板段保前段）。［实证］

## 5. `0x400D38 ← 0x21` 与 `0x400CA0` 的关系

`0x21` = 33 = 参数块字节数，即**编程长度**（编程例程 `0x017E56` 读它作为计数，奇数向上取偶 → 34 B → 17 字）。不是命令字/类型码。同族佐证：`0x02726E` 写 0x0E 配 14 B 块、`0x0272D6` 写 0x05 配 5 B 块、`0x027362` 写 0x21 配 33 B 块。［实证］

## 6. 引导块模板 `0x6010`——"样本限制"的修正

- `LS8000_111_ROM.bin` 确实只覆盖 0x10000–0x47BF8，`0x6010` 不在其中（任务书说法对本样本成立）。［实证］
- **但同目录 `LS8000_bootblock.bin`（65,536 B = 0x0–0xFFFF）与 `LS8000_full_512K.bin`（524,288 B = 0x0–0x7FFFF）都在盘上**，且已验证 `bootblock == full_512K[0:0x10000]`、`111_ROM == full_512K[0x10000:0x10000+len]`（offset = 地址）。［实证］
- 因此 17 字节模板**可直接读取**：`00 04 fc 27 00 05 3a d3 00 03 42 95 00 0e 23 56 00`；另 `@0x6000 = 0x00000085`、`@0x600D = 0xFF`、`@0x17E = 0x53`（flash 类型 = 字宽）。**无需 READ BUFFER 等主动设备访问**。［实证］
- 模板消费者：`0x03109E` 把 `0x6010/14/18/1C` 四个 u32 搬上栈（配合 `0x02ADCE`/`0x02C9E4` 下发），即"恢复/应用已存配置"路径。［实证］

## 7. B3 物理效果综合判断

**机制链（全部实证）**：
```
E0 B3(13B) → 0x026B0A 映射 → 请求块 0x400400–0x400414（opcode 0xF3B3 + V1 + V2 + u16 + 5B）
→ 0x4007C8=1 触发作业 0x02BBAE：
   ① 0x016E8E 等机构空闲
   ② 组装 33B 参数块 @0x400CA0（V1/V2/5B/标志/FFFF/模板）
   ③ 0xFFDC34=0x6000；IRQ off；FFFED2|=3；0x017A78→RAM 擦除分发器：擦 0x6000–0x7FFF（2×4KB 扇区）；IRQ on
   ④ 0x400D38=0x21；0xFFDC30=0x400CA0；IRQ off；0x017A7C→RAM 编程分发器：写 17 字（34B）到 0x6000；FFFED2|=3；IRQ on
   ⑤ 0x02BCCE：端口 0xFFFF48|=0xF000；0x440E50=ROM[0x3F0F9]；0x02BAA6；
      回读 @0x6000 得 V1；若 0x600D==0 且 V1∈[−300,+300] → 目标 = V1+333，否则 333；
      0x02B8EA(参数=100, 目标) + 0x02B82A 等待；@0x4202E0 = 0xE2
```
**物理判断**：
- B3 = **持久设置写 + 机构重定位**复合命令。−300…+300 是写入引导块设置记录的有符号 32 位**位置偏移量 V1**（钳位范围即合法域）；实际电机目标 = **V1 + 333**（333 = 0x14D 为默认/中心基位，无效时退化为 333），相对移动速度/计数参数 = 100。目标区间 33…633。［机制实证；"位置偏移"命名与 333 的物理单位为推断］
- 移动由共享相对移动原语 `0x02B8EA` 完成（与 0x40/0x41/0x42、0x81 作业同一条电机链，现位跟踪于 `0x4202E0`），模式码 `0x400402` = 0x120/0x121 时 B3 尾与移动原语都跳过移动（只落盘不动机）——0x120/0x121 推断为特定机型/介质变体。［实证=行为；机型含义推断］
- 记录有效性门：`@0x600D == 0`。stock 引导块该位为 0xFF，故出厂状态下 B3 的回读校验必然失败 → 走默认 333；只有本命令自己成功编程后（该位写 0）后续命令才会采纳 V1。［实证］

## 8. 未解决的疑问

1. **32 位组装的 `<<16` 怪癖**：CPU 实执行 `V = P1<<24 + (P2+P3)<<16 + P4`，第三字节与第二字节同落 bits16-23（相加）。若源 C 意为 BE32（第三字节应落 bits8-15），则这是编译器的系统性缺陷（≥6 处同式）。后果：仅当 payload[3] = 0（值 0–255）时两种解释一致；**负值（BE32 形式第三字节为 0xFE/0xFF）在两种解释下产出不同 V1**，主机侧编码格式因此无法从样本单独确定——需要主机驱动（Nikon TWIN/SW 侧）报文样本或实机验证。
2. **移动的物理轴未知**：`0x4202E0`/`0x02B8EA` 为多作业共享，B3 代码本身不指明轴（AFE 聚焦？片仓？光学架？）。需 agent-motor 的轴命名结论对齐。
3. **`@0x4202E0 = 0xE2`（226）何意**：移动完成后把"当前位置"变量改写成 226，与 V1+333（33…633）不一致——是状态码/命令字复用，还是归位到某个固定位？未证。
4. **`0xFFFED2` 的物理实体与 bits0-1 功能**：低于片上 I/O 区；全样本只置不清（或由引导块/上电清零）。是 ASIC flash 控制（VPP/CS）还是普通 RAM 标志，未证。
5. **`0x0176D2 = jmp 0x401134`**：第三个 RAM 例程入口，`0x401134` 无任何立即数引用（加载方式未知，疑似另一拷贝循环的算术寻址），内容未证。
6. **V2（`@0x40040C`）与 5 字节字段语义**：被 B3 写盘但 B3 尾不消费；读者可能是引导块逻辑或其他 E0 命令（0x03109E 只读模板段）。
7. **17 字节模板语义**：`00 04 fc 27 | 00 05 3a d3 | 00 03 42 95 | 00 0e 23 56 | 00` 形如多条 `00 XX YY ZZ` 记录（可能是各机构的目标位/限位参数），未证。
8. **模式码 `0x400402` = 0x110/0x120/0x121**：0x120/0x121 跳过移动；0x110 在 0x02740A 另有分支。具体机型/介质含义未证。
9. **`0x02BAA6` 在 B3 尾部的角色**：与 0x81 作业（0x028648 首指令即 `jsr 0x02BAA6`）共享，B3 在 V1 移动之前调用它——是"预定位"还是"应用已存设置"的独立动作，未证。
10. **`trapa #0`（0x010BCE）服务内容**：轮询延时/任务让出由陷阱处理程序实现，处理程序不在本样本分析范围。
