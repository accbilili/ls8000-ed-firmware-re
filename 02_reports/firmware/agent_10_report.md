## 3. `0x03655E` — 片夹配置解析（分派前调用）`[实证]`

**它就是任务问的"初始化/门禁"**：把当前片夹的holder 描述记录解析成一组全局参数，其中 **`0x400D7A`（父函数的分派键）唯一写点就在本函数 `0x036708`**。

流程（296 条指令）：
1. `0x036576` `*0x420264 = 0`（清零扫描计数器）；`0x03657C` `*0x400DAA = *0x4007C0`（holder 槽位数）。
2. `0x03658C-0x0365E2`：把 `0x4007C1[0..count-1]`（槽位码表）拷到栈并规范化：**9→4、4→5**（`0x0365B0`/`0x0365D4`）。
3. `0x0365E4`：取栈[0]（第一槽码）→ r3l；读 `record[r3l].byte[0x28] & 0x0F`（格式 nibble，record = `0x40064E + 码*0x3A`）。
4. nibble≠0（`0x036600`）：建 16 项查找表 `*(0x400DAA + nibble) = 槽码`（同 nibble 后者覆盖）。
   nibble==0（`0x036650`）：建"码出现标记"数组，再按 ROM 表 `0x3F81C`（每项 16 位=(索引,码)）生成顺序码表 `0x400DAB[k]`。
5. **`0x036708`：`*0x400D7A = record[槽0].byte[0x2A]`** ← 模式字节来源。
6. 其余派生 `[实证]`：
   - `0x036730` `*0x400DB7 = record.byte[0x32]&1`（`*0x4206EC≠0` 时强制 1）——`0x03C030` 的门禁、`0x035696`/`0x039342` 的分支条件
   - `0x036752` `*0x400DA0 = record.byte[0x29] bit7`
   - `0x036762` `*0x400DB4 = record.byte[0x29]&1`（`*0x4206EC≠0` 时强制 1）——选 `0x03708E`/`0x037084`、AF 路径、`0x0322C6` 参数块
   - `0x036784` `*0x400DB3 = record.byte[0x2C]&3`
   - `0x0367B0` `*0x400DB5 = (byte[0x2B] bit4) ? (byte[0x28]&0xF0)>>4 : 0`
   - `0x0367D0` `*0x400DB6 = (byte[0x2B]&0x40)>>6`
7. 每槽参数（槽 1..3，`0x0367D6` 循环；槽 1 在 `*0x4007C7==1` 时特例取自 record[0]）：
   `*0x400DA2[i] = read16(record[i+1]+0x33)`（`0x01605A`=16 位 BE 读）；`*0x400DB8[i] = record[i+1].byte[0x2D]`；`*0x400DBC[i] = record[i+1].byte[0x39]`。
8. **模式 0x10 收尾（`0x036892`）**：`*0x400DB7=1, *0x400DA0=0, *0x400DB8[0..3]=0xFF, *0x400DA2[0..3]=0, *0x400DBC[0..3]=0`（作废槽参数）。

> holder 记录表 `0x40064E` 在 **RAM**（运行时数据）。填充源未找到（只发现 9 处基址引用：`0x01087E/0x021D76/0x022550/0x022B8E/0x02511A/0x02567E/0x025874/0x02DAE2/0x0368FA`）`[未证]`。字段偏移与语义的对应（+6/+0x0A=原点、+0x0E/+0x12=尺寸、+0x28=格式码、+0x29/+0x2B/+0x2C=标志、+0x2A=模式、+0x2D/+0x33/+0x39=槽参数）由算术用法归纳 `[推断]`。

## 5. `0x02ED5A` — 配置广播（父在分派后以 (0,0) 调用）`[实证]`

- **`0x02F496`（电机/轴参数）**：`0x02FF00` 取索引 → 描述符 `0x41FFB4+0x22*i`；`0x02FF32((r5h,r5l))` 查 ROM 表 `0x3F616`（或 `0x3F71E`，24 B/项）→ 其 `byte[0x15]` 作第二索引；entry->`[0x10]` 指针所指 4 字节 → `*0x440FDC`；**`*0x400F32/36/3A/3E = (0x27100,0x249F0,0x186A0,0x64190)` 或全 `0x100590`**（视 `*0x4206EC`；`0x186A0`=电机超时常量）；`r0l∈{0,1}` 时从 ROM `0x3F736` 初始化 `0x420108-0x420120`（4×32 位轴参数）。
- **`0x02ED8A`（ASIC 寄存器表）**：`0x02FF32` 查表；忙等 `(*0x200002&0x28)`；`0x02D694`；**`*0x200150 = entry->byte[0x14]`**；遍历 entry->`[2]` 的 (偏移,值) 列表，写 **`*(0x200000+偏移)=值`**（`0xFFFF` 终止）；`*0x4003F6` 延时 12 tick。
- **`0x03A18C`（灯光/曝光，仅用 r5h）**：`r0==0` → **`*0x200208=0, *0x200212=0x78`(120)**；否则 `*0x200208=0, *0x200212=0x58`(88)。
- **`0x02EE6E`（扫描参数）**：`*0x400D5E=read16(entry+6)`、`*0x400D60=read16(+8)`、`*0x400D62=read16(+0x0A)`、`*0x400D64=0`、`*0x400D6E`(32b)=read32(+0x0C)。

`0x02FF32` = "按 (r0l,r0h) 对查 24 B 配置项，指针经 er1 返回"（规范化：`1→0`、非零→1）。

## 6. `0x03C030` — 区域查找 + 扫描位置计算 `[实证]`

- **门禁**：`*0x400DB7==1` → 直接返回（`0x03C04E`）。
- `flag=r1l`（父在模式 2 时传 1）：非零 → 区域索引 = flag-1（=0）；为零 → 用 `(X=*0x400D7C, Y=*0x400D7E)` 在区域矩形表（X0=`0x420308+4i`、W=`0x4204E8+4i`、Y0=`0x4203F8+4i`、H=`0x4205D8+4i`，计数 `*0x40041A`）中查找包含点 → `*0x449A30=索引`（未找到 0xFF）；索引 ≥ 计数 → 返回。
- 计算（大端，`er3=0x4203F8+idx*4`，`er5=0x4205D8+idx*4`）：
  - **`*0x4202F8 = (H/2 + Y0) / 12`**（`0x01872E` 32 位除）；随后 `+0xAB`(171)；若 >`0xFB`(251) → `*0x4202FA = 值-0x50`(80)，否则 `*0x4202FA=171`。
  - **`*0x4202AE = (H/2 + Y0) mod 12 + 0x1EC2`(7874)**；若 >`0x6C`(108) 减 108 否则 0；`*0x4202B0=*0x4202B2=` 同值。
  - `*0x4202FC = *0x4202FA`。
- 与 `0x0301CC` 的独立实现互证：`*0x4202F8 = *0x400DFE/12`、`*0x4202AE = *0x400DFE%12 + 7874`、再 `+171`（`0x0301CC` 反汇编实证）→ `*0x400DFE ≈ H/2+Y0`（帧中心参数）`[推断]`。

## 8. `0x400406` 低字节子状态码的去向（任务问题 5）`[实证，读者清单来自 refs.py 全固件扫描]`

**写点**：
- `0x0355A6`（父）：低字节 ← `0x10/0x11/0x12/0x13/0x14/0x15`（按模式，**替换**而非叠加：`(orig&0xFF00)|码`）。
- `0x035D78`（`0x035696`）：低字节 ← `0x20`（bit5，预扫描中）。
- `0x039A0A-0x039A20`（`0x039342`）：低字节 ← `0x20`（精细扫描中）。
- `0x0285C6`（片夹识别流）：低字节非零 → `|0x10`（bset#4）。
- `0x03C590` / `0x03CCB6`：低字节 ← **`0xF1`**（同时 `*0x400402=0`）——"完成确认"。
- 另有 `0x020C46/0x0215E4/0x02741E/0x02793E/0x027B3A/0x027DD8/0x032612` 以基址寄存器间接访问（未逐一展开）`[未证]`。

**读者（44 处指令，代表性）**：
- `0x0285CE-0x02860E`（片夹识别流）：低字节 == `0x80` → **`*0x400402=0x0F20, *0x400404=0x2000`**（转成状态码！）；∈ {`0x12,0x13,0x14,0x15`} → 分支 `0x028620`。
- `0x021002-0x02103C`（E0 状态解码）：==`0x80` 或 ==0 → 返回码 `0x66`；高字节≠0 → `0x02119C`；低字节 `0x10/0x11/0x12…` → `0x0210E8` 分支。
- `0x0213E8`：==1 且 `*0x400D78==0` → 清 `0x4206F2/0x4206F4`。
- `0x02DB64`：**忙等低字节 == 1**（空闲）后才继续。
- `0x03192C`：==`0x80` → `0x031E02` 错误处理。
- 其余散布：`0x0108BE/0x01197E/0x015E6A/0x016D74/0x016E9E/0x01769C/0x020BDE/0x0230E2/0x02317A/0x0237C4/0x023828/0x023B9C/0x023C36/0x023C9C/0x0251CC/0x028440/0x02DBEA/0x032D52/0x032F12`。

**结论**：`0x400406` 低字节是 **E0 内部状态机子状态码**：`0x01`=空闲、`0x10-0x15`=本作业各模式"定位/参数已设置"子态、`0x20`=扫描进行中、`0x80`=错误、`0xF1`=完成确认。主要由 E0 作业层/状态解码器/片夹识别流消费；**未发现直接进入 sense 三元组链**（该链走 `0x400402/0x400404`，经 `0x03E390`→`0x01914A`）——仅 `0x0285DE` 一处在 0x80 时把 `0x0F20/0x2000` 写入 `0x400402/0x400404` `[实证读者清单；与 sense 链整体关系未证]`。

## 9. 综合判断：E0 子功能 `0x10` 的物理效果（任务问题 4）

**E0 键 `0x10` = "按当前片夹配置执行一次扫描预处理作业（holder-aware scan preparation）"**，不是单一机械动作，而是完整作业链 `[推断，基于全链实证]`：

1. **片夹配置装载**（`0x03655E`）：从 holder 描述表解析格式模式 → `0x400D7A`，派生一批光学/机构参数。
2. **按模式分派执行**：
   - 模式 01/10 → **预扫描/对焦**（`0x035696`）：低分辨率扫描 + AF（`0x03C2B6/0x03C2D0`），为精细扫描确定焦点/曝光；模式 10 额外把灯光/曝光参数设到 226（`0x02B87C`）。
   - 模式 02 → **精细扫描**（`0x039342`）：归位后按帧高行数执行 CCD 曝光+步进主扫描。
   - 模式 04/08/20/40 → **AF 定位/多格式扫描预备**（`0x0370AC`+`0x037496`）：电机定位到计算目标 + 两遍 AF 采样求值（`0x037E68/0x0387AA`）。
3. **配置广播**（`0x02ED5A(0,0)`）：把空闲模式对推到电机参数（`0x400F32-3E`）、ASIC 寄存器表（`0x200000+off`、`0x200150`）、灯光（`0x200208/0x200212`=0/120）、扫描参数（`0x400D5E-6E`）。
4. **下一轮位置计算**（`0x03C030`，仅模式 2 传 flag=1 其余按坐标查区域）：算 `0x4202F8/FA/AE/B0/B2/FC`。
5. **状态上报**：置 `0x400D77/0x400D78` 通知 E0 作业层"作业生效、等待完成"（`0x02777A` 消费并清零）；`0x400406` 低字节记录子状态供 E0 状态机/片夹识别流跟踪。

即：**主机下发 E0 `0x10` ≈ "装载/识别片夹后，按片夹格式执行相应的扫描预备（预扫描/精细扫描/AF 定位），并刷新机构/光学配置与 E0 内部状态"**。物理效果集中在：CCD/灯曝光参数（ASIC `0x2001xx`/`0x200208`/`0x200212`）、电机定位（`0x4202xx` 目标与实际值）、AF 求值（`0x41FF3E` 缓冲区、`0x44903C` 结果）。

## 10. 与既有结论的冲突

1. team-lead 描述"`0x0355CC`: 低字节 = (原高字节)|0x10 后 bset#4"——实际为 `mov.w @er1,r0; and.w #0xff00,r0; bset #4,r0l`，即 `(orig&0xFF00)|0x10`（bset#4 作用于已清空的低字节）。**表述差异，无实质冲突** `[实证 0x0355CC-0x0355D6]`。
2. `0x400D7A` 的分派值 `0x10` 与 `0x4003FB` 的"未识别/默认"类型码数值相同（`0x02859E`、`0x027EA0` 均写 `*0x4003FB=0x10`）。二者是**不同变量**：`0x035706` 判 `*0x400D7A==0x10` 指格式模式 0x10（走 `0x02B87C` 设 226），不是片夹未识别 `[实证]`。提醒后续分析勿混淆。
