# agent-arms 报告：E0/C1 执行层 0x0269A6 全貌 + 0xA0/0xB3 两臂展开

工具链：h8fix.py 修复版加载器 + h8.lst（H8/300H 大端，地址=偏移+0x10000）。只读 D:\。
产物：`f_0269A6_full.asm`（207 条，无未解码字节，单一 rts@0x026BF6）、`f_026C46_parse.asm`、`dis_0269A6.py`、`dis_026C46.py`。

## 1. 架构澄清（重要，影响既有表的命名）[实证]

ROM `0x03E2E8` 起是一张 **SCSI opcode 分派表**，8 字节/条 `[opcode][3B field][4B handler]`，`0x00` 终止：
```
0x03E338: 24 → 0x02510C   0x03E340: 25 → 0x0254F6   0x03E348: 28 → 0x022EC2
0x03E350: 2A → 0x023A3A   0x03E358: 3B → 0x026534   0x03E360: 3C → 0x0267AA
0x03E368: C0 → 0x02694A   0x03E370: C1 → 0x0269A6   0x03E378: E0 → 0x026BF8
0x03E380: E1 → 0x026EFC   0x03E388: 00 00 00 00（终止）
```
- **0x0269A6 = opcode 0xC1（vendor）的处理函数**，即团队所称"E0 执行层"——精确命名应为 **C1 执行层**。
- **0x026BF8 = opcode 0xE0（vendor）的处理函数**：前置校验 + 解析体（0x026C46-0x026EFA 与 0x026BF8 的栈帧/收尾连续，实为一体；"解析层 0x026C46"只是其中段）。
- 协议为两段式：E0 命令解析入库（0x400C55=子功能码、0x400C56 起=payload），主机再发 C1 命令触发执行层（0x0269A6 读 0x400C55 开关分发）。
- E0 CDB @ 0x40043C：CDB[1] 低5位=0、CDB[3..5]=0、CDB[9]=0（0x026BF8 校验，违者 0x400436←0x50）；**CDB[2]=子功能码**（0x40043E，0x026C5E 表查找、0x026EB6 落库）；长度=(CDB[6]<<8)+(CDB[7]<<8)+CDB[8]（0x026C96-0x026CB6）。团队"payload 起于 CDB+2"对**子功能码**成立。
- C1 CDB 同在 0x40043C，但其 CDB[2..5] 必须为 0（0x0269A6 前置校验），子功能码取自 0x400C55（E0 命令的解析产物）。
- 0xC0 处理函数（0x02694A）：检测 0x400400 bit6（执行层公共尾置位的"已执行"标志），置位则 0x400400 bit7、0x4007C8=1、0x400438=0——佐证公共尾语义。

## 2. 0x0269A6 全函数结构（12 子功能值 → 8 臂 + default）[实证]

- 入口 0x0269A6：push er3-er6；er3=0x40043C、er4=0x400436、er6=0x400C55、er5=0x400410（0x0269E6 设）。
- **新增前置校验**（0x0269C0-0x0269E4，既有表未载）：`mem[0x40043D]&0x1F==0` 且 `mem[0x40043E..0x400441]==0`，否则 `0x400436←0x50`（0x0269D8→0x026BCE）并返回。r5l 循环 2..5，`beq` 续跑、非零即错。
- 开关（0x0269EC 起逐条 cmp.b #imm + beq/jmp）与落点，与团队表**完全一致**：

| 子功能 | 落点 | 臂 |
|---|---|---|
| 0x40/0x41/0x42 | 0x026A3E | 拼16位(被清零)→0x400410，**落穿进 0xC1 臂体** |
| 0x80 | 0x026A2E | 0x400D3B←1，直跳收尾 0x026BEE |
| 0x81/0xB0/0xD0 | 0x026BD2 | 公共成功尾 |
| 0x91 | 0x026BB2 | 0x42029E←payload[4] |
| 0x92 | 0x026BBE | 0x42029F←payload[4] |
| 0xA0 | 0x026A92 | 两个 32 位打包值 → 0x400408/0x40040C |
| 0xB3 | 0x026B0A | 13 字节 → 0x400408-0x400414 |
| 0xC1 | 0x026A54 | val1 → 0x400408 |
| default | 0x026BCA | 0x400436←0x56 |

- **公共成功尾 0x026BD2**（0x81/0xB0/0xD0/0x91/0x92/0xC1/0xA0/0xB3 均汇聚）：
  `0x400400 ← 0x4000|子功能码`（`mov.b @er6,r0l; extu.w r0`（清 r0h）`; bset #6,r0h; mov.w r0,@0x400400`，16 位整体覆写）；`0x4007C8←1`；`0x400438←0`。
- 0x80 臂与 default 臂跳过公共尾直跳 0x026BEE：**不更新** 0x400400/0x4007C8/0x400438（与团队表一致）。
- `extu.w r0`（0x1750）语义 = r0h 清零（byte→word 零扩展）[实证：H8 硬件语义 + 固件自洽——0x0269CE 处 r0h 为调用方残留值，若不清零前置校验地址必错；0x026C7E 同理]。因此 B3 路径残留的 r0h=p9 被 0x026BD4 清除，公共尾对各臂一致。

## 3. 0xA0 臂（0x026A92-0x026B06）详细展开 [实证]

读 `mem[er6+2..er6+9]` = **payload[1..8]**（0x400C57-0x400C5E），**不读 payload[0]**：

| 指令段 | 动作 |
|---|---|
| 0x026A92-0x026AC4 | `0x400408 ← (p1<<8)+p2+(p3<<8)+p4`（mov.l er0,@0x400408，8 字节指令 01 00 6B A0 + abs32） |
| 0x026ACC-0x026AFE | `0x40040C ← (p5<<8)+p6+(p7<<8)+p8`（0x026AFE） |
| 0x026B06 | `jmp 0x026BD2` 公共尾 |

组装手法（两段同构）：`sub.l er0,er0; mov.b @(d,er6),r0l; mov.b r0l,r0h; sub.b r0l,r0l; mov.w r0,e0` 得 a<<8；er1 逐字节 `mov.w r1,e1`/`shll.l #2 ×4`/`add.l` 累加。**ADD 而非 OR，高低两半进位互通**——即两个 16 位 BE 半字之和（"半字相加"的业务语义为[推断]）。
与 0xC1 臂（0x026A54-0x026A86）的 val1 计算**逐指令同构**（同读 payload[1..4]、同公式、同写 0x400408）；A0 = C1 的计算 + 第二个打包值。

## 4. 0xB3 臂（0x026B0A-0x026BB0）详细展开 [实证]

读 `mem[er6+1..er6+0xD]` = **payload[0..12]**（全部 13 字节，0x400C56-0x400C62）：

| 指令段 | payload | 落盘 |
|---|---|---|
| 0x026B0A-0x026B0E | p0 | `0x400412 ← p0`（mov.b r0l,@0x400412） |
| 0x026B14-0x026B46 | p1..p4 | `0x400408 ← (p1<<8)+p2+(p3<<8)+p4`（**0x026B46** 写点，与 A0/C1 同构） |
| 0x026B4E-0x026B80 | p5..p8 | `0x40040C ← (p5<<8)+p6+(p7<<8)+p8` |
| 0x026B88-0x026B9A | p9,p10 | `0x400410/0x400411 ← (p9<<8)+p10`（16 位 BE 字，经 er5=0x400410） |
| 0x026B9C-0x026BA0 | p11 | `0x400413 ← p11` |
| 0x026BA6-0x026BAA | p12 | `0x400414 ← p12` |
| 0x026BB0 | — | `bt 0x026BD2` 公共尾（r0h 残留 p9 被 extu.w 清除，行为与其他臂一致） |

13 字节 payload 恰好铺满 **0x400408-0x400414（13 字节连续区）**，与团队"B3 臂把 13 字节 payload 落 0x400408-0x400414"的判断一致 [实证]。

## 5. payload 长度与字段边界（双证据链）[实证]

- 长度表 @ `0x03EDB8`，(子功能, 最小长度) 对，0xFF 终止：`80→0, 81→0, A0→9, B0→0, C1→5, D0→0, 40→0x0B, 41→0x0B, 42→0x0B, 91→5, 92→5, B3→0x0D`。解析体强制 `最小长度 ≤ 实际长度 ≤ 13`（0x026CC0 bcc / 0x026CD4 bls），越界或表未命中 → `0x400436←0x50`。
- 工作区布局（解析体 0x026EB6-0x026EEA 实证）：`0x400C55=子功能码`（源 CDB[2]），`0x400C56+i = payload[i]`（i<长度）。执行层 er6=0x400C55，故 **payload[i] = mem[er6+1+i]**。
- 字段边界（执行层各臂读点，与解析体的 val1/val2 复算互相印证）：
  - payload[0]：仅 B3 用（→0x400412）；A0/C1 不用。
  - payload[1..4]：val1 = (p1<<8)+p2+(p3<<8)+p4 → 0x400408（C1/A0/B3 三臂共用）。
  - payload[5..8]：val2 = (p5<<8)+p6+(p7<<8)+p8 → 0x40040C（A0/B3）。
  - payload[9..10]：16 位 BE 字 → 0x400410（B3 实写；40/41/42 实写 0，见 §7）。
  - payload[11]/[12]：→ 0x400413/0x400414（仅 B3）。
  - payload[4]：→ 0x42029E/0x42029F（91/92）。
- 字节序：全部多字节字段大端（H8 原生）；val 的 (a<<8)+b+(c<<8)+d 结构中 a/c 为高字节。
- 解析体（0x026D10-0x026D74）另从栈缓冲复算 val1→er3、val2→@(0xe,sp) 并按子功能做**数值门限**校验，越界写 `0x53`：40→val1≤0x3BFA(15354)；41→≤0x1C2(450)；42→≤0xCD3(3283)；C1→≤0x1C2；A0→动态门限（0x026E3E-0x026E7E，经 0x018E1E/0x01872E 以 0x2710/0xA6F3/0x0FA0 计算）；B3→有符号 -300≤val1≤300（0xFFFFFED4/0x12C）；91/92→val1∈{0,1}。**这是"450/1000/480"门限的产地**，供门限判决任务参考。

## 6. 落盘布局为何不同（作业层消费方式决定）[实证+推断]

- **A0 作业函数 0x03A3D4**：仅在两处错误上报路径读 `mov.w @0x40040a`（val1 低 16 位）与 `mov.l @0x40040c`（val2 全 32 位）→ 转存 0x420272/0x42026E 后跳 0x03A984 收尾（0x03A418/0x03A424 与 0x03A95E/0x03A96A）。即作业层按"两个值"消费，且 val1 只取其低半 [实证：读点清单]。
- **B3 作业函数 0x02BBAE**：把 0x400408-0x40040F 逐字节搬入 0x400CA0+0..7，再按 0x400410/0x400411/0x400413/0x400414/0x400412 顺序填入 param[8..0xC]，param[0xD]=0、param[0xE..0xF]=0xFF，末尾拼 17 字节模板（0x6010）成 0x21 字节块 + DMA。即作业层按字节消费并重排 [实证：0x02BBC0-0x02BC70]。
- 结论 [推断]：A0 走"少而打包的值"布局（两个 32 位槽），B3 走"13 字节连续原样区"布局（作业层逐字节重组）——布局差异由作业层消费方式决定，而非 payload 长度本身；两者对 payload[1..8] 的解析完全同构（A0 ⊂ B3，C1 ⊂ A0）。

## 7. 与团队既有表的出入（逐条，附判定依据）

1. **命名/架构**：0x0269A6 是 opcode 0xC1 处理函数（分派表 0x03E370 [实证]），非 E0 opcode 处理函数；E0 的是 0x026BF8。团队表内容不受影响，但"E0 执行层"应正名为"C1 执行层（执行 E0 命令解析出的子功能）"。
2. **40/41/42 臂写值**：既表称"取 0x400C5F/0x400C60 拼 16 位 → 写 0x400410"。实证：值确实拼出（0x026A44-0x026A4E，`(p9<<8)+p10`），但 **0x026A50 `sub.w r0,r0`（19 00，h8.lst 1900/ff00 实证）将其清零**，0x026A52 实写 `0x400410 ← 0x0000`。判定：指令序列 6E 68 00 0A / 17 50 / 0C 80 / 18 88 / 6E 69 00 0B / 17 51 / 09 10 / 19 00 / 69 D0 字节对齐精确，无歧义。
3. **40/41/42 臂落穿**（既有表未提）：0x026A52 后无跳转，直接落入 0x026A54（0xC1 臂体）→ 40/41/42 还会写 `0x400408←val1` 并走公共尾。实证：0x026A52+2=0x026A54 即 C1 臂首指令。
4. **公共尾精确语义**：`0x400400 ← 0x4000|子功能码`（16 位整体覆写，非原地 |=0x40）；对 B3 路径同样成立（extu.w 清残留 r0h）[实证]。既表"|="为粗略表述。
5. **新增**：入口前置校验（§2）与 0x80/default 跳过公共尾的行为明细（后者与既表一致）。
6. **新增**：解析体数值门限（§5 末），0x50/0x53 两类检查码分工：0x50=结构错（表未命中/长度越界/CDB 保留位非 0），0x53=数值越界，0x56=执行层 default。

## 8. 未解决的疑问

1. E0 payload 数据的栈缓冲中转机制 [未证]：0x026BF8 设 `er5=sp+1`（13 字节栈缓冲，0x026CE4-0x026CF6 先清零），0x026D06 `jsr 0x0118D0`（→0x013994，未展开）填充，源取自 `mem[sp+0x18]`（16 位）——该栈槽在本函数内无任何写入，推断由分派器/调用方预置；CDB[10] 之后是否即数据区未证。
2. A0 作业函数成功路径在何处消费 0x400408/0x40040C [未证]：已证的两处读点均在错误上报路径；成功路径可能经 0x03A994 等子程序或后续作业代码读取（属 0x03A3D4 展开任务范围）。
3. val 的业务语义（两个 16 位 BE 半字之和：起始+计数？位置+偏移？）[未证]；payload[0] 的语义（A0 忽略、B3→0x400412）[未证]。
4. 长度公式 `(CDB[6]<<8)+(CDB[7]<<8)+CDB[8]` 与 24/16 位 BE 长度字段的对应关系（对 ≤13 的长度等价于 CDB[8]，CDB[6]=CDB[7]=0）[未证]。
5. 40/41/42 臂 0x026A50 的 `sub.w r0,r0` 是固件本意（刻意写 0 重置 0x400410）还是 ROM 补丁痕迹 [未证]。
6. 分派表 8 字节记录中 3 字节 field 的含义（C1/E0/E1 均为 0x14，C0 为 0x754）[未证]。
