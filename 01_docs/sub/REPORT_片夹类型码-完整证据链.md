# Nikon LS-8000 ED 片夹类型码：完整证据链

分析日期：2026-10-24
镜像：`LS8000_111_ROM.bin`（228,345 字节，SHA-256 `fd1f17c5…be85`，与器件 flash 逐字节一致）
基址：`0x10000`

---

## 0. 一句话结论

片夹类型码**不是一个码，是两套**，此前三套工具的记录把它们混在一起了：

| 项目 | RAM 地址 | 谁产生 | 取值 | 语义 |
|---|---|---|---|---|
| **主机请求码** | `0x400C55` | 主机下发（SCSI CDB[2]） | `0x40`/`0x41`/`0x42`/`0x80`/`0x81`/`0x91`/`0x92`/`0xB3`/`0xA0`/`0xB0`/`0xC1`/`0xD0` | 机构控制子命令 |
| **设备识别码** | **`0x400D79`** | 设备自己光学读码 | `0x01`（待识别）/ `0x10`–`0x1F` / `0x81`（中间态）/ `0x00`（下排失败） | **片夹 / 画幅类型** |

真正的"片夹类型码"是后者。它不由主机指定，而是**扫描仪用 CCD 读片夹上的透光孔图案**得出。

## 1. 识别机制：光学一维条码

识别函数入口 **`0x028E30`**（`stm.l er2-er3, @-sp` / `stm.l er4-er6, @-sp`，标准 H8 序言）。

```asm
028E30  stm.l    er2-er3, @-sp
028E34  stm.l    er4-er6, @-sp
028E38  sub.l    #0x12, sp
028E3E  mov.b    r0l, @(0x9,sp)      ; 保存 bank 参数（0x80 或 0x81）
028E42  mov.l    #0x004407FE, er1
028E48  mov.b    #0x04, r0l          ; 采集模式 4
028E4A  jsr      0x02D700            ; 采集一帧
028E4E  mov.l    #0x00C2D000, er4    ; 采样缓冲
```

采样缓冲 `0xC2D000` = **10000 × u16**。

```
10000 / 157.480315 = 63.5 mm
157.480315 = 4000/25.4        ; 4000 dpi 的 samples/mm，双精度常数 @0x3EDE0[0]
```

LS-8000 最大画幅 6×9 为 56 mm，加边距 63.5 mm。**这 10000 个采样就是一条横跨整机光学宽度的 CCD 行**，片夹上那排孔被当作一维码读入。

### 1.1 阈值是自适应的

```
遍历 10000 个采样求 max / min
if (min > max/2)  min = 0        ; 遮光端与透光端差距不够大时，放弃 min
if (max < 0x0FFF) max = 0x3FFF   ; 整体偏暗时，抬高上限
threshold = (max + min) >> 1
```

设计意图：光源老化、灰尘、片夹材质、CCD/AFE 个体差异都会改变绝对亮度，用本次采样的极值自算中点，比固定阈值鲁棒。

`0x0FFF` 与 `0x3FFF` 只是阈值处理里的钳位常数，**不能据此断言 ADC 是 12 或 14 位**。

## 2. 两个 bank 的几何

坐标原点是**采样窗口的基准端**（缓冲索引 10000 那一端），方向朝索引 0。

```
pitch_字节 = int(157.480315 × pitch_mm) × 2
base_字节  = (10000 - int(157.480315 × C_mm)) × 2
```

### bank 0x80 — 上排：位置硬性，无搜索

| 常数 | 地址 | 值 |
|---|---|---|
| pitch | `0x3EF50` | **10.000 mm** |
| 门控位置 | `0x3EF58` | **11.5 mm** |

五个采样点（距基准端）：**11.5 / 21.5 / 31.5 / 41.5 / 51.5 mm**

`base_字节 = (10000 - 1811) × 2 = 16378`，`pitch_字节 = 1574 × 2 = 3148`。

### bank 0x81 — 下排：先光学搜索定位

| 常数 | 地址 | 值 |
|---|---|---|
| pitch | `0x3EF60` | **8.000 mm** |
| 搜索起点 | `0x3EF68` | **1.7 mm** |
| 搜索终点 | `0x3EF70` | **26.0 mm** |
| 兜底位置 | `0x3EF78` | **15.5 mm** |

在 `[1.7, 26.0] mm` 内逐点找**第一个透光采样**，把它当作首个开口的近端边缘；命中后 `+2.000 mm`（= pitch/4）落到开口中心；全部未命中则用 15.5 mm 固定兜底。

这就是下排能容忍机械位置误差的原因——**每次先找基准再读码**。上排不能。

## 3. 位映射（反汇编验证）

`0x028F8C` – `0x028FF4`，两排共用：

```asm
028F8C  sub.b    r5l, r5l            ; r5l 清零，作为位累加器
028F8E  mov.l    er4, er0
028F90  add.l    er6, er0
028F92  mov.w    @er0, r0            ; 门控采样 base
028F94  cmp.w    r3, r0
028F96  bcs      0x02908E            ; 门控 <= 阈值 -> Unknown，直接退出
028F9A  mov.l    er6, er0
028F9C  mov.l    @(0xE,sp), er1      ; er1 = pitch
028FA2  sub.l    er1, er0            ; base - 1*pitch
...
028FAC  bset     #0, r5l             ; bit0
028FB8  sub.l    er0, er1            ; base - 2*pitch
028FC2  bset     #1, r5l             ; bit1
028FD0  jsr      0x018E1E            ; 32×32 乘法 -> 3*pitch
028FE0  bset     #2, r5l             ; bit2
028FE8  shll.l   #2, er0             ; 4*pitch
028FF4  bset     #3, r5l             ; bit3
```

三条要点：

1. **极性**：采样 **>** 阈值才置位 → **透光 = 1，遮光 = 0**
2. **门控不是数据位**，只做合法性判断。门控暗 → 整件判 Unknown
3. **每个 bit 只比较 1 个采样点**，不取平均、不做多数表决。所以孔必须正对采样点，且宽度要吃掉机械间隙

## 4. 解码器（反汇编验证）

### 4.1 上排（bank 0x80），`0x028FFA` 判 bank，`0x029000`–`0x029048`

| raw (bit3..0) | 返回码 | 名字表项 |
|---|---|---|
| `0x0F` | **`0x11`** | Test（工厂/维修工装） |
| `0x08` | **`0x12`** | 16mm Film |
| `0x0A` | **`0x13`** | Praparat（玻片） |
| `0x02` | **`0x14`** | 35mm Mount Film |
| `0x03` | **`0x15`** | 35mm Strip Film |
| `0x04` | **`0x16`** | Brownie Mount Film |
| `0x06` | **`0x17`** | Brownie Strip Film |
| `0x05` | **`0x18`** | Brownie Strip Film with G |
| `0x07` | **`0x81`** | → **进入第二阶段的中间态**，非终止码 |
| 其它 | `0x10` | Unknown |

**注意一处反直觉**：raw `0x05`→`0x18`、raw `0x06`→`0x17` 是**交叉**的。返回码顺序（0x16 < 0x17 < 0x18）与 raw 码顺序（0x04 < 0x05 < 0x06）不一致。这不是笔误，`0x02900C cmp.b #0x05 / beq 0x02903C` 与 `0x029010 cmp.b #0x06 / beq 0x029040` 明确如此。

### 4.2 下排（bank 0x81），`0x02904A` 判 bank，`0x029052`–`0x02908C`

| raw | 返回码 | 画幅 |
|---|---|---|
| `0x08` | `0x19` | 6×4.5 |
| `0x0A` | `0x1A` | 6×6 |
| `0x09` | `0x1B` | 6×7 |
| `0x0B` | `0x1C` | 6×8 |
| `0x0C` | `0x1D` | 6×9 |
| `0x0E` | `0x1E` | Panorama 58 |
| `0x0D` | `0x1F` | Panorama 65 / XPAN |
| 其它 | `0x10` | Unknown |

**下排所有有效码的 bit3 恒为 1** —— 最外侧那点永远透光。七个有效码正好用满 `P1P2P3` 的七种非零组合。

## 6. 类型码的落地与消费（本轮新增）

Harness 的 `REPORT_Holder-Hole-Pattern.md` 只写到"解码器返回什么"，没有追返回码去向。本轮补齐：

### 6.1 调用者 `0x028BB0` 附近

```asm
028B82  mov.b    #0x01, r0l          ; 预置值 = 1
028B84  mov.l    #0x00400D79, er6    ; er6 -> 类型码地址
028B8A  bra      +0x16
...
028BAE  mov.b    #0x80, r0l          ; bank 0x80（上排）
028BB0  bsr      0x028E30            ; 识别
028BB4  mov.b    r0l, @er6           ; ★ 写 0x400D79
028BB6  cmp.b    #0x81, r0l          ; 是 GR 吗
028BB8  bne      0x028C10            ; 不是 -> 结束
028BBA  mov.l    #0x0003EDE0, er1    ; 157.480315
028BC0  mov.l    #0x0003EF38, er2    ; 22.3
028BCE  jsr      0x018AA0            ; 软件双精度
028BD2  jsr      0x01876A            ; double -> int -> 3512
028BD6  add.w    #0x07B0, r0         ; +1968 -> 5480 采样
028BE0  mov.l    #0x000186A0, er1    ; 100000，超时
028BE8  jsr      0x02ADCE            ; 走片
028BF2  mov.w    @0x4202A2, r0       ; 轮询位置
028BF8  cmp.w    r5, r0
028BFA  bne      0x028BDE
028BFC  mov.b    #0x81, r0l          ; bank 0x81（下排）
028BFE  bsr      0x028E30
028C02  mov.b    r0l, @er6           ; ★ 再写 0x400D79
028C04  cmp.b    #0x10, r0l          ; 下排 Unknown?
028C06  bne      0x028C10
028C08  sub.b    r0l, r0l
028C0A  mov.b    r0l, @0x400D79      ; ★ 清 0
028C10  bsr      0x0290A0
028C14  mov.b    @er6, r0l           ; 读回类型码
028C16  cmp.b    #0x15, r0l
028C18  beq      0x028C26
028C1A  mov.b    @er6, r0l
028C1C  cmp.b    #0x17, r0l
028C1E  beq      0x028C26
028C20  mov.b    @er6, r0l
028C22  cmp.b    #0x18, r0l
028C24  bne      0x028C8C
028C26  sub.l    er1, er1
028C28  mov.b    @er6, r1l
028C2A  shll.l   #2, er1             ; ×4
028C2C  shll.l   er1                 ; ×2 -> ×8
028C2E  mov.l    #0x00000010, er0
```

`0x028C14` 那组判等只挑 `0x15` / `0x17` / `0x18` —— 即 **35mm Strip / Brownie Strip / Brownie Strip with G**，三种"条片"型片夹。随后 `返回码 × 8` 当索引偏移，`+0x10` 作基址 —— 典型的**定长记录表查表**，具体表基址在 `er0` 后续指令里。

### 6.2 `0x400D79` 的全部读写点

| 地址 | 函数 | 指令 | 方向 | 值 |
|---|---|---|---|---|
| `0x027E30` | `0x027DC4` | `mov.b r0l, @0x400D79` | 写 | **`0x01`**（预置） |
| `0x027EC4` | `0x027DC4` | `mov.b r0l, @0x400D79` | 写 | **`0x01`**（预置） |
| `0x028BB4` | `0x028BB0` | `mov.b r0l, @er6` | 写 | 上排返回码 |
| `0x028C02` | `0x028BB0` | `mov.b r0l, @er6` | 写 | 下排返回码 |
| `0x028C0A` | `0x028BB0` | `mov.b r0l, @0x400D79` | 写 | **`0`**（下排 Unknown） |
| `0x02758C` | `0x02753E` | `mov.b @0x400D79, r0l` | 读 | — |

**语义因此确定**：

- `0x01` = **已初始化、尚未识别**（`0x027DC4` 在进片流程开始时预置）
- `0x00` = **识别失败**（下排 Unknown 时清零）
- `0x10` = **Unknown**（上排判不出）
- `0x11`–`0x18` = **片夹类型**（上排直接判出）
- `0x19`–`0x1F` = **画幅**（GR 走片后由下排判出）
- `0x81` = **瞬时中间态**，只在上排返回后、进入下排识别前存在，不会停留

### 6.3 唯一的读取点 `0x02753E`

```asm
02758C  mov.b    @0x400D79, r0l
027592  cmp.b    #0x01, r0l
027594  beq      0x02759E
027596  mov.w    #0x5000, r0
02759A  mov.w    r0, @er5           ; 未识别 -> 报 0x5000
02759E  mov.b    @0x4003FB, r0l
0275A4  cmp.b    #0x10, r0l
0275A6  bne      0x0275AE
0275A8  mov.w    #0x1100, r0
0275B0  mov.w    r0, @er5           ; 已识别且 0x4003FB==0x10 -> 0x1100
0275AE  sub.w    r0, r0             ; 否则 0
```

这里 `cmp.b #0x01` 不是"类型码等于 1"，而是**判断是否还停在预置态**——即"片夹还没被识别出来"。这是一个**门禁**，不是类型分发。

真正按类型分发在 `0x028C14` 和 `0x0290A0`（`0x028C10` 调用的后续函数）。

### 6.4 两套码互不相干

`0x400C55`（E0 子功能码）与 `0x400D79`（类型码）**地址相邻但无任何数据流**：

- 全镜像对 `0x400D79` 的立即数引用仅 6 处，全部在 `0x027xxx` / `0x028xxx`
- E0 处理函数 `0x026BF8` 与 C1 处理函数 `0x0269A6` **不读写 `0x400D79`**
- 反之，`0x028E30` / `0x028BB0` **不读写 `0x400C55`**

所以主机"声明"的片夹类型与设备"读出"的片夹类型是**两条独立通道**。

## 8. 对既有记录的三处修正

### 8.1 固件里写的是 `Brownie`，不是 `FH-869`

`REPORT_Holder-Hole-Pattern.md` 第 7.1 节把返回码 `0x16/0x17/0x18` 直接标成 `FH-869M/FH-869S/FH-869G`。

实测名字表（`0x3EAD4`）原文是：

- `0x16` → `Brownie Mount Film`
- `0x17` → `Brownie Strip Film`
- `0x18` → `Brownie Strip Film with G`

固件里**没有出现过 `FH-` 前缀**。`FH-835M` / `FH-869GR` 这些是尼康产品型号，出现在主机侧 `LS8000.md3` 的用户说明资源里（Codex 的 `holder-original-text-evidence.json` 已存档）。

`Brownie` = 柯达 620 胶卷系列，属中画幅，与 FH-869 系列对应是**合理的推断**，但属于推断而非固件证据。施工表里的型号名应视为映射注释。

### 8.2 `0x400C55` 不是片夹类型码

`REPORT_PhaseM-O_v3.md` 称 `0xC100` handler 依 `@0x400C55` 分派"为影片/片夹类型分派"。

`REPORT_FilmCode-Mapping.md` 本身已正确认定为「SCSI CDB[2]，即 E0 机构控制的第 3 字节」。两处表述冲突，以后者为准。片夹类型码在 `0x400D79`，与 `0x400C55` 无数据流。

`REPORT_FilmCode-Mapping.md` 第 4 节的"片夹族归纳"（`0x40/0x41/0x42` → 35mm 族，`0x80/0x81/0x91/0x92` → 中画幅族）**没有代码依据**，是从数值分组推测的。E0 handler 不读类型码，无法证实该分族与片夹对应。这条应降级为假设。

### 8.3 `bsr` 是相对跳转，绝对地址搜不到

`0x028BB0` 处字节 `5c 00 02 7c` 是 **`bsr d:16`**，目标 `0x028BB0 + 4 + 0x027C = 0x028E30`。

所以对 `0x028E30` 做 3 字节绝对地址搜索得 0 处，**不能据此认为无人调用**。识别函数只有一个调用者 `0x028BB0`，通过 16 位相对跳转进入。

同理，`cfg_v4.json` 的 `owner` 在 `0x028B00`–`0x028D00` 是空白，说明该段未被 CFG 覆盖——不是没有代码，是 CFG 从该段之后才重新接上。

## 10. 仍未确定的

1. **绝对机械基准**。固件只给"距采样窗口基准端 11.5 mm"这类相对量，没有表达它与片夹机械定位边的对应关系，也没说插到位后停在哪个工位。自制件唯一缺的就是这一条。
2. **`0x027DC4` 的完整语义**。已知它预置 `0x400D79 = 0x01`，同段还写 `0x4003FB = 0x10`、`0x400D72 = 0x05`、`0x400D78 = 0x01`、`0x40041A = 0`，且含走片超时轮询。这是一个进片流程的状态机，边界未完全确定。
3. **`0x028C2E` 之后查表的表基址**。已确认按 `返回码 × 8` 索引，但记录表在 `er0` 的后续指令里，未追到具体地址与字段含义。
4. **`0x4003FB` 的语义**。初值 `0x10`，被 `0x02753E` 比较后决定报 `0x1100` 还是 `0`。可能是"扫描模式"或"读出结果码"，未证。
5. **主机侧 E0 子功能码与型号的对应**。需要抓主机实际发出的 CDB，静态无法闭合。
