## 3. 本轮核心成果

### 3.1 B16：解码器缺陷与 1299 条丢失指令 `[实证]`

**缺陷**：`h8tab.py` 的表项正则 `^([0-9a-f]{2,8})\s+([0-9a-f]{2,8})\s+…` 最多吃 8 位十六进制，而 `h8.lst` 里有 **6 条 12 位（6 字节模式）表项**被**整行跳过**（393 → 399 条）：

```
01006900 ffffff88 0 mov.l r32ih    r32l      010078006b20 ffffff0ffff8 0 mov.l r32d32hh r32l
01006980 ffffff88 0 mov.l r32l     r32ih     010078006ba0 ffffff0ffff8 0 mov.l r32l    r32d32hh
…（其余 8 条同族）                                              ↑ 12 位 val/mask → 整行被丢
```

**后果**：`mov.l @(d:32,ERn),ERm` / `mov.l ERm,@(d:32,ERn)`（10 字节）**永不解出** → 反汇编出现 `.byte` 断点，其后代码整段不可见。
**实测损伤**：42 个洞点 → 波及 **36/529** 个函数；因线性扫描按 2 字节步进，**错位为 0**（其余指令长度全对）；**复走后多解出 1299 条指令**（远超洞点数——10 字节指令解开后其后整段代码才显形）。

**新解出代码正是图像算法骨架**：

| 函数 | 新解出 | 关键内容 |
|---|---|---|
| `0x030000` | 88 | 读 `0x400D7A`(holder 模式) 比 0x10；读 `0x400D7E`(原点 Y)；写 `0x4202FA = 0xAB`(**171**，与静态公式 `(H/2+Y0)/12+171` 一致) |
| `0x0354DE` | 114 | 读 holder 每槽参数 `0x400DA2`；`mulxu.w` 缩放；常量 `0x22`(=34，与 `0x02896C` 传感器表步长同源) |
| `0x0315A8` | 93 | `er1 = 0x74 + sp`——**0x74 是栈帧偏移，不是行距**（第六轮更正，见 §8.3）；含 `jsr 0x018E68`/`0x018AA0`/`0x01876A` 双精度调用与表 `0x420108`（16 B/项，RAM 运行表）；常量 `0x7A120` = **500000** |
| `0x03B87C` | 97 | 建 `0x4499D8`/`0x4499E8` 位置表；调 `0x02ADCE`（位置换算）、`0x0322B4` |
| `0x022F4E` | 152 | 读 `0x40043E`、写栈上表项（`0x400402` 判定 0x50 错误码） |

### 3.5 六数值门限：全部坐实（§11.4 的悬案关闭）`[实证]`

前序「找不到」的原因是**反汇编只做到 `0x026CD4`（长度 ≤ 13 检查）就收手**；六个比较在同一函数**后段 `0x026DF8–0x026EA8`**（`cmp.l #imm32,er3`，大端编码 `7A 23 <imm32>`）：

|---|---|---|---|
| `0x40` | ≤ 15354 | `0x026DF8 cmp.l #0x3bfa` + `bls` | `mov.w #0x53` |
| `0x41` | ≤ 450 | `0x026E0A cmp.l #0x1c2` + `bls` | 同上 |
| `0x42` | ≤ 3283 | `0x026E1C cmp.l #0xcd3` + `bls` | 同上 |
| `0xC1` | ≤ 450 | `0x026E2E cmp.l #0x1c2` + `bls` | 同上 |
| `0xB3` | −300…+300 | `0x026E86 cmp.l #0xfffffed4` + `blt`；`0x026E8E cmp.l #0x12c` + `ble` | 同上 |
| `0x91`/`0x92` | 0 或 1 | `0x026E9C mov.l er3,er3` + `beq`；`0x026EA0 cmp.l #1` + `beq` | 同上 |

**校验对象 = `er3` = 32 位大端参数 V1 = `payload[1..4]`**（`payload[1]<<24 | payload[2]<<16 | payload[3]<<8 | payload[4]`）〔R25：模拟器实跑确认〕：

> **打包阶段实测补全（R22 保留部分）**：`0x026DAE` 起是**按子功能号（CDB[2]）分派的校验表**（12 分支、6 个校验值、其中 `0x80`/`0x81`/`0xB0`/`0xD0` **完全不校验**）。这条**不依赖**公式口径，独立成立。证据与复现命令见 `03_analysis/firmware/E0子功能分派与校验表-实测补全.md`。

```
0x026C06  er4 = 0x0040043c        ; CDB 基址
0x026C0C  er5 = 1 ; add.l sp,er5   ; er5 = sp+1 = 13 字节 payload 暂存区
0x026D06  jsr 0x0118D0             ; data-out 相位的 payload 拷入暂存区
0x026D12–0x026D40  er3 = payload[1]<<24 | payload[2]<<16 | payload[3]<<8 | payload[4]
```
⇒ **与执行层写 `0x400408` 的 4 字节同源同序**；**这三个数在 data-out payload 里，不在 CDB 里**（想从实机取到必须抓 data-out）。
**A0 是分辨率动态门限**（`0x026E3E–0x026E7E`）：`V1 ≤ res×10000/4000` 且 `payload[5:8]` 24 位量 ≤ `res×42739/4000`（res = `*0x4007BE`）。
越界统一 `0x53`（与参数块引擎 `0x025A56` 同码 → 跨模块坐实「0x53 = 参数越界」）。
旁路甄别：`0x03EBC0` lo/hi 表（666/333/4000/512）属另一命令（`0x400316` 参数块）；`0x024058`/`0x03E5D8` 是 6 B/条纯命令分派；`0x03E518` 的 mask 是位标志。
`0x43E1`(17377) 与六数值无关：走片物理极限（执行层钳位 `0x02AEFE` + 助手 `0x02AD18`，全镜像仅 3 处）。
`±300` 在执行层另有第二处守卫 `0x02BD18`/`0x02BD28`。

### 3.6 sense 通路：两源一口（推翻「两条独立通路」）`[实证]`

**出货链 fn `0x0116A0`**（主循环 `0x020EBA` 轮询；另一调用点 `0x0114AE`）：

```asm
0x0116A2  mov.w  @0x400436, r6        ; 取原值
0x0116AA  mov.w  r0, @0x400436        ; 读后即清（一次性消费）
0x0116D0  mov.w  #0x0005, r0
0x0116D4  mulxu.w r6, er0             ; 原值 × 5
0x0116D6  mov.b  @(0x1914a,er0), r0l  ; ★ 直接索引 0x01914A，无中间转换表
0x0116C6  mov.w  r6, r1               ; 原值作第二参
0x0116CE  bsr   0x011708              ; 写 sense 缓冲（槽 0x400464 + *0x400503*0x13）
```
`0x011708` 内部同款（`0x011714 mulxu.w e4,er5` + `0x011716 add.l #0x01914A,er5`）⇒ **「索引 = 状态码原值」在 `0x03E390` 之外直接坐实**。

**汇合点 fn `0x021536`**：

```asm
0x02155C  r0 = @0x400402        ; 源 A 的 16 位状态码
0x021562  jsr 0x0211B6          ; 查 0x03E390 → sense_index
0x021566  mov.w r0, @(0xfffe,er6)
0x02157E  r0 = @0x400436        ; 源 B 单元格
0x021584  bne 0x021590          ; 非零 → 不合并
0x021586  r0 = @(0xfffe,er6)
0x02158A  mov.w r0, @0x400436   ; ★ 合并（源 B 优先）
```
⇒ **两个输入源、一个出货口**；`0x400436` 是「统一待刷新 sense 索引」单元格。
字节核验：`sense[0x50]@0x0192DA = 00 05 24 00 00`（INVALID FIELD IN CDB）、`sense[0x56]@0x0192F8 = 06 05 2C 00 00`（COMMAND SEQUENCE ERROR）。
`0x50` 第二写入点 `0x026CC8`（CDB 长度 > 0x0D 拒绝）；`0x400436` 写点值域远宽于 `0x50/0x56`（`0x6F`/`0x7C` 族属传输层，勿与解析层 0x50 族混谈）。
另存在第二条 sense 消费路径 `0x022AFE`/`0x022C00`（把 sense[1..4] 复制进 `0x4007D1` 缓冲）。

### 3.7 图像算法本体：采集配置 · 逐行时序 · 缓冲几何（第六轮）

**逐行时序**（主扫描循环 `0x035E20`–`0x036260`）`[实证]`：

```
分段：段号 r2l；每段行数 @0x4202DD；段内行号 = r2l / 0x4202DD
每行：① jsr 0x02D4CC        打包 12 B 行采集描述符 → ASIC 0x200142
      ② 0x200001 |= 0xC0     启动曝光
      ③ 自旋等 0x200001 bit6  采集完成
      ④ 等 0x4202A4 == 7      走片轴就绪（否则 jsr 0x010B56）
      ⑤ 行计数 += r5，与总行数比较
行末：0x449020++；与 0x449021 相等时把 0x448FEE（行缓冲指针）回填 0x400416；bclr #4,@0xFFFF2E
段末：jsr 0x02A2F6（参数 r1 = 0x09C4 = 2500）走片步进
```

**采集配置层**（ASIC 寄存器组）：`0x200102`=采集模式字节（`0xE2`/`0x62`/`0x22|bit5/6/7`，bit7←`0x4206EC==3`、bit6←`0x41FFA4`）、`0x200181`=0x0D、`0x200182-188` 与 `0x200194-19A`=两组 4×u16 参数、`0x2001C2←0x400D5E`、`0x2001C6←0x400D60-1`、`0x2001C8←0x400D62+0x400DF8-1`、`0x2001C0`=模式位（由 `0x4007C9` 决定）、`0x200142-153`=行描述符；`0x200001`=曝光启动（bit6=完成）、`0x200002`=状态（bit5=缓冲就绪、bit3=忙）、`0xFFFF54` bit2=曝光就绪（`0x02D000` 轮询 20 次）。

**按行参数表**：`0x3F104` 与 `0x3F108` 两张并行字节数组（索引=行号 `0x420264`），按位或后成为描述符 byte0；`0x3F104` 尾部单调递增、步长 15→8→5→4 ⇒ 形状像**逐行曝光/光学补偿曲线** `[推断]`。

**每行算术**：`0x03C194`→`0x03C1AE`×4，以 `er1+4×r5l` 取表项，经 `0x018E68` + 双精度助手 `0x018AA0`/`0x01876A` 换算；第二张表 `0x400F32`。

**缓冲**：ASIC 图像缓冲 `0x8DC000`、采样缓冲 `0xC2D000`、RAM 运行表 `0x420108`（16 B/项）、行缓冲指针 `0x448FEE`→`0x400416`、行号/总行 `0x449020/21`、位置表 `0x4499D8/9E8`、传感器表 `0x41FFD4`（10×0x22 B）。

**仍未落定**：两组参数寄存器的位域含义（曝光/增益/偏置/gamma/位深）、像素从 ASIC 缓冲到 RAM 的搬运路径、`0x018E68` 语义、5 张表的生成者、gamma/位深转换算法本体。详见 `_jobfuncs/image_algo.md`。

## 4. `0x400408` 的真相（一条长期错误结论被推翻）`[实证]`

**旧结论**：「全镜像 3 处写、0 处读，推断为交给引导块消费的请求块」——**两处都错**。

| 类别 | 数量 | 位置 |
|---|---|---|
| 直接写 `mov.w rX,@0x400408` | **4** | `0x026A88`(C1 臂)、`0x026AC6`(A0 臂)、`0x026B48`(B3 臂)、**`0x028D96`**（片夹识别区，此前漏记） |

## 5. 引导块：144 字节的 1394 硬件桥

### 5.1 物理构成 `[实证]`

```
0x00000–0x0016F   92 项 × u32 表（向量表 / 描述表混合，切分待查）
0x00170–0x0020F   代码：复位 0x180（11 条）+ 缝隙 0x192（30 条）+ 共享尾 0x1FC
0x00210–0x0FFFF   数据（含 0x6000–0x7FFF 可写设置区、0x17E = 0x53 flash 命令集选择器）
```
**全部可达代码仅 144 字节**（`0x180`–`0x210`），其余 64 KB 是数据。

### 5.2 表 `0x0000`：92 项，不是纯向量表

| 项 | 值 | 次数 | 判读 |
|---|---|---|---|
| `vec[0]`,`vec[1]` | `0x000180` | 2 | 复位向量 |
| 80 项 | `0x000284` | 80 | 默认桩（未处理中断） |
| `vec[7]` | `0x000280` | 1 | 另一个桩 |
| `vec[8,16,17,19,20,22,48,56,73]` | `0xFFDC00/04/08/10/14/18/1C/20/24` | 9 | **1394 控制器寄存器地址，不是代码**——不能作为中断向量被跳转（切分待查） |
| `vec[92..95]` | `0xFFFFFFFF`×3 + `0xFFFF53FF` | 4 | **已是数据**（`0x180` 处的代码字节） |

### 5.3 复位入口 `0x000180`（11 条）`[实证]`

```asm
0x000180  mov.l #0x00fffb00, sp   ; 栈顶
0x000186  ldc   #0xc0, ccr        ; 关中断
0x00018A  mov.b r0l, @0xffdc3c   ; 1394 控制器 = 0
0x00018E  bt    0x0001fc         ; = BRA（无条件）
0x0001FC  ldc   #0x07, exr
0x000200  mov.b @0x004001, r0l   ; ★ 镜像选择字节
0x000208  bne  0x000210
0x00020C  jmp   0x020600         ; ★ 段2
0x000210  jmp   0x010600         ; ★ 段1
```
**⇒「双镜像回退」的判据是 RAM 字节 `0x4001`**（0 → 段2；非 0 → 段1）。此前只知道两个入口地址，不知道谁选、依据什么。

### 5.4 缝隙函数 `0x000192`（应用↔引导块唯一调用缝）`[实证]`

```asm
0x000192  mov.l #0x00fffb00, sp         ; 每次重设栈顶
0x0001A0  mov.b r0l, @0xffdc3c         ; 1394 控制器模式 = 1
0x0001A4  mov.b @0x40033a, r0l → @0xffdc3d  ; 3 个状态字节
0x0001AE  mov.b @0x40033b, r0l → @0xffdc3e
0x0001B8  mov.b @0x420736, r0l → @0xffdc3f
0x0001C2  mov.l #0x0040033c, er5 ; mov.l #0x00ffdc40, er6 ; r4l=0x08 ; eepmov.b  ; 8 B  CDB
0x0001D4  mov.l #0x00400344, er5 ; mov.l #0x00ffdc48, er6 ; r4l=0xa0 ; eepmov.b  ; 160 B 描述块
0x0001E6  mov.l #0x004003e4, er5 ; mov.l #0x00ffdce8, er6 ; r4l=0x08 ; eepmov.b  ; 8 B  附加块
0x0001F8  bt    0x0001fc                ; → 选镜像段（不返回应用）
```

**⇒ 职责划分**：
- **应用**负责 SCSI 语义：解析收到的 CDB（`0x0114B8` → `0x40043C`）、构造待发的 1394 请求（`0x40033C` CDB / `0x400344` 160 B 描述块 / `0x4003E4` 8 B 附加块）。
- **引导块**只是 1394 硬件桥：`EEPMOV.B` 搬进控制器寄存器区 `0xFFDC40`/`0xFFDC48`/`0xFFDCE8`，写 `0xFFDC3C=1` 发起，然后跳回应用入口。
- `jsr 0x000192` **不返回** ⇒ 应用是「每轮重新初始化」的节拍式结构。

### 5.5 引导块数据侧（第五轮）`[实证]`

```
0x00000–0x0016F   92 项表        0x00170–0x0017D  0xFF（擦除态）
0x0017E           0x53          ★ flash 命令集选择器（擦除区里唯一被编程的字节）
0x00180–0x00213   代码 144 B     0x00214–0x0027F  0xFF
0x00280 / 0x00284  nop; bt 自身  ★ 两个「挂死桩」：未处理异常 = 死循环
0x00288–0x05FFF   0xFF          0x06000–0x0601F  ★ 出厂设置记录 33 B
```
引导块 **99.7% 是擦除态 0xFF**；真内容只有四块（表 / 桥接码 / 选择器 / 记录）。

**记录结构**（= B3 参数块同格式）：`V1(4)=133` + `V2(4)=0` + `5B=0` + `00` + `FFFF` + **模板 17 B = 4 组 (count,value) + 0**：
`(4,0xFC27) (5,0x3AD3) (3,0x4295) (14,0x2356)`，消费点 `0x03109A` 按 u32 字取（业务语义未解）。
读取点：`0x027154`（有效标志 `@0x600D`）、`0x027166/0x027196`（V1/V2）、`0x02692A`（`jsr 0x011900` 从 flash 读 16 B 模板）。

**flash 驱动**（应用 ROM `0x17708` 起 **880 B** → RAM `0x400F5A`）：`@0x17E`=0x53 → 字宽命令集（0xAAAA/0x5554），0x00/0xFF → 字节宽（0xAAA/0x554）；**同址写**（`目标|0xAAAA` 写 0xAA、`目标|0x5554` 写 0x55、擦除 0x80、编程 0xA0+bit7 轮询）；目标 16 位 `0x6000` ↔ 芯片 20 位 `0x60000/0x70000`（×16 换算）。

### 6.1 已验证的 ioctl 协议 `[实证]`

**★ 前序 2340 组扫描全军覆没的真因**：**SCSI 数据出现在「输出缓冲」**（`bytesRet` = 数据长度），不在用户态 DataBuffer —— 之前一直在读错的地方。〔R24〕**机制解释更精确**：该码是 **METHOD_OUT_DIRECT** 语义，`lpOutBuffer` 就是用户缓冲本身、I/O Manager **不做代拷贝**，驱动直接写用户页；且**32 位调用者必须在结构体里传入有效指针**（64 位进程的用户态指针普遍 > 4 GB，不被接受）。**实测现象本身不变。**

**实机结果**：
- `INQUIRY` 标准页 → 36 字节，与已知模板**逐字节一致**：`06 80 02 02 1F 00 00 00` + `Nikon   LS-8000 ED      1.11`
- `REQUEST SENSE` → 18 字节定长格式 `70 00 00 00 00 00 00 0B …` ⇒ **SenseKey=0 / ASC=0 / ASCQ=0（NO SENSE）**，与固件 `0x01914A` 的三元组结构对应
- `INQUIRY` VPD 页 0x80 → `bytesRet=0`（设备不支持 VPD → CHECK CONDITION 路径）
- `MODE SENSE(6)` → `bytesRet=0`

**嫌疑收敛**：probe6 相对之前成功过的调用新增了 **INQUIRY VPD 页 0x80**（设备不支持 → CHECK CONDITION）与 **MODE SENSE ×3**（alloc 252/4/4）；而 probe4 曾成功下发约 768 次字段全错的 INQUIRY **未崩** ⇒ **崩溃在「设备返回非常规响应 → 驱动错误/短数据处理路径」，不在快乐路径**。
`0x2F40CEA` 这类小数值特征与「SRB 字段未初始化 / 陈旧设备扩展指针被当长度或地址使用」一致。
历史同构：10/05 亦为 `0x9F DRIVER_POWER_STATE_FAILURE`（同样是「长间隔无日志」形态）。

**新安全策略（已固化进 `live\ps_readonly.ps1` 的 `$SAFE_ONLY` 护栏）**：默认**只允许 INQUIRY 标准页 0**（实测数百次从未崩溃，且任何 SCSI 设备必须 GOOD 应答）。禁止 VPD 页、MODE SENSE、READ BUFFER（任何 mode）、任何 E0/E1、任何 WRITE BUFFER；**TEST UNIT READY 暂缓**（设备忙时会返回 CHECK CONDITION，同样进入危险路径）。扩大命令集前必须先解析转储定位责任代码路径。

## 8. 方法论与坑（累计）

| # | 内容 |
|---|---|
| M1 | **`h8.lst` 把 `0x4000`/`0x5800` 命名成 `bt`，实为 `BRA`（无条件）**；`bf` = `BRN`（永不跳）。按「T 置位才跳」读会把条件判反 |
