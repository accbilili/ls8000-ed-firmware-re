# E0/CDB 解析 → C1 执行 → 内部作业 → 状态码上报：固件侧全通路

日期：2026-10-24（**第三轮修订：E0/C1 两段式结构、作业表地址更正、六数值坐实、sense 出货口闭合**）
输入 `LS8000_111_ROM.bin`（228,345 B，H8/300H **大端**，地址 = 文件偏移 + `0x10000`）
方法：`h8dis.py` 线性反汇编 + 表转储 + 交叉核对（`hostcode_source.md` / `table_01914A.md` / `_jobfuncs\` 第三轮产物）
分级：`[实证]` 字节/指令可复现；`[推断]` 自洽未直证；`[未证]` 仅线索

> **第三轮更正摘要（必读）**
> 1. **`0x0269A6` 不是「E0 执行层」，而是 C1（EXECUTE）处理函数**；`0x026BF8` 才是 E0 handler。协议为两段式：E0 解析+门限+落存 → C1 触发 12 值开关。依据：分派表 `0x03E2E8` 实测 `[17] op=0xC1 → 0x0269A6`、`[18] op=0xE0 → 0x026BF8`。
> 2. **作业表 `0x40` 项的处理函数是 `0x02AEAA`，不是 `0x2AAAE`**（表项字节 `00 02 AE AA` @`0x03EDF0`）。
> 3. **E0 解析层要求的零位是 `CDB[3..5]`（不是 `[3..6]`）**；`CDB[6..8]` 是 24 位大端分配长度。
> 4. **六个数值（15354/450/3283/450/±300/{0,1}）已全部坐实**，在 `0x026DF8–0x026EA8`；被比较的量是 **V1 = `payload[1..4]`**（32 位 BE），不是 CDB 字节。
> 5. **两条状态通路不是「独立」，而是「两输入源、一个出货口」**：出货口 fn `0x0116A0`。
> 6. **解码器有系统级缺陷**：`h8tab.py` 正则丢 12 位十六进制表项行 → 10 字节指令永不解出。修复版：`_jobfuncs\h8fix.py`（本文件所有反汇编已用修复版重出）。

## 0. 结论摘要

1. **CDB 落 `0x40043C`，E0 的解析在 `0x026BF8`，C1 执行在 `0x0269A6`，作业分派在 `0x02753E`/`0x0275F2`。三段串联，各有一张表（第三轮更正：`0x0269A6` 是 C1 handler）。**
2. **`0xD1` 在两层都被拒**：解析层 `0x03EDB8` 表里没有 `0xD1`（12 条 + `0xFF` 终止），C1 执行开关也没有 `0xD1` 臂。收到 `0xD1` → 状态码 `0x50`。**主机侧 `md3/cdb_sites.md` 证实主机确实会发 `0xD1`，所以这是一个真实的协议缺陷。**
3. **E0 的长度约束不在解析层做 15354/450/3283 这类数值比较，而是 `表内长度 ≤ 主机给的分配长度 ≤ 13`**；那六个数值在同一函数**后段 `0x026DF8–0x026EA8`** 单独校验，**校验对象是 32 位参数 V1 = `payload[1..4]`**（第三轮已坐实，见 §7）。
4. **固件有两层状态上报，但不是「两条独立通路」**：两个输入源（作业码 `0x400402/0x400404`、检查码 `0x400436`）在 `0x400436` 汇合，出货口唯一 = fn `0x0116A0`（第三轮更正，见 §6）。

## 1. CDB 布局与解析层 `0x026BF8` `[实证]`

CDB 缓冲 `0x40043C`：`CDB[0]`@`0x40043C`、`CDB[1]`@`+1`、…、`CDB[9]`@`+9`。

`0x026BF8` 收到的 `er4 = 0x40043C`，逐段校验（每条都给指令地址）：

| 步骤 | 指令 | 判据 |
|---|---|---|
| ① | `0x026C1A mov.b @(1,er4),r0l` / `0x026C1E and.b #0x1f,r0l` / `0x026C20 bne 0x026cdc` | `CDB[1] & 0x1F != 0` → 拒 |
| ② | `0x026C24`–`0x026C3A`（`r3l` 从 3 循环到 5） | **`CDB[3]`–`CDB[5]` 必须全为 0**（第三轮更正：早前写 `[3..6]`，实测循环迭代 3/4/5，`CDB[6]` 是长度高字节） |
| ③ | `0x026C3C mov.b @(9,er4),r0l` / `bne 0x026cdc` | `CDB[9]` 必须为 0 |
| ④ | `0x026C46 mov.l er4,er0` / `0x026C48 inc.l #2,er0` | **payload 起点 = CDB+2**，即 `0x40043E`（=`CDB[2]`） |
| ⑤ | `0x026C56`–`0x026C92` | 以 2 字节步长线性搜 `0x03EDB8`，命中即取 `表[idx+1]` 为期望长度；遇 `0xFF` 终止 → 拒 |
| ⑥ | `0x026C96`–`0x026CB6` | 分配长度 = `CDB[6]<<16 | CDB[7]<<8 | CDB[8]` |
| ⑦ | `0x026CC0 cmp.l er1,er0` / `0x026CC2 bcc 0x026cce` | 分配长度 < 期望长度 → `0x400436 ← 0x50` |
| ⑧ | `0x026CD4 cmp.l #0x0d,er0` / `0x026CDA bls 0x026ce4` | 分配长度 > 13 → `0x400436 ← 0x50` |
| ⑨ | `0x026CE4`–`0x026CF6` | 清 13 字节工作区（`er5 = sp+1`） |

三条拒绝路径都汇到 `0x026CDC mov.w #0x0050,r0` → 写 `0x400436`。

## 3. C1 执行层 `0x0269A6`：12 路开关 `[实证]`

> **第三轮更正**：本节原名「执行层 `0x0269A6`」，实为 **C1（EXECUTE）命令处理函数**（分派表 `0x03E2E8` `[17] op=0xC1 → 0x0269A6`）。E0 走 `0x026BF8`（解析+门限+落存），**两段式**。

入参 `er6 = 0x400C55`（子功能码副本）、`er4 = 0x400436`（状态输出）、`er5 = 0x400410`。逐个 `cmp.b #imm` 后跳。
**入口前置校验（第三轮新增）**：`0x0269C0–0x0269E4` 要求 `mem[0x40043D]&0x1F==0` 且 `mem[0x40043E..0x400441]==0`，否则 `0x400436 ← 0x50`。

| 子功能 | 落点 | 动作 |
|---|---|---|
| `0x40`/`0x41`/`0x42` | `0x026A3E` | 拼 16 位后 **`0x026A50 sub.w r0,r0` 清零** → 写 `0x400410 ← 0x0000`（**不是拼出的值**），且**落穿进 C1 臂体**（`0x026A54` 起）→ 一并写 `0x400408` |
| `0x80` | `0x026A2E` | `0x400D3B ← 1`，转收尾 `0x026BEE` |
| `0x81` / `0xB0` / `0xD0` | `0x026BD2` | 公共成功尾：`0x400400 |= 0x40`、`0x4007C8 = 1`、`0x400438 = 0` |
| `0x91` | `0x026BB2` | `0x400413/0x400414 ← payload[+0xC/+0xD]`；`0x42029E ← payload[+5]` |
| `0x92` | `0x026BBE` | 同上，另写 `0x42029F ← payload[+5]` |
| `0xA0` | `0x026A92` | 读 `payload[1..8]`（不读 `payload[0]`）→ `0x400408 ← payload[1..4]`、`0x40040C ← payload[5..8]`（32 位 BE） |
| `0xB3` | `0x026B0A` | 读全部 13 字节 → `p0→0x400412`、`p1..p4→0x400408`、`p5..p8→0x40040C`、`p9,p10→0x400410/0x400411`（16 位 BE）、`p11→0x400413`、`p12→0x400414` |
| `0xC1` | `0x026A54` | `0x400408 ← payload[1..4]`（32 位 BE） |
| **default** | `0x026BCA` | **`0x400436 ← 0x56`** |

**公共成功尾 `0x026BD2`（第三轮精确化）**：`0x400400 ← 0x4000 \| 子功能码`（**整体覆写**，非 `|=`）→ `0x4007C8 ← 1` → `0x400438 ← 0`。`0x80` 与 default 跳过公共尾直接到 `0x026BEE` 收尾（不更新这三个地址）。
**错误码分层语义（第三轮定名）**：`0x50` 结构错 · `0x53` 数值越界 · `0x56` 执行层 default。

`0x026A2A jmp 0x026bca` 是兜底臂。**`0xD1` 没有自己的臂，会落到 default → `0x56`。**

## 4. 作业层 `0x02753E` → 作业表 `0x03EDE8` `[实证]`

`0x0275F2` 起的消费逻辑：

```asm
0x0275F2  mov.l #0x0003ede8, er4     ; 表基址
0x0275FA  mov.w @er3, r0             ; r0 = 状态字（er3 指向状态寄存器）
0x0275FC  and.w #0x00ff, r0          ; 取低字节 = 刚执行的子功能/命令码
0x027600  mov.b @er4, r1l            ; 记录的键
0x027604  cmp.w r0, r1 ; beq 命中
0x027608  add.l #0x00000006, er4     ; 步长 6 字节
0x02760E  mov.b @er4, r0l ; bne 继续
0x02763C  mov.l @(0x2,er4), er4      ; 取记录 +2 处的 32 位处理函数
0x027642  jsr   er4
```

H8/300H 是**大端**，所以 `mov.l @(0x2,er4)` 读出的是大端 32 位。表实为 6 字节/条 `[u8 键][u8 0][u32 BE 处理函数]`，11 条 + `0x00` 终止：

| 键 | 处理函数 | 键 | 处理函数 |
|---|---|---|---|
| `0x10` | `0x00035598` | `0xB0` | `0x00027F24` |
| **`0x40`** | **`0x0002AEAA`** ← 第三轮更正（原记 `0x0002AAAE`，末两字节错位） | `0xC1` | `0x0002BA24` |
| `0x41` | `0x0002B98A` | `0xD0` | `0x0002866E` |
| `0x42` | `0x0002CB66` | `0x80` | `0x00028722` |
| `0x81` | `0x00028648` | `0xB3` | `0x0002BBAE` |
| `0xA0` | `0x0003A3D4` | `0x00` | `0x00028722`（终止） |

**11 个处理函数第三轮已全部展开到机构动作级**（含三轴台账/ISR/就绪位/步数/状态码），总表见 `_jobfuncs\LS8000-E0总表与修正-20261024.md` §2。其中 `0x40 → 0x02AEAA` 的真实语义＝**走片轴绝对移动**：目标 `*(u16*)(0x400408+2)`，钳位 `cmp.w #0x43E1`(17377)，方向+增量 → `0x02A2F6` 相对步进 → `0x02ACBA` 等待 → 到位存 `0x4202B2`。

`jsr` 之后的收尾（`0x027644`–`0x02766C`）：状态字低字节清零（`and.w #0x3fff`）、`0x400400` 置 bit0、若状态非 0 则结果码 ← `0x3000`，再 `bsr 0x027afa` / `bsr 0x0288f6` / `jsr 0x010b56`，最后 `jmp 0x02753e` 回到作业体自循环。

**注意 `0x91`/`0x92` 不在这张表里**——它们已在执行层内联处理完，不再进作业分派。这张表的键域是「状态字低字节」，不是「子功能码」本身；二者在成功路径上重合（子功能码会被写进状态字低字节），所以看起来像同一张表，实际键空间不同。

## 5. `0xD1` 定案 `[实证]`

三层独立证据，全部指向「固件不认 `0xD1`」：

1. **解析层**：`0x03EDB8` 12 条无 `0xD1`，线性搜到 `0xFF` → `0x026C8E beq 0x026cdc` → `0x400436 ← 0x50`。
2. **执行层**：`0x0269A6` 的 12 个 `cmp.b` 无 `0xD1` 臂 → default `0x026BCA` → `0x400436 ← 0x56`。
3. **作业层**：`0x03EDE8` 11 条无 `0xD1` 键 → 走到 `0x00` 终止记录（处理函数 `0x00028722`，与 `0x80` 共用）。

而主机侧（`md3/cdb_sites.md`）**确实会构造并下发 `0xD1`**：构造点 `0x100AA3BC`（`mov word [esi+0x456], 0xD1`），调度器 `0x100997A9–0x100997C0` 对 `0xD0–0xD6` 整段放行，另有机登记表 `0x100A2654/0x100A2669`。

**结论：主机把一个固件必然拒绝的子功能当作合法命令在发。** 由于主机不做数值校验（`cap_to_cdb.md` §4），这个错配一路上行到总线，只能靠固件在解析层用 `0x50` 挡掉。要么是主机侧照抄了一份过期的 Nikon 私有命令清单，要么 `0xD1` 属于另一台机型（LS-9000？）的能力。

## 6. 两层状态上报：两个输入源、一个出货口 `[实证]`（第三轮更正）

> **第三轮更正**：早前写「两条**彼此独立**的通路」不准确。实测二者在 `0x400436` 汇合，该单元实为「统一待刷新 sense 索引」；出货口唯一。

| | 源 A（结果/作业码） | 源 B（解析层/执行层检查码） |
|---|---|---|
| 载体 | `0x400402`（低字）/ `0x400404`（高字） | `0x400436` |
| 取值 | 16 位：`0x1100`/`0x5000`/`0x9000`/`0x0E10`/`0x0E00`/`0x2000`/`0x3000`/`0x0000` | 小值：`0x50`/`0x53`/`0x56` 等 |
| 到 `0x400436` 的路径 | fn `0x021536`：`0x0211B6` 查 `0x03E390` 得 sense_index → `0x02158A` **仅当 `*0x400436==0` 时**写入 | 直接写 |
| 出货 | **两源共用 fn `0x0116A0`** | 同左 |
| 实证 | `hostcode_source.md` §1、`table_03E390.md` | `_jobfuncs\agent_sense\agent_sense_report.md` |

通路 A 的索引换算已闭环：`0x1100 → field2 142 → rec[142] = 00 02 04 03 07` = **NOT READY / 04 / 07（LOGICAL UNIT NOT READY, INITIALIZING COMMAND REQUIRED）**。

**通路 B 的出货链（第三轮已直证）**——fn `0x0116A0`：

```asm
0x0116A2  mov.w  @0x400436, r6         ; 取原值
0x0116AA  mov.w  r0, @0x400436         ; 读后即清（一次性消费）
0x0116D0  mov.w  #0x0005, r0
0x0116D4  mulxu.w r6, er0              ; 原值 × 5
0x0116D6  mov.b  @(0x1914a,er0), r0l   ; ★ 直接索引 0x01914A，无中间转换表
0x0116C6  mov.w  r6, r1                ; 原值作第二参
0x0116CE  bsr   0x011708               ; 写 sense 缓冲（槽 0x400464 + *0x400503*0x13）
```

`0x011708` 内部同样以原值索引同一张表（`0x011714 mulxu.w e4,er5` + `0x011716 add.l #0x01914A,er5`）。**⇒ 「索引 = 状态码原值」在 `0x03E390` 之外直接坐实。**
字节核验：`sense[0x50]@0x0192DA = 00 05 24 00 00`（INVALID FIELD IN CDB）、`sense[0x56]@0x0192F8 = 06 05 2C 00 00`（COMMAND SEQUENCE ERROR）。
另：`0x50` 有第二写入点 `0x026CC8`（CDB 长度 > 0x0D 拒绝）；`0x400436` 写点值域远宽于 `0x50/0x56`（`0x6F`/`0x7C` 族属传输层，勿与解析层 0x50 族混谈）。

**这条双层结构解释了前序为什么会对不上**：`0x03E390` 的 85 条只覆盖源 A 的 16 位码，把源 B 的小码混进来数，自然得出「48 条/85 条怎么都凑不齐」的结论。

## 7. 「15354 / 450 / 3283」等六个数值：已全部坐实 `[实证]`（第三轮）

**前序「找不到」的原因是反汇编只做到 `0x026CD4`（长度 ≤ 13 检查）就收手**；六个比较在同一函数**后段 `0x026DF8–0x026EA8`**（`cmp.l #imm32,er3`，大端编码 `7A 23 <imm32>`）：

| 子功能 | 约束 | 指令 |
|---|---|---|
| `0x40` | ≤ 15354 | `0x026DF8 cmp.l #0x3bfa` + `0x026DFE bls` |
| `0x41` | ≤ 450 | `0x026E0A cmp.l #0x1c2` + `bls` |
| `0x42` | ≤ 3283 | `0x026E1C cmp.l #0xcd3` + `bls` |
| `0xC1` | ≤ 450 | `0x026E2E cmp.l #0x1c2` + `bls` |
| `0xB3` | −300…+300 | `0x026E86 cmp.l #0xfffffed4` + `blt`；`0x026E8E cmp.l #0x12c` + `ble` |
| `0x91`/`0x92` | 0 或 1 | `0x026E9C mov.l er3,er3` + `0x026E9E beq`；`0x026EA0 cmp.l #1` + `beq` |

越界统一 `mov.w #0x0053,r0` → `0x400436`（与参数块引擎 `0x025A56` 同码，跨模块坐实「`0x53` = 参数越界」）。

**被比较的量是 32 位参数 V1 = `payload[1..4]`，不是 CDB 字节**：

```
0x026C06  mov.l #0x0040043c, er4      ; er4 = CDB 基址
0x026C0C  mov.l #0x00000001, er5
0x026C12  add.l sp, er5               ; er5 = sp+1 = 13 字节 payload 暂存区
0x026D06  jsr 0x0118D0                ; data-out 相位的 payload 拷入暂存区
0x026D12–0x026D40  er3 = payload[1]<<24 | payload[2]<<16 | payload[3]<<8 | payload[4]
```

**⇒ 这三个数在 data-out payload 里，不在 CDB 里**（抓 CDB 字节流看不到它们）。
**⇒ `0x91/0x92` 的 `V1∈{0,1}` 是布尔参数校验**（语义自洽，**不是**死子功能——第二轮曾误判，见 §10.15 of REPORT）。
**⇒ 与执行层同源同序**：C1 臂 `0x026A54`、B3 臂 `0x026B14` 写的 `0x400408` 就是这 4 字节（32 位 BE）。
自洽交叉验证：引导块 stock 记录 `@0x6000` 的 V1 = `0x00000085` = 133，落在 B3 的 [−300,300] 内，目标位 = 133+333 = 466 ✓。
旁路甄别：`0x03EBC0` lo/hi 表（666/333/4000/512）属另一命令（`0x400316` 参数块）的字段校验，**不含**六数值；`0x024058`/`0x03E5D8` 是 6 B/条纯命令分派，**无数值校验**；`0x03E518` 的 mask 是位标志非数值范围。
`±300` 在执行层另有第二处守卫 `0x02BD18`/`0x02BD28`；`0x43E1`(17377) 与六数值无关（走片物理极限，执行层钳位 `0x02AEFE`）。

## 8. 与 G2 的接点

G2（`hostcode_source.md`）从 `0x01750E` 反向追到「host_code 是固件内部状态机用立即数写进 `0x400402`/`0x400404` 的」。本文件正向给出写入者的上半段：**E0 子功能经 `0x0269A6` 执行后，由作业层 `0x0275F2` 按状态字低字节分派到 `0x03EDE8` 的处理函数，再由那些函数把 16 位状态码写进 `0x400402`/`0x400404`。**

两侧在 `0x027642 jsr er4` 这一跳接上。也就是说：**主机可控的只有 CDB 字节与 E0 payload；从「作业函数」往后，主机无法影响状态码的取值。** 这就是 17.1 对接面在固件侧的终点。
