### 2.3 `er3` 与 `0x400408` 的公式：**逐指令模拟实测，与 R22/R23 的表述不一致**

台账在 **2026-10-25 00:27** 新增了 R22/R23（打包阶段），其对 `er3` 与 `0x400408` 公式的表述，与本次逐指令模拟结果**不一致**。为免把存疑结论回灌进前轮文档，这里给出实测过程与结论：

**实测方法**：用项目自带 `dis.py`（h8dis.py + h8.lst）逐条反汇编，再用 H8/300H 精确寄存器语义（`erN` 32 位；`eN`=`erN[31:16]`；`rN`=`erN[15:0]`；`rNh`=`erN[15:8]`；`rNl`=`erN[7:0]`；**M7：`MOV.W Rm, ERn` 写 ERn 高 16 位**）逐指令模拟，代入自造字节样本后与候选公式比对。

**实测结论 1 —— `er3` = BE32(payload[1..4])**（`0x026D10–0x026D40`）
```
0x026D12  mov.b @(0x1,er5), r3l   ; payload[1]
0x026D16  mov.b r3l, r3h          ; r3h = payload[1]
0x026D18  sub.b r3l, r3l          ; r3l = 0
0x026D1A  mov.w r3, e3            ; er3[31:16] = payload[1]<<8
0x026D20  mov.b @(0x2,er5), r0l   ; payload[2]
0x026D24  mov.w r0, e0            ; er0[31:16] = payload[2]
0x026D28  add.l er0, er3
0x026D2C  mov.b @(0x3,er5), r0l   ; payload[3]
0x026D30-36 shll.l #2, er0 ×4     ; er0 = payload[3]<<8
0x026D38  add.l er0, er3
0x026D3C  mov.b @(0x4,er5), r0l   ; payload[4]
0x026D40  add.l er0, er3
```
模拟样例 `payload[1..4] = 12 34 56 78` → `er3 = 0x12345678` = **BE32(payload[1..4])**，与 R6 原始表述一致。
紧接着 `0x026D42–0x026D74` 用**同构手法**把 `payload[5..8]` 装配成第二个累加器，存入 `@(0xe,sp)`（模拟得 `0x9ABCDEF0` = BE32(payload[5..8])）—— **两者是两个独立累加器，不是同一个 er3**。

**实测结论 2 —— `0x400408` = BE32(payload[2..5])**（三个臂同构）
- C1 臂 `0x026A54–0x026A86`、A0 臂 `0x026A92–0x026AC4`、B3 臂 `0x026B14–0x026B46` 三条链**指令形态完全相同**：`mov.b @(0x2,er6),r0l` → `mov.b r0l,r0h` → `sub.b r0l,r0l` → `mov.w r0,e0` → … 模拟得 `0x400408 = 0x12345678` = **BE32(payload[2..5])**，**P1（payload[1]）确实不参与**（此点与 R23 一致）。
- 但 R23 给出的公式 `(P2<<8)+(P3<<8)+(P4<<16)+P5` **与模拟不符**（同样字节代入得 `0x00564678`，≠ 实测 `0x12345678`）；正确的位分布是 `P2<<24 | P3<<16 | P4<<8 | P5`。
- B3 臂 `0x026B0A–0x026B0E` 另将 `payload[1]` 单独写入 `0x400412`（此点与 R23 一致）。

**与现有 R 编号的关系（请 lead 裁决，本文件不单方面改判）**：
- 前轮 MASTER.md §B:84 与 Mechanism-Focus.md §2:33 的措辞「**er3 = CDB[6..8] 组成的 24-bit 值**」**两种口径下都错**：CDB[6..8] 是 24 位**分配长度**（R7），`er3` 是 payload 派生的 32 位量（R6/R22）。故前轮这两处无论按哪一版口径都需改写 —— 但改写目标文本需等 R22/R23 与 R6 的口径统一后确定。
- **本次实测更接近 R6 原始表述**（「er3 = payload[1..4]，32 位 BE」），而 R22 表述为「payload[1..8] 经重排+相加」。二者不能同时成立。**建议 lead 复核 `E0子功能分派与校验表-实测补全.md` §1 的公式推导**：该文的指令清单与本次反汇编逐条一致，但随后的「精确公式」与位段展开表似未应用 M7（`mov.w` 写高 16 位）。
- **本索引不把任何一版公式当作定论**，凡涉及处一律标「待核」。

### 2.4 `er3` 之外的量纲归属（涉及 4 份）

- `CDB[6..8]` = 24 位**分配长度**（`0x026C96–0x026CB4`，与表 `0x03EDB8` 的期望长度比较，见 `0x026CC0`），**不是**被数值门限比较的量。
- `CDB[3..5]` 须为 0（`0x026C28–0x026C3A` 循环迭代 3/4/5）；`CDB[6..8]` 是分配长度 —— R7 口径，前轮 PhaseM-O_v6.md 已对。
- 六个数值本身在 `0x026DF8–0x026EA8` 全部坐实、越界 → `0x53`；其中 `0x80`/`0x81`/`0xB0`/`0xD0` 四个子功能**完全不校验**（直接落 `0x026EB6` 放行）。

### 2.5 片夹类型码与名字表的口径（涉及 9 份）

- **`0x400C55` = E0 子功能码**（源：E0 的 CDB[2]），**不是**片夹类型码；
- **片夹识别类型码落 `0x4003FB`**（值域 `0x10–0x1F` + `0x81`，初值 `0x10`）；
- **`0x400D79` = 「识别正常」标志**（仅 0/1），失败路径置 `0x4003FB=0x10` + `0x400D79=0`，**不重试**；
- 名字表 `0x3EAD4`：固件原文是 **Brownie Mount Film / Brownie Strip Film / Brownie Strip Film with G**（返回码 `0x16/0x17/0x18`），`FH-` 前缀属主机侧推断，**不是固件证据**；
- **GR 走片量 = 5479 采样**（`22.3`×`157.4803149606` 截断得 **3511**，再 `+0x07B0`=1968），前轮写的 5480 差 1。

### 2.6 解码器口径（涉及 5 份）

凡引用「622 函数 / 27,215 指令 / 0 越界调用 / 覆盖完整」，必须同时标注：**该收敛建立在有缺陷的解码器上**（`h8tab.py` 正则 `[0-9a-f]{2,8}` 整行丢弃 12 位十六进制的 6 字节模式表项 → `mov.l @(d:32,ERn),ERm` 等 10 字节指令永不解出）。实测损伤：**42 条未解出、波及 36/529 函数、零错位**；复走后**多解出 1299 条**（36 个函数合计）——洞点虽只有 42 个，但 10 字节指令解开后**其后的整段代码才显形**。新解出的正是扫描位 / AF / 行缓冲实算部分。
