# `0x02753E` / `0x02759E` 校准链路 —— 分块语义、错误码谱系、调用时序

> 任务 ID `F3`。输入：`firmware\calib_2753E.asm.txt`（约 58 KB，线性反汇编）、`BRIEF.md`、
> `REPORT_L3-交接定稿.md` §9.7 / 第 11、12 章。
> 样本：`D:\DS\TEST\LS8000\LS8000_111_ROM.bin`（228,345 B，`addr = file offset + 0x10000`）。
> 分级：`[实证]` 可复现的字节/反汇编/表证据；`[推断]` 逻辑自洽未直接验证；`[未证]` 仅线索。

## 0. 结论先行

1. `0x02753E` 不是函数，是**任务体内部的循环头**：全镜像只有 `0x027670` 一处 `jmp 0x02753E`，
   另有 `0x027538` 顺序落入。**无任何 `bsr`/`jsr` 调用它** `[实证]`（CFG 全量边扫描）。
2. 整段是**一台四级闸门的状态汇报机**：`0x02753E` 每轮先把本轮机械/识别结果算出来（调 `0x027676`），
   再用 `0x400D72` / `0x400D79` / `0x4003FB` 三个变量把结果翻译成 `0x400404` 的**结果码**。
3. `0x1100` 与 `0` 的唯一区别就是 **`0x4003FB` 这一个字节是否等于 `0x10`**；
   两者的控制流完全相同（都汇到 `0x0275B8`），差别只在 `0x400404` 的值 `[实证]`。
4. 结果码全集是 **8 个**：`0x0000` / `0x1100` / `0x2000` / `0x3000` / `0x5000` / `0x9000` / `0x0E00` / `0x0E10`；
   另有一个**易混的兄弟寄存器** `0x400402`（状态码，本段触及 7 个值），前序文档把两者混提过。
5. 校准顺序：**待命位 → 1.2 s 稳定 → 原位回零两遍 → 500 ms 稳定 → 定位 0x07FF → 前端脉冲 →
   （条件满足才做）第二轴参考位 + 清参考表 + 采集 + 回位**。没有独立的"聚焦归位"步骤。

## 1. 证据基线（先纠三个会影响结论的读法）

### 1.1 `bt` 就是 `BRA`（无条件），不是"T 置位才跳" `[实证]`

`h8tab.py`/`h8.lst` 把 `0x4000` 命名为 `bt rel8`、`0x5800` 命名为 `bt rel16`（`h8.lst:1419`、`h8.lst:1607`），
但从条件码排布和实测字节看，`0x40` = `BRA d:8`、`0x58 0x00` = `BRA d:16`：

| 位置 | 实测字节 | 按 `addr+size+disp` 算目标 | 结论 |
|---|---|---|---|
| `0x02758A` | `40 2C` | `0x02758A+2+0x2C = 0x0275B8` | 跳到 `0x0275B8`，与清单一致 |
| `0x02759C` | `40 14` | `0x02759C+2+0x14 = 0x0275B2`（再 `40 04` → `0x0275B8`） | 同上，两跳 |
| `0x0275B2` | `40 04` | `0x0275B2+2+4 = 0x0275B8` | 同上 |
| `0x0275AC` | `40 02` | `0x0275AC+2+2 = 0x0275B0` | 同上 |

并且 `h8.lst` 里 `0x58n0`（n=0..F）依次是 `bt/bf/bhi/bls/bcc/bcs/bne/beq/bvc/bvs/bpl/bmi/bge/blt/bgt/ble`
—— `n=0` 落在条件码表的 `BRA` 槽位、`n=1` 落在 `BRN` 槽位。所以清单里**每个 `bt` 都是无条件跳转**。

**这条修正了输入文件头注释里的"stale-T 伪影"说法**：不是解码伪影，是助记符命名错了。
后果：`0x0275B2 bra 0x0275B8` 使 `0x0275B4 jsr 0x03C31E` **不是** `0x1100`/`0` 两条路的公共尾，
它只由 `0x02755C` 的 `bne` 进入（见 §4）。这一条若按"T 置位才跳"读，会把 `0x1100` 的判据读反。

### 1.2 CFG 覆盖缺口正好落在任务体前段 `[实证]`

`cfg_v4.json`（622 函数 / 27,215 指令）里 `0x02740A..0x0274B8` **一条指令都没有**，
函数起点从 `0x0274BC` 才开始（`0x0274BC / 0x02753E / 0x027676 / 0x0277CE / 0x027930 / 0x027A54 / 0x027AFA`）。
这不是漏扫，而是**该段没有静态入边**——它只能由任务表装载（§7.1）。
所以前段（A0）的结论只能靠线性反汇编 `[实证-线性]`，标注时我会单独说明。

### 1.3 `0x03E390` 是 85 条，不是 48 条 `[实证]`

本次直接按 `0x03E390 + i*4` 读原镜像：`[0]..[84]` 有效（`[84] = 0x03E4E0: 11 00 00 8E`），
`[85] = 0x03E4E4: 00 00 00 00` 为终止项。BRIEF 与 §8.4 写的"48 条"是早期抽样口径的残留，
**与字节事实冲突，以 85 条为准**（终止项地址 `0x03E4E4` 也与输入文件末尾注释一致）。

各块要点：

- **A0**：`0x027424` 读 `0x4207F8`（校准已启动标志）为 `1` 则直接跳到 `0x0274B0`（`bsr 0x0283DC`）。
  `0x027430` 判 `0x400402 == 0x0010`（= 从上电初始态第一次进来），是则 `0x400404 = 0x2000`、
  `0x027A54(2)`、`0x010B56` 等就绪。`0x02744E` 起按 `0x4206EC` / `0x420245` 分两条初始化路径，
  两条都会 `bsr 0x027B1E`（E2 全参数复位）。尾段 `0x0274B4` 把 `0x400406` 的 bit0 置 1。
- **A1**：`0x4206EC != 0` 时向 `0x200042` 写 `0xFF`（ASIC 侧一个"暂停/复位"字节）并跳过后续；
  否则若 `0x400404 == 0x2000` 且 `0x400402 ∈ {0x0110,0x0120,0x0121}`（或 `0x40041C == 1`）
  就清 `0xFFFF2E.bit1` 并等就绪。收尾把 `0x4202A2→0x4202B2`、`0x4202EC→0x4202FC`（**记下当前位置作为回位点**）。
- **B0**：见 §4，四级闸门。
- **B1**：`0x400400.bit6` 为 0 就整块跳过（`0x0275BC → 0x027668`）。为 1 时先 `0x027A54(1)`、
  `0x400402 = 0`，然后按 `0x400406 & 0xFF` 在表 `0x03EDE8`（记录 6 B：`[u8 code][pad][u32 handler]`）里线性找，
  命中就 `jsr @handler`；`0x400402` 非 0 则 `0x400404 = 0x3000`。
- **C0**：`0x027688` `bset #3,@0xFFFF2E`（屏蔽某中断），按 `0x400D72` 是否为 `5` 分两条；细节见 §6。
- **D0**：`0x420300` 四态机；`0x420301`（word `0x420300` 的低字节）是另一个 bit 标志字节，由 `0x029D2A` 写 `bit6` `[实证]`。
- **E0**：`0x4003FB → 0x4003FC` 同步比较（`0x0279BC`–`0x0279D0`），变了就 `bset #4,@0x400406`；
  末尾把 `0x4003FB = 0x10`、`0x400D72 = 0x05`、`0x400404 = 0x9000`。
- **E1**：`0x027A54(k)` 是**唯一**的超时武装/撤防入口：
  `k=0` 撤防（`bset #0,@0xFFFF6F`）；`k=1` 时限 `0x313`(787)；`k=2` 时限 `0x64`(100)；
  `k=3` 时限 `0x64` 且额外把 `0x4206D2/0x4206D6 = 0xFA0`(4000) `[实证]`。
  计时基准是 32 位 tick `0x4003F6`（递减/递增方向未证，见 §8）。

## 3. 错误码谱系（本文最高价值项）

### 3.0 先分清两个"码寄存器"

前序文档出现过 `0x1100` 与 `0x0110` 混提。**这是两个不同寄存器上的两套码**：

| 寄存器 | 宽度 | 语义 | 消费者 |
|---|---|---|---|
| `0x400404` | word | **结果码**（本轮做完了什么/错在哪） | `0x0211B6` → 索引 → `0x400436`（TUR） |
| `0x400402` | word | **状态码/当前子操作**（idle `0x0010`、`0x0110`、`0x0810`、`0x0F20` …） | 同上，另一条查表路 |

`0x400404` 由 `er5` 指向（A0 装载），`0x400402` 在 A0 里以绝对地址比较。二者都进 `0x03E390` 查表，
所以**同一个查表函数吃两种码**，这正是历史混淆的来源 `[实证]`。

### 3.1 `0x400404` 结果码全集（本段 8 个）

| 码 | 写点 | 触发条件 | 阶段 | B0 是否放行 | 表映射 | 5 字节记录（`0x01914A+i*5`） |
|---|---|---|---|---|---|---|
| `0x0000` | `0x027B34`（E2）、`0x0275B0`（B0b） | E2 复位；或 §4 第 4 级判 `0x4003FB != 0x10` | E2/B0 | 不参与闸门比较 | **查表未命中 → 0** | `00 00 00 00 00`（全零 = 无 sense） |
| `0x1100` | `0x0275A8` | `0x400D72==1` ∧ `0x400D79==1` ∧ `0x4003FB==0x10` | B0b | — | idx **142** | `00 02 04 03 07` |
| `0x2000` | `0x027440`（A0）、`0x0285EC`（识别） | A0 首次进入（`0x400402==0x0010`）；识别路径（`0x400406&0xFF==0x80`） | A0 / `0x02842C` | **放行** | idx **10** | `02 02 04 02 00` |

读法（`[推断]`，依据链：`0x0211B6` 查 `0x03E390` → 取 `idx` → `0x01914A+idx*5` 取 5 字节；
字节 1..4 与宿主侧 sense 拼装格式 `key<<24|ASC<<16|ASCQ<<8`（§13.6）同序）：

- 5 字节记录 = `[flags][SK][ASC][ASCQ][Nikon 子码]`；`flags.bit1` = "有 sense 可发"，`flags.bit7` = "抑制"
  （判据来自 `0x0174BC` 的 `0x01753C`–`0x01754A`）。
- `0x0E10/0x5000/0x1100` 三条记录的 `flags = 0x00`，**不会**走 `0x0174BC` 的主动 sense 通路；
  它们只经 TUR（`0x02159C` → `0x0211B6` → `0x400436`）被主机看到。这三条 SK/ASC/ASCQ = `02/04/03`
  （NOT READY + "manual intervention required"），只有末字节 `05/06/07` 不同 —— 即**同一类"未就绪"的三个阶段**。
- `0x9000` 的记录 `02 3A 00` = NOT READY + ASC `0x3A`（MEDIUM NOT PRESENT）`[推断]`。
- `0x2000` / `0x3000` 记录相同 `02 04 02` = "not ready, initializing command required" `[推断]`。

## 4. `0x1100` 的穷举条件

### 4.1 到达 `0x02759E` 的全部前置（四级闸门，缺一不可）

| # | 地址 | 指令 | 条件 | 不满足的去向 |
|---|---|---|---|---|
| 0 | `0x027556` | `mov.b @0x4206EC` / `bne` | `0x4206EC == 0` | `0x0275B4 jsr 0x03C31E`（另一台状态机接管，**本轮不判任何码**）→ `0x0275B8` |
| 1 | `0x02755E` | `bsr 0x027676` | 先跑完 C0（含 D0 与 F0） | — |
| 2 | `0x027562`/`0x02756A`/`0x027572` | `cmp.w` + `beq` | `0x400404 ∉ {0x0E10, 0x3000, 0x2000}` | 三者任一相等 → `0x0275B8`（**放行，不覆盖**） |
| 3 | `0x02757A`/`0x027580` | `mov.b @0x400D72` / `cmp.b #0x01` / `beq` | `0x400D72 == 0x01` | `0x400404 = 0x9000`（`0x027584`–`0x02758A`）→ `0x0275B8` |
| 4 | `0x02758C`/`0x027592` | `mov.b @0x400D79` / `cmp.b #0x01` / `beq` | `0x400D79 == 0x01` | `0x400404 = 0x5000`（`0x027596`–`0x02759C`）→ `0x0275B8` |
| 5 | `0x02759E`/`0x0275A4` | `mov.b @0x4003FB` / `cmp.b #0x10` / `bne` | — | 见下 |

### 4.2 `0x02759E` 内部的完整分支（就 6 条指令）

```asm
02759E  mov.b  @0x4003FB, r0l     ; 取一个字节
0275A4  cmp.b  #0x10, r0l         ; 与 0x10 比（字节比较，无掩码）
0275A6  bne    0x0275AE           ; 不等 → 走 0 分支
0275A8  mov.w  #0x1100, r0        ; 相等 → r0 = 0x1100
0275AC  bra    0x0275B0           ; 跳过下面的清零
0275AE  sub.w  r0, r0             ; r0 = 0x0000
0275B0  mov.w  r0, @er5           ; 0x400404 = r0
0275B2  bra    0x0275B8           ; 两条路在此汇合
```

**穷举结论** `[实证]`：

```
报告 0x1100  ⟺  0x4206EC == 0
              ∧  0x400404 ∉ {0x0E10, 0x3000, 0x2000}      (进入本闸门时的值)
              ∧  0x400D72 == 0x01
              ∧  0x400D79 == 0x01
              ∧  0x4003FB == 0x10                          (即 16)

报告 0x0000  ⟺  同上四条成立，但 0x4003FB != 0x10        (即 256-1 = 255 个取值)
```

- 比较是 `cmp.b`（字节、立即数），**没有掩码、没有范围判断** —— 不存在"高位被忽略"的情况。
- 两条路的控制流**完全一致**（都到 `0x0275B8`），`0x0275B4` 不在这条路上（§1.1）。
  所以 `0x1100` 与 `0` 的**唯一**可观测差别就是 `0x400404` 的值。
- `0x4003FB` 在本函数视角下只有"是不是 `0x10`"这一个判据。**它的名字/编码含义不在本文范围**（B5 任务）。
  只给两条旁证、不下结论：
  - 全镜像 32 处对 `0x4003FB` 的绝对地址操作里，**常量写点 5 处全部写 `0x10`**
    （`0x027B53`、`0x027E23`、`0x027EA3`、`0x027EB7`、`0x0285A1`，都是 `mov.b #0x10` 后紧跟 store）；
  - 非常量写点在 `0x0289B4` 内（`er6 = 0x4003FB`，`0x028BB4` / `0x028C02` 写识别返回码，
    例如 `0x80`/`0x81`），即**该字节确实会变成非 `0x10`**，`0` 分支不是死代码。

## 5. 与 §9.7 的一处冲突（如实列出）

§9.7 表格写：`0x02758C` 是门禁，"**若仍为 1，报状态 `0x5000`**"。

反汇编事实（`0x02758C`–`0x02759A`）：`beq 0x02759E` 在 `0x400D79 == 1` 时**跳过**写 `0x5000`，
所以 `0x5000` 只在 `0x400D79 != 1` 时出现。**结论方向相反。**

判定依据：`0x027592 cmp.b #0x01` + `0x027594 beq` 的语义无歧义；且 `0x400D79 == 1`
是 `0x027E30`（进片开始）与 `0x028B84`（识别开始前）预置的"待识别"值，
`0x028C02`/`0x028C0A` 在其后写识别码或 0 —— 也就是说 `== 1` 恰好是"还没识别完"，`!= 1` 才是"识别已有结果"。
按此，三个码是一条**递进的未就绪阶梯**：

| 阶段 | `0x400D72` | `0x400D79` | `0x4003FB` | 结果码 | 记录末字节 |
|---|---|---|---|---|---|
| 进片中 | `0x05` | `0x01` | `0x10` | `0x9000` | `01`（ASC 3A） |
| 进片完、待识别 | `0x01` | `0x01` | `0x10` | `0x1100` | `07` |
| 识别码已落 | `0x01` | `0x01` | `!= 0x10` | `0x0000` | 无 sense |
| 类型码落定 | `0x01` | `!= 0x01` | 任意 | `0x5000` | `06` |

`[推断]`：`0x1100` 对应"片子已装好但识别结果还没出来"，`0x5000` 对应"类型码已确定、等主机下一步"。
反证条件：若实机在"已装片夹且已识别"状态下持续报 `0x1100` 而非 `0x5000`，则本表需改。

## 6. 校准顺序：进片完成 → 可扫描

### 6.1 总时序（同任务串行，一轮 = `0x02753E` 到 `0x027670`）

```
[C0 内] F0 0x027DC4 进片：0x4202EC += 0x55 逐格推进
        └→ 预置 0x400D72=5, 0x400D79=1, 0x4003FB=0x10, 0x400D78=1, 0x40041A=0
[本任务] B0 0x02753E ──→ C0 0x027676 ──→ D0 0x0277CE（机械：归零/定位）
                                    └──→ F0 0x027DC4（若还需进片，mode 0/1/2）
                                    └──→ E0 0x027930（若 0x4202FE==1，中止/卸载）
        └→ 状态闸门：0x9000 / 0x5000 / 0x1100 / 0
        └→ B1 0x0275B8 命令表 0x03EDE8 回调（真正开始扫描的是这里）
```

### 6.2 D0 的机械序列（`0x420300` 四态），逐步判据与超时

| 步 | 地址 | 动作 | 判据（等哪个地址的哪一位） | 超时 |
|---|---|---|---|---|
| S1 | `0x0277EC`–`0x027806` | 机构状态预检 | 依次调 `0x02CFA0`/`0x02CF60`/`0x02CFE0`，三者都是"轮询到该位被清就返回 1"；**任一返回 1（即 `0xFFFF55` 的 bit5/bit2/bit4 之中有被清掉的）→ `r4h=1`**（`0x027808`），随后状态机复位重来 | 每项 20 次轮询（`cmp.w #0x0014`），无时钟超时 |
| | | | 反向理解：三位的"正常"态是**保持置位**（轮询超时才返回 0） | |
| S2 | `0x02780E`–`0x02781C` | 状态 0 → 3 | `r4h==0` ∧ `0x02D000()==0`（`0xFFFF54.bit2` **清**） | — |
| S3 | `0x027840`–`0x027858` | 稳定期 1 | `0x4003F6 − 0x420302 ≥ 0x4B0`(1200 tick) | 1200 tick |
| S4 | `0x02785A`–`0x027872` | **原位回零（第 1 遍）** | 目标 `0x440E40 = 0`，轮询 `0x4202A2 == 0` | `0x02ADCE` 的 `er1 = 0x186A0`；同时 `0x027A54(1)` 武装 787 tick 硬件看门狗 |
| S5 | `0x027876`–`0x027890` | `0x4202A2` 预置 `0x07FF`，再走一次目标 0 | 轮询 `0x4202A2 == 0` | 同上 |
| S6 | `0x027892`–`0x02789C` | 状态 3 → 4 | `0x02D000()==1`（`0xFFFF54.bit2` **置位**） | 20 次轮询 |
| S7 | `0x0278A2`–`0x0278B2` | 状态 4 → 5 | `0x02D000()==1` | 20 次轮询 |
| S8 | `0x0278D2`–`0x0278EA` | 稳定期 2 | `0x4003F6 − 0x420302 ≥ 0x1F4`(500 tick) | 500 tick |
| S9 | `0x0278EC`–`0x02790A` | 定位到工作位 | `0x4202A2 = 0` → 目标 `0x07FF` → 轮询 `0x4202A2 == 0x07FF` | `0x186A0` |
| S10 | `0x027912` → `0x02B038` | 前端脉冲/定时块 | 先把 `0x03F0E8` 一个字节搬到 `0x440846`（`0x02B062`），再 `0x02CF40()`（`0xFFFF55.bit3`，20 次）：**若该位已被清则整段跳过**；否则发 `0x02A2F6(0, 0x2710, 0x4517)` + `0x02AFA4()` | `0x02CF40` 20 次；`0x02AFA4` 内等 `0x44080E` 走到 2，走不到则 `0x400402 = 0x0110`（`0x02AFE4`） |
| S11 | `0x027916`–`0x027924` | 状态 5 → 0（完成） | 正常则 `0x420300 = 0`；`0x02D000()!=1` 则退回状态 4（`0x027922`） | — |

要点（`[实证]`）：**"原位回零"确实存在，而且是两遍**（S4/S5），并且两次都是
"**先写位置计数器、再走到另一端**"的对称手法：S4 走到 0 →S5 把 `0x4202A2` 预置 `0x07FF` 再回 0；
S9 反过来把 `0x4202A2` 预置 0 再走到 `0x07FF`。这是**建立绝对基准**（写计数 → 单向走满 → 计数可信）的做法，
不是简单的"回零" `[推断]`。异常（`r4h=1`）时状态机不报错，而是 `0x02789E` 把 `0x420300` 清 0
**从头再来**——这就是"卡在校准"现场看不到任何错误码的原因 `[实证]`。

### 6.3 参考采集（条件触发）

只有 `0x42029F == 1` ∧ `0x4207F8 == 1` 时，F0 尾部 `0x027F0C` 才 `bsr 0x027F24` `[实证]`：

1. `0x02B87C(0x00E2)` —— 把第二轴（当前位置 `0x4202E0`）开到 `0x00E2`；该函数在
   `0x400402 ∈ {0x0120,0x0121}` 或已到位时立即返回（`0x02B882`–`0x02B8A2`）。
2. `0x02896C` —— 清 `10 × 0x22` 字节的参考表（`0x41FFD4 + i*0x22` 每条第 0 字节，`0x028970`–`0x028986`）。
3. `0x027F44` —— 置 `0x4007C9 = 1`，然后 **`0x4007CA = 0/1/2/3/4` 五段**依次 `bsr 0x028148`
   （`0x027F5E`–`0x027F8A`）；`0x028148` 内部是"仅当 `0x400402 == 0` 才执行"的五个 ASIC 前端配置调用
   （`0x030262`/`0x030F8E`/`0x034782`/`0x032700`/`0x032914`，`0x028152`–`0x028186`）；
   之后进入 `0x008CC000` 缓冲、`0x4207FE` 的采集循环（`0x027F8E`–`0x027F9A`）。
4. `0x02B87C(原值)` —— 第二轴回原位。

`[推断]` 这一段就是"白/黑参考（shading）采集"：**移动到位 → 清旧参考 → 分段配前端 → 采集 → 回位**。
**反证条件**：若 `0x027F44` 之后实际读的是图像缓冲而非参考缓冲（需继续反汇编 `0x027F9A` 以后），则改为"扫描前预扫"。

### 6.4 这一步里**没有**的东西（避免过度解读）

- **没有独立的"聚焦归位"**：第二轴 `0x4202E0` 只在 §6.3 第 1/4 步被开到 `0x00E2` 再回原位，
  D0 四态机完全不碰 `0x4202E0`。`[推断]` 该轴是对焦/变焦轴，但"回零"动作不存在于此链路。
- **没有黑电平/白电平的数值校准**出现在 `0x02753E`–`0x027930` 区间内；
  该区间只做机构与状态，数值类配置全在 `0x027F44` 之后与 `0x0289B4` 内。

## 7. 接口关系

### 7.1 本段入口由谁调用：**没人"调用"，它是 2 号任务的函数体** `[实证]`

任务表（`0x010920` 与 `0x010934` 两个变体，记录 10 B = `{u32 栈顶, u32 入口, u16 标志}`）：

| 变体 | 记录 | 栈顶 | 入口 | 标志 | 选择条件 |
|---|---|---|---|---|---|
| A @`0x010920` | #0 | `0x00480000` | `0x00020A5A` | `0x0000` | `0x4003FA == 0`（`0x010948`–`0x010952`） |
| A @`0x01092A` | #1 | `0x00470000` | **`0x0002740A`** | `0x0000` | 同上 |
| B @`0x010934` | #0 | `0x00480000` | `0x00010F5C` | `0x0000` | `0x4003FA != 0` |
| B @`0x01093E` | #1 | `0x00470000` | **`0x0002740A`** | `0x0000` | 同上 |

- 装载者：`0x010946` 起的循环（`r2 = 2`，`0x010968`；`mov.l @er0+,er3/er4` + `mov.w @er0+,r4` 逐字段取，
  再压 `er4/er3` 到该任务栈构帧），装完 `0x4003EC = 0`（`0x0109A6`）。
- 因此 `0x02740A` 的入口不来自任何 `bsr`/`jsr`，而是**任务切换时 PC 被装成 `0x0002740A`**。
  这也解释了 §1.2 的 CFG 缺口。
- `0x02753E` 的入边：仅 `0x027670 jmp` 与 `0x027538` 顺序落入 `[实证]`（CFG 全量边，含 `cond/jmp/call`）。
- `0x02759E` 的入边：仅 `0x027594 beq` 一条 `[实证]`。
- `0x027676`（C0）：仅 `0x02755E`。
- `0x0277CE`（D0）：仅 `0x02769A`。`0x027930`（E0）：仅 `0x0276FA`。
- `0x027DC4`（F0）：`0x0276EE`、`0x02774A`、`0x02776E` 三处，**全部在 C0 内**。

### 7.2 相对 `0x027DC4` 的调用时机：**之前，同一轮，严格串行**

- 一轮循环的顺序是 `0x02753E`（闸门）→ `0x02755E bsr 0x027676`（C0）→ C0 内部 `bsr 0x027DC4`
  → 回到 B0 继续 `0x027562` 起的状态判定。
- 所以 `0x027DC4` **先执行**，它写下的 `0x400404`（`0x0E00`/`0x0E10`/`0x9000`）
  正是紧接着被闸门读到并可能覆盖的那个值。二者**无并发、无中断级并行**：同一任务、同一栈。
- 与"另一台状态机" `0x03C31E` 是**互斥**的：`0x4206EC != 0` 时 B0 在 `0x02755C` 直接 `jsr 0x03C31E`
  并跳过 C0；`0x4206EC == 0` 时才走 C0，此时 `0x03C31E` 不介入。`0x03C31E` 自己会 `0x400D72 = 1`（`0x03C340`），
  这也是"进片结束（`0x400D72` 由 5 回到 1）"的实现处。
- 循环节拍由 `0x010B56`（设备就绪等待，内部 `trapa #0`）控制，**没有 sleep/定时器**；
  需要"等 N 毫秒"的地方一律用 tick 比较（`0x4003F6` 差值 vs `0x4B0`/`0x1F4`）。

## 8. 未解决的疑问（≤5）

1. **`0x4003F6` 的时基方向与单位**：D0 用 `0x4003F6 − 0x420302 ≥ 0x4B0` 判 1.2 s，
   意味着它的单位约 1 ms 且**单调递增**。但写 `0x4003F6` 的只有 `0x010BE8`（清 0），
   递增方（应为定时器 ISR）在引导块内，静态不可达（§14.1 A2）。若它实际是递减计数器，
   则 S3/S8 的比较方向要反过来（差值仍为正，故不改变"等够时长"的结论，只改变边界）。
2. **`0x027A54(k)` 的时限单位**：`0x313`/`0x64`/`0xFA0` 分别疑似 787/100/4000 tick，
   但 `0x4206CA`（截止）与 `0x4206CE`（时限）谁减谁、谁触发 `0xFFFF6F.bit0` 中断，未证。
3. **`0x0289B4` 的入口分支**：本文只用到"它会写非 `0x10` 值"这一点。它内部另有两个写点
   （`0x0285DE` 写 `0x400402 = 0x0F20`、`0x0285EC` 写 `0x400404 = 0x2000`），条件是
   `0x400406 & 0xFF == 0x80`（`0x0285D8`）；但谁把 `0x400406` 的 `0x80` 位设起来没有追到，
   所以"识别完成 → `0x2000`"这条链还差最上面一环。
4. **`0x027F44` 之后（`0x027F9A` 起）的采集循环**未反汇编完，故 §6.3 的"白/黑参考"仍是 `[推断]`。
   下一步：从 `0x027F9A` 线性反汇编到该函数 `rts`，看是否读 `0x008CC000` 并写 `0x41FFD4` 参考表。
5. **`0x400436` → REQUEST SENSE 的落地**：TUR 把索引写进 `0x400436`（`0x0216DA`），
   但 `0x021768` 的 sense 队列取的是 `0x400464 + 0x400508*0x13`，两者之间的桥没有找到。
   若补上，就能把 §3.1 的"表映射"升级为完整的主机可见 sense 链。
