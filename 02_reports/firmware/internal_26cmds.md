## 0. 结论摘要（先说最重要的）

**这 26 条记录不是 26 条“内部命令”，而是一张 58 字节参数块的 26 个字段描述符。**

`0x03EBC0` 唯一的静态引用点是 `0x025A74`（`mov.l #0x0003ebc0,er6`），落在函数 `0x025A56` 里。该函数是一个**通用参数块校验引擎**：

```
0x025A56  CMD / 参数块校验引擎（入参 er0=块指针, r1=块长-1, 栈参=&累加字节数）
0x025A72  er6 ← 0x3EBC0（硬编码，不是入参）
```

## 1. 引擎 `0x025A56`：调用约定（`[实证]`，全文 47 条指令）

```asm
0x025A56  mov.l er2,@-sp / stm.l er4-er6,@-sp / subs.l #2,sp
0x025A60  mov.l er0,er6            ; er6 = arg1 = 参数块指针
0x025A62  mov.w r1,r4              ; r4  = arg2
0x025A64  mov.l @(0x16,sp),er5     ; er5  = 第 3 参 = &累加字节数
0x025A6A  mov.l er6,@0x400316      ; ← 全镜像唯一写点：块指针存全局
0x025A72  mov.l #0x0003ebc0,er6    ; 描述符表（硬编码）
0x025A78  mov.w r4,e4 / dec.w #1,e4
0x025A7E  sub.w r0,r0 / mov.w r0,@sp   ; 本表项消费字节数 = 0
0x025A88  mov.w e4,r1              ; handler 第 2 参 = 末索引（= 块长-1）
0x025A8C  mov.l @(0x4,er6),er2
0x025A92  jsr er2                  ; handler(er0=表项, r1=末索引, 栈=&消费数)
0x025A96  mov.b r0l,r0l / bne 0x025AAE
0x025A9A  ...                      ; 返回 0：*累加 += 消费数；[0x400436]=0x53；退出
0x025AAE  mov.w @sp,r0 / beq 0x025ACE    ; 消费 0 → 结束
0x025AB2  ...  *累加 += 消费数
0x025ABA  mov.w @er5,r0 / cmp.w r0,r4 / bls 0x025ACE   ; 累加 >= 块长 → 结束
0x025AC0  add.l #0x00000010,er6          ; 下一表项
0x025AC6  mov.l @(0x4,er6),er0 / bne 0x025A7E          ; handler==0 → 结束
```

要点：
- `0x400316` 是**块指针全局**：全镜像 1 写（`0x025A6E`）+ 24 读，读点**全部**在本区 handler 内（`0x25B00 … 0x264E2`）。`[实证]`
- 失败时统一写 `0x400436 = 0x53`（`0x025AA2/0x025AA6`）。`0x400436` 是命令状态字：分派器 `0x020E86` 入口清零、`0x020EA8` 判非零后转错误上报。`[实证]`
- `0x025A56` 自身在**应用镜像**内无 jsr/jmp/24 位/32 位引用，调用点可能在引导块（引导块镜像本地已有，见 `boot_block_code.md`）或 RAM 驻留副本。因此 r1 的实参无法直接读到，只能由 §3 反推。

## 2. 为什么 `op` 是“字节偏移”而不是“命令号”（三条独立证据）

**证据 A：26 段长度把 `0x00–0x39` 无缝铺满**

```
0x00(1) 0x01(1) 0x02(4) 0x04(4) 0x06(4) 0x0A(4) 0x0E(4) 0x12(4)
0x16(3) 0x19(1) 0x1A(1) 0x1B(2) 0x1D(1) 0x1E(2) 0x20(8)
0x28(1) 0x29(1) 0x2A(1) 0x2B(1) 0x2C(1) 0x2D(1) 0x2E(4) 0x32(1)
0x33(2) 0x35(4) 0x39(1)
```
每一段起点 = 上一段起点+长度，从 `0x00` 连续覆盖到 `0x3A`，**零空隙、零重叠**。26 个任意命令号恰好形成这种完全划分的概率可忽略。`[实证]`

**证据 B：每个 handler 都做 `op+len-1 <= r1` 的越界守卫**

`0x025C6A`（`add.w #3,r0` 后 `cmp.w r3,r0`）、`0x025D2C`、`0x025F0A`、`0x026062`、`0x0264D8` 等，都是 `if (op > max) fail` 与 `if (op+len-1 > max) fail`。若 `max = 25`（26 条命令的末索引），op 为 `0x1A…0x39` 的 13 条会全部立刻失败。只有 `max = 0x39`（= `0x3A`-1）时 26 条才全部通过，而 `0x39+1-1 = 0x39` 恰好顶格。`[实证]` + `[推断]`（强）：**r1 = 0x39，块长 = 0x3A = 58 字节**。

**证据 C：`0x25FDE` / `0x260F2` 用 `mov.w #0x003a` 作步长索引块数组**

```asm
0x025FDA  mov.b @er4,r4l        ; r4l = 块[0]（字段 0x00 的值）
0x025FDE  mov.w #0x003a,e4
0x025FE2  mulxu.w e4,er4        ; r4 = 字段0 × 58
0x025FE4  mov.b @(0x400680,er4),r4l
```
`0x400680` 是**元素宽 0x3A 的结构数组**，用字段 `0x00` 的值选元素。同码见 `0x260F2/0x260F8`、`0x3488E/0x34894`。`[实证]`

**结论**：`len` = 字段字节跨度，`op` = 字段在块内的字节偏移，`range_lo/hi` = 该字段的合法值域。

顺带解释了本轮最关心的“共用 handler 怎么区分两条”：**不需要区分**。handler 从入参 `er0`（表项指针）里读 `len`/`lo`/`hi` 字段，因此同一段代码天然服务多个字段：

```asm
0x025C84  mov.l @(0x8,er5),er1   ; lo ← 表项 +0x08（不是“当前 op”）
0x025C8E  mov.l @(0xc,er5),er0   ; hi ← 表项 +0x0C
```
`0x002E` 与 `0x0035` 的 hi 差一位，来自数据而不是代码。`[实证]`。此前的“handler 可能读当前 op”假设可以**否定**：全 26 条 handler 内没有任何读取“当前 op 号”的全局变量。

## 3. 参数块 `0x400680 + n×0x3A` 是什么

- 5 个可用元素（`n = 0..4`；`0x400680 + 4×0x3A = 0x400768`，末字节 `0x4007A1`），字段 `0x00` 的合法值正是 `{0..4, 9}`（`0x025CE8/0x025CEC`）。`9` 是越界哨兵，无第 10 个元素。`[推断]`（强）
- 字段 0 的合法值被当作数组下标使用（证据 C），故字段 `0x00` = **块/通道编号**。
- 块内两个 dpi 字段（`0x02`/`0x04`）+ 两个 32 位像素量（`0x06`/`0x0A`）+ 两个 32 位起点（`0x0E`/`0x12`）+ 一组位标志（`0x28–0x32`）→ **一条扫描通道的几何/输出参数块**，形态与 SCSI SET WINDOW / MODE SELECT 的参数页一致。`[推断]`（中）

## 4. 26 条逐条

每条固定五项：①参数怎么取 ②写了哪些全局 ③调用了谁 ④等待/轮询 ⑤建议名。
“块”= `[0x400316]` 指向的 58 字节参数块。所有 handler 的入参一律是 `er0=表项指针`、`r1=末索引`、`栈=&u16 消费字节数`，**没有一条读 CDB**（`0x40043C` 区在本区段 0 引用）。

### 4.1 `op=0x0000` → `CHK_BLK_ID`（`0x025CC0`，len=1，表 range 0..0）`[实证]`
① `0x025CE6 mov.b @er1,r6l` 取块+0x00 一个字节；硬编码 `<=4`（`0x025CE8`）或 `==9`（`0x025CEC`），**完全不看表里的 lo/hi**。
② 只有栈参 = 1（`0x025CFA`）；无 RAM/ASIC/IO 写。
③ 无子调用。
④ 无等待。
⑤ `CHK_BLK_ID`。**表 range 与实现冲突**（表写 0..0，实际 0..4/9）。

### 4.2 `op=0x0001` → `CHK_RSVD01`（`0x025ADA`，len=1）
① `0x025AFC mov.l @0x400316,er1` + `0x025B06` 取块+0x01 字节；与**表项 +0x0B**（`range_lo` 最低字节 = 0）做相等比较（`0x025B08/0x025B0C`）。
② 无全局写；`0x025B1A` 每字节把栈参 +1。
③ 无子调用。
④ 无等待。
⑤ `CHK_RSVD01`（必须为 0 的保留字节）。

### 4.3 `op=0x0002` → `CHK_RES_MAIN`（`0x025D08`，len=4，表 range 666..4000）
① `0x025D36/0x025D3C jsr 0x01605A` 取块+0x02 的 **u16**（不是 4 字节）；`0x025D4E..0x025D5E` 用表项 `+0x0A/+0x0E` 做 lo/hi 比较，与表 666..4000 **一致**。附加规则：`4000/value` 必须整除（`0x025D6E..0x025D80`，`divxu`），偏差 `>2` 视为非法分频（`0x025D82..0x025D90`）；`blk+0x2A` bit1 置位时改判 `==0x53`（`0x025D4A..0x025D6C`）；`blk+0x2A` bit0 且 `blk+0x2B` bit2 时 `n` 必须 ∈{1,2,3,4,6}（`0x025DA6..0x025DDA`）。
② 写 `0x400436 = 4`（`0x025D9C/0x025DA2`）表示“入参被修正”；写回块内 u16（`0x025D98 jsr 0x0160DE`）。**写回偏移异常**：`0x025D92 mov.l er5,er1` 把 r1 设成 `4000/n`（如 dpi=1200 时为 1333），而姊妹函数 `0x025DF8` 同位置传的是 `op+2=6`（`0x025E82/0x025E86`）。见 §6.4。
③ `0x01605A`（读 u16，`[实证]`：`0x016060..0x01607E` 两字节大端拼字）、`0x0160DE`（写 u16，值来自 `e1`：`0x0160E4 mov.w e1,@sp`）。
④ 无等待/轮询。
⑤ `CHK_RES_MAIN`（主扫描分辨率，须为 4000 的整数分频）。

### 4.4 `op=0x0004` → `CHK_RES_SUB`（`0x025DF8`，len=4，表 range 333..4000）
① 同 4.3：取块+0x04 的 u16（`0x025E28`），表 lo/hi 比较（`0x025E3A..0x025E4A`）与表一致；整除 4000；`n`∈{1,2,3,4,6,**12**}（`0x025EB2..0x025ED4`）；附加门控 `blk+0x2C` bit6（`0x025EA6..0x025EB0`）。

③ `0x01605A`、`0x0160DE`。
④ 无等待。
⑤ `CHK_RES_SUB`（副扫描分辨率）。

⑤ `CHK_NIB28`（低半字节枚举，高半字节闲置）。

### 4.17 `op=0x0029` → `CHK_FLAG29`（`0x0262D4`，len=1）
① 取块+0x29 字节：`0x026304 and.b #0x1e` 必须为 0（bit1–bit4 保留）；bit4 置位时，若 `blk+0x2B` bit2（`0x026314..0x02631A`）或 `blk+0x2C` bit6（`0x02632C..0x026336`）置位，则**清 bit7 并写回**（`0x02632A` / `0x026344`）。
② 写块+0x29（就地清 bit7）。
③ 无。
④ 无。
⑤ `CHK_FLAG29`（带条件回写的标志字节）。

### 4.18 `op=0x002A` → `CHK_ONESHOT`（`0x02635E`，len=1）
① 取块+0x2A 字节：`0x026388 and.b #0x88` 必须为 0；再 `0x02638C and.b #0x77` 后必须 ∈{0x01,0x02,0x04,0x10,0x20,0x40}（`0x02638E..0x0263A4`）。
② 栈参 = 1。③ 无。④ 无。
⑤ `CHK_ONESHOT`（严格 one-hot：bit3/bit7 禁用，且只能置一位）。

### 4.19 `op=0x002B` → `CHK_OPT2B`（`0x0263BE`，len=1）
① 取块+0x2B 字节：`0x0263E8 and.b #0xe9` 必须为 0（允许 bit1/2/4）；若 `blk+0x2A` bit1 置位（`0x0263F4..0x0263F8`）则 bit4 也被禁（`0x0263FC`）。
② 栈参 = 1。③ 无。④ 无。
⑤ `CHK_OPT2B`（位掩码 + 与 0x2A 的跨字段互斥）。

### 4.20 `op=0x002C` → `CHK_OPT2C`（`0x026418`，len=1）
① 取块+0x2C 字节：`0x026442 and.b #0xbd` 必须为 0（允许 bit1/bit6）；`blk+0x2A` bit1 置位时 bit6 被禁（`0x026456`）。
② 栈参 = 1。③ 无。④ 无。
⑤ `CHK_OPT2C`。0x2B/0x2C 各自与 0x2A bit1 互斥，构成三选一开关。

### 4.21 `op=0x002D` → `SET_ARM2D`（`0x026472`，len=1，表 range 0..255）
① 取块+0x2D 字节，`0x026498` 读到寄存器后 `0x02649A bne 0x0264AE`：**必须等于 0**；随后 `0x0264AA mov.b #0xff,r0l / 0x0264AC mov.b r0l,@er1` 写 0xFF。
② 写块+0x2D = 0xFF（`0x0264AC`）。这是 26 条里唯一“置位”型副作用。
③ 无。④ 无。
⑤ `SET_ARM2D`（一发式触发/挂起标志）。**表 range 0..255 与实现冲突**：实际只接受 0。

### 4.22 `op=0x002E` → `CHK_POS32A`（`0x025C4C`，len=4，range 0..0x7FFFFFF）
① `0x025C7E jsr 0x016022` 取块+0x2E 的 u32；`0x025C84` 比 lo、`0x025C8E` 比 hi，**均从表项读**。
② 栈参 +4。③ `0x016022`。④ 无。
⑤ `CHK_POS32A`（27 bit 上限的 32 位位置量）。

### 4.23 `op=0x0032` → `CHK_OPT32`（`0x0264C2`，len=1）
① 取块+0x32 字节：`0x0264EA and.b #0x9c` 必须为 0（允许 bit0/1/5/6）。
② 栈参 = 1。③ 无。④ 无。
⑤ `CHK_OPT32`。其 bit0 被 4.6/4.8 读作“长行程/半分辨率”开关（`0x025FF6`、`0x026106`）。

### 4.24 `op=0x0033` → `CHK_CNT512`（`0x025BE6`，len=2，range 0..512）
① `0x025C18 jsr 0x01605A` 取块+0x33 的 u16；`0x025C1E` 比表 lo、`0x025C26` 比表 hi（512）。
② 栈参 +2。③ `0x01605A`。④ 无。
⑤ `CHK_CNT512`。唯一 hi>255 的 16 位字段，故必须用字比较——与 4.12/4.14“只比 lo”形成对照，说明分三种校验强度。

### 4.25 `op=0x0035` → `CHK_POS32B`（`0x025C4C`，len=4，range 0..0x3FFFFFF）
① 与 4.22 同码，仅表项 hi 不同（26 bit）。
② 栈参 +4。③ `0x016022`。④ 无。
⑤ `CHK_POS32B`。**这条专门回答“同一 handler 怎么区分两条”**：不区分，hi 是数据。

### 4.26 `op=0x0039` → `CHK_MODE3`（`0x025B2C`，len=1，range 0..2）
① 取块+0x39 字节；`0x025B5C mov.b @(0xb,er5),r0l`（lo 最低字节 = 0）与 `0x025B64 mov.b @(0xf,er5),r0l`（hi 最低字节 = 2）做**字节**区间比较。
② 栈参 = 1。③ 无。④ 无。
⑤ `CHK_MODE3`（0/1/2 三选一模式字段）。它是唯一用“字节区间”的用例，且 `0x39+1` 恰为块末 `0x3A`——表尾证据。

## 6. 关键发现

**6.1 “26 条内部命令”应改判为“58 字节参数块的 26 个字段描述符”**（`[实证]`，§0/§2）
handler 无外部引用、op 无缝铺满 `0x00–0x39`、引擎硬编码表址、`len` 被当作迭代跨度使用——四条互相独立。此结论直接影响第 17.1 节的表述：`0x03EBC0` 与主机的“MAID 能力枚举”不是同一层东西，不能用它反推主机命令语义。

**6.2 `0x4007BE` 是**被读**，不是被写**（`[实证]`）
任务线索预期 dpi 字段写入 `0x4007BE`；实测 `0x025D08`/`0x025DF8` 只写 `0x400436` 和块内 u16，**不碰 `0x4007BE`**。反过来，`0x4007BE` 在本区段被读了两次（`0x026002`、`0x026126`），作 `==0x0FA0` 判断以切换行程上限。写它的在 `0x0219B6` 等 MODE SELECT 侧。因此 `0x4007BE` 是**已解析的“当前主扫描 dpi”**，是输入而非输出。

**6.3 两条行程上限常数交叉验证了第 11 章的机构参数**（`[实证]`）
`0x021A72..0x021ABA`：`0x4007BE==1200` → `0x400C64=0x0BB7(2999)`、`0x400C8C=0x3232(12850)`；`==4000` → `0x400C64=0x270F(9999)`、`0x400C8C=0xA752(42834)`。
- `9999 ≈ 4000/25.4×63.5 = 10000`、`2999 ≈ 1200/25.4×63.5 = 3000` → `0x400C64` = 63.5 mm 光学窗口在当前 dpi 下的像素数。
- `42834/4000×25.4 = 272.0 mm`、`12850/1200×25.4 = 272.0 mm` → `0x400C8C` = 副扫描最大行程 272 mm。
- `0x025F94` 里硬编码的 `0xA616=42518` 正是第 11.3 节“4000 dpi 行程上限 42518”，`0x31D2=12754 ↔ 1200 dpi` 一路。

**6.4 `0x025D08` 的写回偏移疑似缺陷**（`[推断]`，强）
姊妹函数 `0x025DF8` 在调 `0x0160DE`（写 u16，签名 `er0=基址, r1=偏移, e1=值`，见 `0x0160E4`）前明确构造 `mov.w e6,e1` + `inc.w #2,e5; mov.w e5,r1`（偏移 = op+2 = 6）；`0x025D08` 同位置是 `mov.l er5,er1`（`0x025D92`），而此刻 `er5` 已被 `0x025D80` 覆写成 `4000/n`，且 `e1` 未设置。若 `0x0160DE` 的约定如 4.4 所示，则 `dpi=1200` 时会向 `块+1333` 写 2 字节脏值，且超出 58 字节块。反证条件：若 `0x0160DE` 另有第二套约定（不成立——全镜像仅 2 个调用点，均在本文）。

**6.5 `0x4003FB` 在这里作模式码用，取值 `0x15`**（`[实证]`，供 17.3 使用）
`0x025F32 mov.b @0x4003fb,r0l` / `0x025F38 cmp.b #0x15,r0l`：等于 `0x15` 时把 `0x400C64/2` 作为额外下界，并从 `0x400ECE` 而非 `0x400ED6` 复制 4 个 word。这是 `0x4003FB` 除第 17.3 节 `0x02753E` 之外的第二个消费点，且证明它是一个**多值模式码**（初值 `0x10`，`0x15` 是另一态），而不是布尔量。

**6.6 无任何等待/轮询**（`[实证]`，否定性结论）
26 条 handler 内对 `0x010B56`（设备就绪）、`0x4202A2`（走片位置）、`0xFFFFxx` 的引用数均为 0；`0x4202A2` 全镜像在本区段 0 引用。全部是纯计算/取数，故“命令级”语义不成立（命令才需要等待硬件）。

## 7. 与既有结论的冲突（如实列出）

| 项 | 既有说法 | 本轮实测 | 依据 |
|---|---|---|---|
| `0x03EBC0` 性质 | 26 条内部命令 | 58 字节参数块的字段描述符 | §0、§2 |
| `len` 语义 | “参数长度” | 字段字节跨度（可含出参） | §2、4.4 |
| `0x400C78` 上限 | 1200 dpi → **12626** | `0x31D2` = **12754** | `0x02522E/0x025234` |
| `0x03E390` 索引 `0x03EBC0` | “抽样 16/16 命中” | 不成立：`field2` 索引的是 `0x01914A` 的 5 字节记录表（并行子任务 `table_03E390.md` 定案）；本轮独立复核：`field2` 实测 `0x05–0x8E`，远超本表 26 项 | 数值越界，两表无关 |
| `0x4007BE` | 分辨率（Harness） | 一致，且本轮补上“只读不写”的用法 | §6.2 |

`12626` 与 `12754` 差 128：`0x3152` vs `0x31D2`，只差 bit7。若他处确有 `0x3152`，则说明存在两套上限（例如是否含片夹起始偏移）；未在本轮找到 `0x3152` 的写入点。

## 8. 未解决（写清卡在哪条指令）

1. **调用者缺失**：`0x025A56` 全镜像 0 引用（`jsr/jmp` 24 位、32 位表项、`bsr` 可达区均无）。卡在“无法读到 r1 实参”。本轮用 §2 证据 B/C 反推 r1=`0x39`、块长 `0x3A`，等级 `[推断]`（强）。下一步：取引导块 `0x0–0xFFFF` 原始镜像，查 `jsr @0x25A56`。
2. **块数组元素数**：`0x400680 + 4×0x3A` 末字节 `0x4007A1`，与 `0x4007BE`（分辨率全局）不重叠，故判 5 个元素；但字段 0 允许值含 `9`，若真有第 10 个元素则会与 `0x4007BE` 冲突。卡在“找不到 `0x400680+9×0x3A` 的写入点”（`0x400680` 全镜像仅 4 个引用，无写点）。
3. **`0x025D08` 偏移缺陷**是否真会触发：需确认 `0x0160DE` 的 `r1` 是否可能被解释为“值”而非“偏移”。卡在 `0x0160E4 mov.w e1,@sp` 与 `0x0160E8 mov.w r1,r4` 的角色分配，只有 2 个调用点可对照。
4. **`0x0006` 分支写入的 `0x400EC6..0x400ECD` 未命名**：`0x400EC6` 全镜像 6 引用（`0x235FE/0x25F74/0x28A0A/0x29FD0/0x2A0FC/0x2A2A4`），未归入第 5.2 节表；`0x400ECE`/`0x400ED6` 两张 4-word 常数表用途未证。
5. **`0x026506`（紧接末条 handler，`0x0264C2` 之后）**：结构与其他 handler 相同（`r6=op; inc; cmp; 消费=2`），但表内无该项、全镜像无引用。是死代码还是第二张表的 handler，未证。
6. **`0x0019` 的 `{2,5}`、`0x0028` 高半字节、`0x002E/0x0035` 的 27/26 bit 量纲**：均只有掩码/边界证据，无物理含义证据，故只给中性名。
