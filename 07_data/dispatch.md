# LS8000.md3 — 16 位选择子 / 能力 ID 分派机制

样本：`D:\DS\TEST\LS8000\driver\LS8000.md3`（958,464 B，PE32，ImageBase `0x10000000`，只读）
产物：`dispatch.md`（本文）、`dispatch_caps.json`（268 条能力 ID）、脚本 `pe_md3.py / cfgmod.py / sim_factory.py / final_gen.py`

---

## 0. 结论摘要

1. **md3 里没有一张「一张表打天下」的能力 ID 表**，而是 **4 个互相独立的分派层**，全部是 MSVC 编译出来的 `jmp [reg*4+imm32]` 或比较树：
   | 层 | 入口 VA | 键 | 条目 | 结论 |
   |---|---|---|---|---|
   | A `NkCtrlEntry` | `0x10091850` → `0x10091D50` | **16 位选择子**（有符号扩展） | 11 + 4 特殊 | 选择子 1..11 / `0x1000` / `0x2000` / `0x2100`，3、4 另走一路 |
   | B `NkMDCtrlEntry` | `0x1000B520` | 选择子（32 位比较，语义为 16 位） | 4 | 只认 1..4，**5 落到 default 返回 `0x1001`** |
   | C `MAIDEntryPoint` | `0x10027600` | MAID 功能号 | 16 | 0..15，6 个号共享同一入口 |
   | D **能力 ID 工厂** | `0x10071A60` | **16 位能力 ID** | **268 个 ID / 129 个分支** | `(group<<8)|sub` 空间，ID 唯一用途 = 选对象构造器 |
2. **选择子 ≠ 能力 ID**，是两套编号、两个参数、两层语义。详见 §8。
3. 能力 ID 空间确实是 `(group<<8)|sub`，共 15 个 group：`0x05 0x11 0x12 0x13 0x14 0x15 0x40 0x50 0x51 0x52 0x54 0x55 0x60 0x80 0x81`。
4. `.rdata` **没有** `(u16 id, u32 handler)` 静态表（§7，实证否定）。
5. `selector = 5`：在 `NkCtrlEntry` 里是「按设备 ID 定位设备对象并调其虚方法 #2」（`0x10091E05` → `0x10091A50`）；在 `NkMDCtrlEntry` 里是**非法值**（返回 `0x1001`）。第 13 章那个 `selector 5` 属于 `NkDriverEntry`（NKDSBP2.dll），不在本模块内。

## 1. 方法与覆盖率（先说清楚边界）

- **递归下降**：以 3 个导出为根，capstone `CS_MODE_32`，逐指令解码；`call/jmp/jcc imm` 入队；命中 `jmp [reg*4+imm32]` 时解析表项并把目标入队；迭代到不动点（`cfgmod.py`）。
- **线性扫描只用来找站点**：全 `.text` 扫 `FF 24 /4` 编码（`FF 24 85/8D/95/9D/A5/AD/B5/BD`），得 **185 个候选站点，全部能解成 7 字节 `jmp`**（`scan_jmp.py` → `jmp_scan.txt`；注意 `0x100B60DD` 那张表落在 `.data`，是唯一位于非 `.text` 的）。其中 **37 个落在导出可达 CFG 里**，其余 148 个在不可达区（多为图像处理库的 C++ switch）。
- 可达图规模：**1,241 函数 / 13,616 指令 / 43,632 字节 = `.text` 的 5.6%**。这是**下界**，原因明确：大量调用是 `call [reg+off]`（C++ 虚调用），静态无法定对象，故没有继续展开；`.text` 里剩余部分主要是图像处理与容器模板代码，与本问题无关。
- 可达的 37 个站点里，**20 个是 MSVC `memcpy/memmove` 内联产生的跳转表**（`0x100AB9xx`、`0x100AD5xx~0x100AD7xx`，紧邻 `rep movsd`/`std`），属编译期惯用法，不是语义分派，本文不列。
- 真正的语义分派点 **5 个**（§2）。

## 2. 分派点总表（`[实证]`）

| # | 站点 VA | 编码 | 表地址 | 条目（有效/总） | 索引变换（指令地址 + 操作数） |
|---|---|---|---|---|---|
| A1 | `0x10091DBD` | `FF 24 9D 88 1F 09 10` | `0x10091F88` | **11/11** | `dec ebx`@`0x10091DB3`；`cmp ebx,0xA`@`0x10091DB4`；`ja`@`0x10091DB7` |
| B1 | `0x1000B52A` | `FF 24 85 7C B5 00 10` | `0x1000B57C` | **4/4** | `dec eax`@`0x1000B524`；`cmp eax,3`@`0x1000B525`；`ja`@`0x1000B528` |
| C1 | `0x1002760E` | `FF 24 85 40 78 02 10` | `0x10027840` | **16/16** | 无变换；`cmp eax,0xF`@`0x10027604`；`ja`@`0x10027608` |
| D* | 11 个（见 §6.1） | `FF 24 xx` | `0x10073720` 等 | 见 §6.1 | `add eax, -base` + `cmp` + 可选 `movzx` 字节重映射 |
| A2 | `0x10091D8D` 等 4 个 | 比较树（无表） | — | — | `cmp ax,3` / `cmp ebx,0x1000` / `cmp ebx,0x2000` / `cmp ebx,0x2100` |

**三张小表的边界判据（都是显式 count 比较，不靠"相邻数据"猜）**：`ja` 的目标即 default 臂，`count = imm + 1`。

**表尾独立校验**（三种判据互相印证，`[实证]`）：

- `0x10027840 + 16*4 = 0x10027880` 起是 `C7 41 58 00 ...`（`mov dword ptr [ecx+58h],0`，是下一个函数的代码）→ 16 条，不多不少。
- `0x10091F88 + 11*4 = 0x10091FB4` 起是 12 个 `0x90` 再 `64 A1 00 00`（`mov eax,fs:[0]`，下一函数序言）→ 11 条。
- `0x1000B57C + 4*4 = 0x1000B58C` 起是 4 个 `0x90` 再 `53 8B 5C 24 08`（`push ebx; mov ebx,[esp+8]`）→ 4 条。

无效条目：**0 条**（三张表全部 3/3 命中 `.text`；工厂 11 张表 100% 命中 `.text`）。表中确有 **2 条死项**，但不是"越界"，而是被前置比较截走（见 §3）。

## 3. A 层：`NkCtrlEntry` 的 16 位选择子

### 3.1 三层结构（`[实证]`）

```
导出 ?NkCtrlEntry@@YGFFFFPAX@Z @0x10091850
    call 0x100918a0                 ; 取单例（全局 0x100d85a0，懒构造，size 0x34）
    [eax] = vtable 0x100c24c4
    jmp dword ptr [edx+4]           ; = vtable[1] = 0x10091D50
0x10091D50  真正的分派器
```

- `0x100918a0` 是 `__declspec` 式的 call-once 单例 getter（SEH 帧 `0x100bcd5b`），对象存 `0x100d85a0`。
- vtable `0x100c24c4` 实测 16 项：`[0]=0x10091910 [1]=0x10091D50 [2]=0x10092770 [3]=0x10092D30 [4]=0x10091C10 [5]=0x10092E80 [6]=0x10091AA0 [7]=0x10091AE0 [8]=0x100A37A0 [9]=0x10092EE0 [10]=0x10092870 [11]=0x10091C70 [12]=0x10091CB0 [13]=0x100931E0 [14]=0x10091D50 [15]=0x10092770`。
- **参数**：`ret 0x10`（`0x10091865`、`0x10091DEE`）→ 4 个栈参数。实测读取位点：`[esp+4]`=选择子（`movsx ebx,ax`@`0x10091D5C`）、`[esp+8]`=参数2、`[esp+0xC]`=参数3、`[esp+0x10]`=request（`mov ebp,[esp+1Ch]`@`0x10091D57`）。即 `u16 NkCtrlEntry(u16 selector, u16 a2, u16 a3, void* request)`。
  > 与 BRIEF 给的「`u16,u16,void*` 三参」不一致，也与导出名的 4×`F`（4 个 short）不一致。以 `ret 0x10` + 实际读取偏移为准。列为本轮疑问 Q3。

### 3.2 选择子取值域（`[实证]`）

```
0x10091D62  cmp ebx,0x1000 ; jg  → 0x10091D79: cmp ebx,0x2000 ; je L
            ≤0                  → 前置调用 0x10091CF0(request)
            1..2                → 直接 L
            3..0xFFF            → 前置调用 0x10091CF0(request) 后 L
            0x2000              → 直接 L
0x10091D8D L: cmp ax,3 / cmp ax,4 → je 0x10091F34      ; 3、4 提前截走
            cmp ebx,0x1000 → je 0x10091F7C (直接返回 0)
            ebx > 0x1000  → 0x10091ECA: cmp 0x2000 / cmp 0x2100
            其余          → dec ebx; cmp 0xA; ja default; jmp [ebx*4+0x10091F88]
```

`0x10091CF0` 是「按 request 里的 key 在 `[this+8]` 的 map 里查一项，并把该项的 `+4/+8/+0xC` 三个字段写回 request」——`[推断]` 为前置的会话/设备定位。

### 3.3 11 路表（`0x10091F88`，`[实证]` 目标 + `[推断]` 语义）

| idx | 选择子 | 臂 VA | 参数闸门 | 行为 |
|---|---|---|---|---|
| 0 | 1 | `0x10091DC4` | `[esp+1C]==1 && [esp+20]==2` | `call [vt+8]`= `0x10092770` |
| 1 | 2 | `0x10091DF1` | 无 | `call [vt+0x14]`= `0x10092E80` |
| 2 | 3 | `0x10091EDA` | — | **死项**（被 `0x10091D91` 截走）→ 返回 6 |
| 3 | 4 | `0x10091EDA` | — | **死项**（同上） |
| 4 | **5** | `0x10091E05` | 无 | `call 0x10091A50(*(request+8))` |
| 5 | 6 | `0x10091E1D` | `[esp+20]==1` | `call [vt+0x1C]`= `0x10091AE0` |
| 6 | 7 | `0x10091EB6` | 无 | `call [vt+0x20]`= `0x100A37A0` |
| 7 | 8 | `0x10091E3E` | `[esp+20]==1` | `call [vt+0x24]`= `0x10092EE0` |

| 3 / 4 | `0x10091F34` | 无 | `0x10091B50(this+0x14, &a, &b)` 查表；命中比 `[esi+0x18]`，再 `call [edx+4]`（`[推断]`：按子键二次分派的一对多命令） |

**注意**：闸门比较的是 `word ptr [esp+1C]` / `word ptr [esp+20]`，即 a2 / a3 的**低 16 位**；`NkCtrlEntry` 的第 2、3 参数按 16 位使用。

## 4. B 层：`NkMDCtrlEntry`（4 路，`[实证]`）

```
0x1000B520  mov eax,[esp+4] ; dec eax ; cmp eax,3 ; ja 0x1000B571
0x1000B52A  jmp dword ptr [eax*4+0x1000B57C]
```

| 选择子 | 臂 | 目标 | 语义（`[推断]`，依据 request 字段用法） |
|---|---|---|---|
| 1 | `0x1000B531` | `0x1000B220` | 校验 `[req+4]==1 && [req+0]==0x10`、名串与 `0x100be778` 比对，分配句柄写 `[req+8]`，失败 `0x1008`/`0x1005` → **打开模块** |
| 2 | `0x1000B541` | `0x1000B270` | 校验 `[req+4]==1`，按 `[req]==0x10` 返回 `0`/`0x1005` → **查询/校验** |
| 3 | `0x1000B551` | `0x1000B2A0` | SEH 帧，长流程 → **执行/关闭类**（未细读） |
| 4 | `0x1000B561` | `0x1000B3A0` | 同上 |
| **5** | `0x1000B571` | — | `mov eax,0x1001; ret 8` → **非法选择子** |

`0x1001` / `0x1005` / `0x1008` 是该模块统一的错误码族（`0x1000 | n`），与 A 层 default 返回的 `6` 不同源。

## 5. C 层：`MAIDEntryPoint`（16 路，`[实证]`）

```
0x10027600  mov eax,[esp+8]     ; 第 2 个参数 = 功能号
0x10027604  cmp eax,0xF
0x10027608  ja  0x1002780E      ; default: eax=0xFFFFFF81(-127)，且若 [esp+1C] 非 0 先回调

| 功能号 | 臂 | 转发目标 | 附带常量 |
|---|---|---|---|
| 0 | `0x10027615` | `0x10026260` | 0 |
| 1 | `0x10027643` | `0x10026D80` | 1 |
| 2 | `0x10027671` | `0x100264E0` | 2 |
| 3 | `0x1002769F` | `0x10024EC0` | 3 |
| 4 | `0x100276CD` | `0x10024F30` | 4 |
| 5,6,7,8,9,13 | `0x100276FB` | `0x100250A0` | eax（= 功能号本身） |
| 10 | `0x10027728` | `0x100252D0` | 0xA |
| 11 | `0x10027756` | `0x10025510` | 0xB |
| 12 | `0x10027784` | `0x10025780` | 0xC |
| 14 | `0x100277B2` | `0x100259F0` | 0xE |
| 15 | `0x100277E0` | `0x10025C60` | 0xF |

每个臂都把 7 个参数原样转交，并把「功能号」作为额外常量压栈；被调函数内部再用这个常量做二级索引（`[推断]`：`MAIDEntryPoint` 只是 MAID 标准入口的 ABI 垫片，功能号在这里被"下推"了一层）。

**这是从导出到能力 ID 的唯一通道**：`MAIDEntryPoint(...,5)` → `0x100276FB` → `0x100250A0` → `0x100251DB: push 0x1012; push 0x8005; call 0x10071A60`（`[实证]`）。

## 6. D 层：能力 ID 工厂 `0x10071A60`（本任务的「能力 ID → 处理函数」）

### 6.1 结构（`[实证]`）

不是单表，而是 **比较树 + 11 张稠密跳转表 + 4 张字节重映射表**（MSVC 对稀疏大 switch 的标准降级）：

```
eax = capId
0x10071A72  cmp eax,0x50E6 ; ja 0x100728B2    ┐
0x10071A8C  cmp eax,0x5031 ; ja 0x1007221A    │ 22 个显式 cmp/je
0x10071A9D  cmp eax,0x5005 ; ja 0x10071EE0    │ （0x1100/0x1200/.../0x8100）
0x10071AAE  cmp eax,0x4003 ; ja 0x10071CF6    │
0x10071ABF  cmp eax,0x1400 ...                ┘
                           └→ add eax,-base; cmp eax,N; ja default
                              movzx eax, byte [eax+bmap]     ; 稀疏→稠密重映射
                              jmp [eax*4+table]
```

**索引变换全表**（`[实证]`，每条含站点/表/基址/范围/槽位/默认槽）：

| 站点 | 表 | `add eax,-base` 操作数 | 覆盖 ID 区间 | 槽位 | 默认槽 |
|---|---|---|---|---|---|
| `0x10071D15` | `0x10073720` | `0xFFFFBFFC` = −`0x4004` | `0x4004..0x4008` | 5 | 0 |
| `0x10071EF5` | `0x10073734` | `0xFFFFAFFA` = −`0x5006` | `0x5006..0x5030` | 19（bmap `0x10073780`） | 1 |
| `0x10072231` | `0x100737AC` | `0xFFFFAFCB` = −`0x5035` | `0x5035..0x50E5` | 38（bmap `0x10073844`） | 1 |
| `0x100728D1` | `0x100738F8` | `0xFFFFAF19` = −`0x50E7` | `0x50E7..0x50F1` | 11 | 4 |
| `0x10072A7B` | `0x10073924` | `0xFFFFADF8` = −`0x5208` | `0x5208..0x5284` | 9（bmap `0x10073948`） | 1 |
| `0x10072C14` | `0x100739C8` | `0xFFFFABF8` = −`0x5408` | `0x5408..0x5420` | 9（bmap `0x100739EC`） | 1 |
| `0x10072DAD` | `0x10073A08` | `0xFFFFABDD` = −`0x5423` | `0x5423..0x551E` | 5（bmap `0x10073A1C`） | 1 |
| `0x10072F5D` | `0x10073B18` | `0xFFFF9FFC` = −`0x6004` | `0x6004..0x600F` | 12 | 4 |
| `0x100730DF` | `0x10073B48` | `0xFFFF9FEA` = −`0x6016` | `0x6016..0x602A` | 21 | 2 |
| `0x10073468` | `0x10073B9C` | `0xFFFF7FFD` = −`0x8003` | `0x8003..0x800E` | 12 | 5 |
| `0x100735E1` | `0x10073BCC` | `0xFFFF7EFF` = −`0x8101` | `0x8101..0x8105` | 5 | 0 |

**换算公式**：
```
若 capId 命中显式 cmp 分支  → handler = 该 je 的臂
否则找 base ≤ capId < base+range 的表：
      i = capId - base
      j = bmap ? byte[bmap+i] : i          ; bmap 里 0x12/0x25 等大值是「洞」，指向 default
      target = *(u32*)(table + 4*j)
      target == 0x10073700 → 该 ID 无能力
```
11 张表共 688 个候选 ID，**全部 100% 落在 `.text`，0 个越界**。

**分支形态**（`[实证]`）：每个臂都是
```
push <size>            ; 对象大小
call 0x100AB280        ; operator new
...
mov  ecx, eax
call <ctor>            ; 构造函数
jmp  0x100736A0        ; 统一出口（*out = obj, return 0）
```
所以「处理函数」= 该能力 ID 对应类的**构造函数**。能力行为在构造出的对象的 vtable 里，不在分派点。

```
`*` `0x8007` 的分支不调构造器，直接在 `0x100734EF` 内联写 vtable `0x100C08F0`，故 handler 记为臂地址本身。

**别名（多个 ID → 同一 arm）是普遍现象**，例如 `0x5088`/`0x50E7` 同指 `0x100728DA`；`0x5468`/`0x6005` 同指 `0x10072F69`；`0x548A`/`0x8005` 同指 `0x100734C5`。`0x5xxx` 与 `0x6xxx`/`0x8xxx` 基本是一一对应的新旧两套编号（`0x548x ↔ 0x80xx`），这一层关系是 `[实证]`（同一 arm），含义是 `[推断]`。

### 6.3 md3 自己实际请求的能力 ID（`[实证]`，10+2 处直接调用）

## 7. `.rdata` 静态表检查：**不存在**（`[实证]` 否定）

- 把 `.rdata`（0x100BE000，75,768 B）按 dword 扫，筛出「值落在 `.text` 内」的元素，连成游程：**42 段长度 ≥4 的指针密集区**（最长 1,589 项，`0x100C04C0`）。
- 逐段检查相邻字段：每个指针**前 2 字节**恒为 `0x1000..0x100B`，即**上一个指针的高半字**；**后 2 字节**是下一个指针的低半字。也就是说这些区段是**纯 `void*[]` 的 C++ vtable**，没有任何 u16 id 字段。
- 结论：**`.rdata` 里没有 `(u16 id, u32 handler)` / `(u32 handler, u16 id)` 记录**。所有 id→handler 映射都靠 `.text` 内的编译器跳转表 + 比较树。

## 8. selector 与能力 ID 是不是同一个东西？

**不是。**（`[实证]` 结构 + `[推断]` 语义）

| | 选择子（selector） | 能力 ID（capability ID） |
|---|---|---|
| 出现位置 | `NkCtrlEntry` 第 1 参 / `NkMDCtrlEntry` 第 1 参 | `0x10071A60` 第 1 参 |
| 取值域 | `1..11`、`0x1000`、`0x2000`、`0x2100` | `0x05F2`、`0x11xx..0x15xx`、`0x40xx`、`0x50xx`、`0x51xx`、`0x52xx`、`0x54xx`、`0x55xx`、`0x60xx`、`0x80xx`、`0x81xx` |
| 粒度 | **动作**（open/query/…/invoke） | **类**（要实例化哪种设备/功能对象） |
| 目标 | 虚方法槽 或 具体函数 | 构造函数 |
| 谁调用 | 宿主（Nikon Scan）经导出 | md3 内部（`0x1004CE40`/`0x10071A60` 直调） |

**两级结构**（`[实证]` 链路 + `[推断]` 语义）：

```
第 1 级  导出选择子
         NkCtrlEntry(selector, a2, a3, request)
             ├─ 1..11 → 虚方法 / 具体函数（含 5 → 0x10091A50）
             └─ 0x1000/0x2000/0x2100 → 特殊臂
第 2 级  能力 ID（只在"要造对象"时才发生）
         MAIDEntryPoint(id=5..9,13) → 0x100250A0 → 0x10071A60(capId, 0x1012, &obj)
                                     └→ 129 个分支 → 构造函数
         a2/a3 在每个选择子臂里当"闸门"（例：sel1 要求 a2==1 && a3==2）
```

**`selector = 5` 落在哪**（`[实证]`）：

- `NkCtrlEntry(5, …)` → `0x10091E05`：
  ```
  10091E05  mov eax,[ebp+8]      ; request->+8（设备 ID）
  10091E08  push eax
  10091E09  mov ecx,esi
  10091E0B  call 0x10091A50
  ```
  `0x10091A50` 遍历 `[this+0x18]` 的链（`0x10085660` 步进），找 `[dev+0x80] == id` 的设备，命中后 `call [dev->vtbl + 8]`；找不到返回 0。→ **语义 `[推断]`：按设备 ID 定位设备对象并调用其控制方法（虚槽 #2）**，是最像"对某台设备下发一条请求"的入口。
- `NkMDCtrlEntry(5, …)` → **非法**，返回 `0x1001`。
- 第 13 章的「更新器用 selector 5」指的是 `NKDSBP2.dll` 的 `NkDriverEntry(selector, request, ctx)`，**不是本模块的任一导出**。本模块内没有能证明"更新器走 md3 的 selector 5"的证据，只能说：**若**更新器调的是 `NkCtrlEntry`，那么 5 = 上述"定位设备并下发"。

## 9. 与固件 `0x03E390` host_code 的对齐：只有否定结论

- 固件 host_code 是 `0x0120/0x0430/0x0500/0x0600/0x0800/0x0910/0x0F10…`。
- md3 的能力 ID 是 `0x05F2/0x1100…/0x40xx/0x50xx/0x60xx/0x80xx`。
- **两个集合只交 1 个值 `0x4000`**（`[实证]`：把 268 个 ID 与 BRIEF 的 48 条 host_code 逐一比对）。`0x4000` 两边都有：md3 侧是能力 `0x4000`→构造器 `0x1004BC10`，固件侧是 `0x4000`→internal_index `0x0E`→`0x02604A`。`[推断]` 这是**巧合**，依据：md3 其余 267 个 ID 与固件 47 个码全不重合，且两侧编号的分组边界完全对不上（md3 有 `0x11xx–0x15xx`/`0x50xx`/`0x80xx`，固件只有 `0x01xx/0x04xx/0x05xx/0x06xx/0x08xx/0x09xx/0x0Fxx`）。`0x6004` 与固件 `0x0604` 只是形似，数值不同。
- 因此第 17.1 节设想的「用 md3 的能力 ID 直接给固件 26 条命令命名」**这条路走不通**。`[推断]` 二者是不同层的编号：能力 ID 选"用哪个设备/功能类"，host_code 是"该类内部的动作码"；中间还隔着 request 结构（`+0x14` CDB 长度 / `+0x18` CDB 指针）这一层 SCSI 封装。要对齐，应从 CDB 构造点（第 7.2 节的"主机构造点"列）入手，而不是从能力 ID。

## 10. 未解疑问（按重要性）

1. **Q1（卡点）** `0x10071A60` 的 22 个显式 `cmp` 分支里，有 6 个是"多 ID 共享一个臂"（如 `0x600E`/`0x600F` 同臂）。共享是"同一类的不同版本"还是"别名"，需要看构造器内部对第二参数 `0x1012/0x1016/0x1021…` 的处理才能定。下一步：读 `0x10053100`（cap 0x8005 的构造器）里对第二参数的使用。
2. **Q2** 能力 ID 的**名字**仍是空的。268 个 ID 只有"ID→ctor VA"。可行的命名线索：ctor 里写的 vtable 地址（如 `0x8007` 写 `0x100C08F0`）→ 反查 vtable 的 RTTI（本 PE 有 `.rdata` 的 `??_R4` 结构，未解析）。本轮未做。
3. **Q3** `NkCtrlEntry` 的签名自相矛盾：`ret 0x10` + 4 个实际读取的参数 vs 导出名 `YGFFFFPAX`（4×short + `void*`，应为 `ret 0x14`）vs BRIEF 记的 3 参。以机器码为准（4 参），但**为什么导出名多一个 short 未解释**，可能上游 .def 与实现不同步。
4. **Q4** `0x10091F34`（选择子 3/4 共用臂）内部还有一层 `0x10091B50` 查表 + `call [edx+4]`，本轮只读到形状，没定键值域。
5. **Q5** 覆盖率 5.6% 是下界。若要把"能力对象建好之后到底发什么 SCSI 命令"接上，需要解虚调用：至少要把 42 段 vtable 的槽位与类对上（本轮只解了 `0x100C24C4` 一段）。
6. **Q6** `0x100737`/`0x100738` 那几个字节重映射表里的"洞值"（`0x12`、`0x25` 等）与 default 臂的对应关系是**按表内容推的**（洞值指向 `0x10073700`），没有源码级证据；但 11 张表 100% 命中 `.text` 且洞值一致，可信度高。
